### Structure

```json
{
  "type": "vless",
  "tag": "vless-in",

  ... // Listen Fields

  "users": [
    {
      "name": "sekai",
      "uuid": "bf000d23-0752-40b4-affe-68f7707a9661",
      "flow": ""
    }
  ],
  "decryption": "",
  "tls": {},
  "multiplex": {},
  "transport": {}
}
```

### Listen Fields

See [Listen Fields](/configuration/shared/listen/) for details.

### Fields

#### users

==Required==

VLESS users.

#### users.uuid

==Required==

VLESS user id.

#### users.flow

VLESS Sub-protocol.

Available values:

* `xtls-rprx-vision`

Without `decryption`, `xtls-rprx-vision` requires TLS or REALITY directly on the connection (no `transport`).

#### decryption

VLESS Encryption, compatible with Xray-core.

Format: `mlkem768x25519plus.<appearance>.<ticket lifetime>.[padding.]<server key>`

| Part            | Values                                                                                                       |
|-----------------|--------------------------------------------------------------------------------------------------------------|
| appearance      | `native` (TLS records), `xorpub` (obfuscated public keys) or `random` (fully random bytes), must match the clients |
| ticket lifetime | Lifetime of the 0-RTT tickets issued to clients, e.g. `600s` or a range `300-600s`; `0s` to disable 0-RTT     |
| padding         | Optional padding length/gap parameters, e.g. `100-111-1111.75-0-111.50-0-3333`                              |
| server key      | X25519 private key or ML-KEM-768 seed, generated by `sing-box generate vless-encryption`                     |

With decryption enabled, `xtls-rprx-vision` works on every transport and without TLS.

Empty or `none` to disable.
