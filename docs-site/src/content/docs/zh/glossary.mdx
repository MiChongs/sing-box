这一页集中解释文档里反复出现的词。每个词先说是什么，再说它影响什么，最后指向详细讲解的页面。按主题分组，同组内大致按出现的先后排列。

## 基础概念

**出站 / 节点**：sing-box 中负责把流量发出去的配置项，例如一个 `vless`、`shadowsocks` 服务器。文档里说“节点”，一般指来自订阅的代理服务器。

**策略组**：自己不连接服务器、而是从一批出站中挑一个来用的出站，例如 `selector`（手动选）、`urltest`（选延迟最低的）、`loadbalance`（轮流用）、`smart`（按学习结果选）、`smart-loadbalance`（按地区分摊）。文档中常简称“组”。

**成员**：策略组可以挑选的出站，来自 `outbounds` 字段直接列出的出站，以及 `providers` 引用的订阅中的节点。订阅节点的标签带订阅名前缀，如 `my-subscription/香港 01`。成员也可以是其他策略组。没有任何成员时，组退回内置的直连出站 `Compatible`。

**订阅（provider）**：在 `providers` 中定义的节点来源，定期从网址下载节点列表。更新后，引用它的组会重建成员列表。

**目标 / 目标键**：Smart 记录统计的单位，由要访问的域名归并而来，例如 `www.example.com` 记作 `www.example.com`，`a.b.example.com` 记作 `*.b.example.com`；没有域名时用 IP。同一个节点访问不同目标的表现分开记录、分开打分。详见 [工作原理](../how-it-works/#目标)。

**样本**：一次连接的结果（成功或失败、建连耗时、首字节延迟、流量等）。同一个（目标, 节点）至少有 2 个样本才会计算权重。

## Smart 怎样选节点

**权重**：Smart 给（目标, 节点）打的分，大约在 0–1.2 之间，越高越优先；低于 0.4 的节点不会成为候选。由成功率、延迟、抖动、吞吐等计算，旧数据随时间打折。详见 [工作原理](../how-it-works/#权重公式)。

**时间衰减**：读取统计时，越旧的数据所占分量越小，基础半衰期 7 天。这样节点最近的表现比很久以前的表现更重要。详见 [工作原理](../how-it-works/#时间衰减)。

**排名**：把每个节点在各目标上的权重平均后得到的整体排序，换算为 0–100 分并分为 `MostUsed`、`OccasionalUsed`、`RarelyUsed` 三档，通过 `GET /proxies/{name}/weights` 查看。它反映节点整体表现，实际选路仍按目标进行。

**候选**：一次拨号准备尝试的节点列表，最多 10 个，排在第一位的最先拨。详见 [工作原理](../how-it-works/#分层取候选)。

**unwrap 缓存**：内存中按目标保存的上一次候选列表，让同一网站的后续连接不必重新计算。没有过期时间，节点失效、手动指定变化、连接劣化或清空数据时清除。

**预取**：后台每 2 分钟为最近用过的目标预先算好候选列表，新连接可以直接使用。

**选路算法**：决定候选中先拨哪一个，例如 `strict-best` 总是先拨得分最高的，`p2c` 从前几名中随机取两个比较。分为“排序型”（只调整前几名的顺序，第 0 轮可能同时拨两个）和“选择型”（明确选定一个节点，只拨它）。详见 [选路算法](../algorithms/)。

**`hysteresis`（防抖窗口）**：窗口时间内，同一目标优先沿用上一次成功的节点，避免在得分相近的节点之间来回切换。详见 [节点偏好与手动指定](../priority-and-pinning/)。

**`policy_priority` 系数**：按节点名称给节点乘的系数，如 `香港:1.3` 让名称含“香港”的节点系数为 1.3。系数大于 1 的节点会排到其他节点前面。详见 [节点偏好与手动指定](../priority-and-pinning/)。

**对冲拨号**：首选节点看起来不太可靠时，250 ms 后同时拨下一个候选，谁先连上用谁，用一点额外的连接换更快的失败切换。

**场景**：Smart 对连接用途的判断。打分时按流量形态把连接归为下载、流媒体、交互、实时、语音等类别，套用不同标准，例如实时类更看重延迟；选节点时按端口和域名猜测用途，调整前几名候选的顺序。

## 健康与故障处理

**测速 / 健康检查**：后台每隔 `interval`（默认 3 分钟）经节点请求 `url`（默认 `https://www.gstatic.com/generate_204`），超时 5 秒，记录延迟。组空闲时不测。详见 [健康检查与故障处理](../health/)。

**空闲**：组从未成功拨号，或最近 2 分钟没有成功拨号。空闲时测速、预取、排名等任务暂停，节省电量。

**不可用标记**：节点拨号或测速失败后被标记为不可用 3 分钟，期间不作为候选。重启后仍然有效。

**熔断器**：30 秒内同一节点拨号失败 2 次，熔断器“打开”，节点暂时被排除：第一次约 15 秒，之后每次翻倍，最长约 2 分钟，带 ±20% 随机偏差。到期后放行一次试探，成功则恢复。

**软屏蔽**：只针对某个目标的屏蔽。某节点访问某网站时连接卡死、被重置或出现致命错误，这个节点对这个网站会被避开 10 分钟，访问其他网站不受影响。

**Watchdog**：逐条检查连接的守护机制，识别“发出请求后迟迟没有首字节”“写出后 60 秒没有任何回应”、连接被重置、TLS / HTTP/2 / QUIC 致命错误等情况，并触发软屏蔽。

**可疑节点**：最近对某个目标 TLS 探测失败，或近期成功率低于 40% 的节点。它不会被删除，只会排到候选末尾。

**劣化 / 屏蔽**：节点在组内累计失败次数增加时会“劣化”，权重被打折；累计到 30 次时被屏蔽一段时间（至少 93 分钟），之后逐渐恢复。也可以通过 Clash API 手动屏蔽节点。详见 [工作原理](../how-it-works/#劣化与恢复)。

**失败风暴**：短时间内大量连接失败（通常是本地网络断开）时，Smart 暂停后台探测，避免网络恢复前白白消耗资源和误判节点。

## 手动控制

**手动指定（pin）**：在面板中点击节点，或调用 `PUT /proxies/{name}`，让组只用这个节点。和 `selector` 不同，指定的节点故障时 Smart 会临时换用其他节点。详见 [节点偏好与手动指定](../priority-and-pinning/)。

**指定暂停**：手动指定的节点拨号失败、Smart 临时改用其他节点的状态。Clash API 中 `fixedSuspended` 为 `true`，`fixedActive` 显示实际使用的节点。指定的节点恢复后自动切回，不需要重新指定。

**指定认可**：Smart 记住你手动指定过哪些节点、用了多久、成功率如何，取消指定后仍给这些节点一个随时间减弱的加成（3 天减半，14 天后完全失效）。

## 数据、模型与地理库

**缓存文件**：`experimental.cache_file` 指定的数据库文件。Smart 的统计、权重、手动指定、熔断状态、地区锁定等都存在这里，重启后保留。命令行版本必须开启，否则 Smart 不会学习。

**Clash API / 面板**：`experimental.clash_api` 提供的网页接口。metacubexd、zashboard 等面板通过它显示和操作策略组，Smart 的权重、地区等也通过它查看。详见 [Clash API](../clash-api/)。

**ASN**：自治系统编号，大致对应目标 IP 所属的网络运营商或云服务商，如 Cloudflare 的 AS13335。开启 `use_asn` 后，Smart 还会按 ASN 汇总经验，访问同一运营商下的新网站时也能直接用上（CDN 运营商的 ASN 除外，因为同一个 CDN 背后的网站差别太大）。详见 [ASN 与 GeoX](../asn-geox/)。

**GeoX**：`experimental.geox` 提供的地理数据下载服务，负责下载并定期更新 ASN 数据库、国家数据库等，下载完成后立即生效。

**国家数据库**：根据 IP 查国家的数据库文件（`country.mmdb`），供 LightGBM、训练数据和 `smart-loadbalance` 的 `destination` 模式使用。

**LightGBM**：一种机器学习模型。开启 `use_lightgbm` 后，由预训练模型代替传统公式给节点打分。详见 [LightGBM 模型](../lightgbm/)。

**训练数据**：开启 `collect_data` 后，Smart 把每条连接的特征和结果写入 CSV 文件，可用来训练自己的模型。

## smart-loadbalance

**地区 / 地区池**：`smart-loadbalance` 组把成员按所在国家或地区分组，每组称为一个地区池，地区用代码表示，如 `HK`、`JP`；识别不了的节点归入 `OTHER`。详见 [Smart 负载均衡](../smart-loadbalance/)。

**出口探测**：经节点访问一个回显 IP 的网址，按网站实际看到的出口 IP 判断节点所在国家，用于名称看不出地区的节点。

**地区模式**：决定每条连接用哪个地区：`auto` 按目标学习最优地区，`destination` 按目标所在国家匹配，`priority` 按优先级顺序，`off` 不分地区。

**锁定地区**：在面板中点选地区出站，或调用 Clash API，让组只用某个地区。重启后保持。

**质量**：`smart-loadbalance` 用来比较节点的分数，取该节点对当前目标的权重；没有时依次用整体权重、测速延迟换算值或默认值。连接按质量和当前连接数分配。

**分配策略**：在选中地区的节点之间分配连接的方式，例如 `smart` 让质量高一倍的节点承载约两倍的连接，`round-robin` 轮流使用。

**会话亲和**：让一组连接固定用同一个节点，例如 `site` 让同一网站的所有连接走同一节点，避免出口 IP 变化导致登录失效。默认不绑定。

**地区出站**：`smart-loadbalance` 为某个地区生成的出站（类型 `smart-region`），可在路由规则、`selector` 或落地节点的 `detour` 中引用，只使用该地区的节点。

## 网络与部署

**前置与落地（嵌套代理）**：落地节点是你真正想用的出口，例如自建服务器；它不直接连接，而是先经过前置节点（通常是机场节点）转发，在配置中通过落地节点的 `detour` 指向前置。前置可以是一个 `smart-loadbalance` 组或它的地区出站。详见 [Smart 负载均衡](../smart-loadbalance/)。

**`detour`**：出站的一个字段，指定这个出站先经过哪个出站连接服务器，是实现前置与落地的方式。

**FakeIP**：sing-box 的一种 DNS 模式，给域名返回 `198.18.0.0/15` 等范围内的假地址，连接时再还原出域名。Smart 仍能按域名识别目标；但对假地址查国家、查 ASN 没有结果。

**嗅探**：sing-box 从连接的前几个数据包中读出域名（如 TLS 的 SNI），即使客户端直接用 IP 连接，Smart 也能按域名记录。
