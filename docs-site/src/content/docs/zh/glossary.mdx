## 基础概念

| 术语 | 含义 |
|---|---|
| 成员 | 组内可供选择的出站，可以是节点，也可以是其他策略组 |
| 精确目标 | 连接的域名（没有时为 IP）加端口，如 `api.example.com:443` |
| 通配主机 | 把子域名归并后的主机，如 `*.example.com`；封锁记录、响应探测以它为单位。见 [服务键](../service-keys/) |
| 服务键 | 决定哪些连接算同一个服务：命中的路由规则（如 `RuleSet [geosite-netflix]`），没有规则时为通配主机；开启 `prefer_asn` 后大合集规则按 ASN 归并 |
| 网站键 | 目标在共用网络上或查不到 ASN 时，用通配主机作为服务键 |
| ASN | 自治系统号，标识一个网络运营者，如 Google 的 15169 |
| 共用 ASN | Cloudflare、Akamai、AWS 等上面住着大量不相干网站的网络，从不作为服务键 |
| ASN 认领 | 服务规则的连接成功落在某个 ASN 上后，这个 ASN 被归给该服务，见 [ASN 认领](../service-keys/#asn-认领) |

## 评分与选择

| 术语 | 含义 |
|---|---|
| 综合分 | 来自 honk：观测成功率加上延迟、吞吐、质量的微调，减去丢包惩罚，再乘以 `policy_priority` 系数。见 [综合评分与选择](../scoring/) |
| 证据层 | 同一节点的四层记录：全局、地址族、服务、精确目标；越具体的层数据越多越能覆盖上层 |
| 有效完成 | 双向都有数据的成功连接，或任何失败的连接；被判为“不计”的不算 |
| 可靠性下界 / 上界 | 按成功与失败次数算出的 Beta 分布置信区间，样本少时区间宽 |
| 观测成功率 | 衰减后的成功 ÷ (成功 + 失败)，拨号失败按 3 次计 |
| 半衰期 | 可靠性证据每 30 分钟权重减半，旧的成功与失败逐渐被遗忘 |
| 资格 | 可靠性不明显落后于最好成员、且没有连续失败 3 次的成员才能在普通选择中胜出 |
| 已验证 | 4 次有效完成，或最近 60 秒内有正常收发 |
| 成熟 | 某项性能指标有 4 个样本且最新的不超过 60 秒 |
| 在任节点 | 某个服务上一次普通选择的结果；挑战者只有在双方成熟的数据上证明优势才能取代它 |
| 服务池 | 普通选择、试用与换人都在其中进行的少数成员，大小随业务量变化，见 [服务池](../scoring/#服务池) |
| 试用 / 探索 | 把一条连接交给缺数据的成员，受探索预算约束（冷启动、定期、恢复三种） |
| 失败计数与退避 | 硬失败让计数加 1，并在 5 分钟起、翻倍、最长 6 小时内不再被试用；4 条不同连接证明恢复后清零 |
| 连接质量 | mihomo 的场景公式（或 LightGBM 模型）为每条连接算出的值，大致 0–1.5；低于 0.4 会封锁节点 |
| 系数 | `policy_priority` 给节点的倍数，第一条命中的规则生效 |

## 封锁与探测

| 术语 | 含义 |
|---|---|
| 封锁 | 节点对某个网站暂时不能用；按网站记录，不影响其他网站。代码有 `manual`、`answer`、`error`、`lowWeight`、`loss`、`stalled`，见 [封锁代码](../blocks-and-probes/#封锁代码) |
| 整组封锁 | 节点对本组所有连接暂时不能用：API 手动封锁或稳定性检查的 `unstable` |
| 网站本身故障 | 超过 1/3 的成员（至少 2 个）对一个网站被封锁时，认为是网站的问题，暂时忽略这些封锁 |
| 响应探测 | 短连接结束后经同一节点请求 `https://<网站>/robots.txt`，识别拒绝、质询与“该地区不可用” |
| 出口 | 节点流量实际落地的国家与 IP；网站眼中的出口可能与节点自身的出口不同 |
| 出口嫌疑 | 同一地区的多个出口被一个网站拒绝、而其他地区正常时，该地区的成员对这个网站被推迟 |
| 半开 | 嫌疑到期后每次只放一个成员去试，持有 8 秒租约 |
| 失败风暴 | 连续 50 次失败、每次间隔不超过 2 秒；期间失败不计入任何节点 |
| 收敛 | 主选失败、由备用节点接通后，同一服务经其他节点的连接被关闭，统一到新节点 |
| MAD | 中位数绝对偏差，稳定性检查用它从最近 10 次延迟中找出抖动与变慢的节点 |

## 手动控制

| 术语 | 含义 |
|---|---|
| 手动指定 | 在面板中点选节点；之后新连接只走这个节点，不过滤、不换备用，也不因连接结果封锁节点 |
| 当前节点（`now`） | 面板显示的代表节点：手动指定的节点，否则是最近一次承载连接的成员 |
| 清空 | 删除一个组的全部学习数据，包括封锁、手动指定与缓存文件中的记录 |

## 数据与模型

| 术语 | 含义 |
|---|---|
| 缓存文件 | `experimental.cache_file` 的 bbolt 数据库，Smart 的数据在 `smart_score` bucket 中 |
| LightGBM | 由决策树组成的机器学习模型；开启 `use_lightgbm` 后代替场景公式计算连接质量 |
| 特征 | 交给模型的 32 个输入数值，按位置对应，见 [特征](../lightgbm/#特征) |
| GeoX | 下载 ASN 与国家数据库的全局服务（`experimental.geox`） |

## 负载均衡

| 术语 | 含义 |
|---|---|
| 地区 | `smart-loadbalance` 按名称、规则或出口探测把成员分成的组，如 `HK`、`JP` |
| 地区出站 | 某个地区的 `smart-region` 出站，可以被路由规则、`detour` 或 `selector` 引用 |
| 锁定 | 把 `smart-loadbalance` 组固定到一个地区 |
| 分配策略 | 在选中地区内把连接分给哪个节点，如 `smart`、`least-connections` |
| 会话亲和 | 让一组连接固定使用同一个节点，如同一网站、同一客户端 |
