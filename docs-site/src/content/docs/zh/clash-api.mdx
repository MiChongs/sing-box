Smart 组（以及 `smart-loadbalance` 组）通过 sing-box 自带的 Clash API 提供状态与控制接口，路径与返回格式尽量与 [vernesong/mihomo](https://github.com/vernesong/mihomo) 的 Smart 组一致，所以 metacubexd、zashboard 等面板可以直接使用。想用脚本查看排名、封锁节点或清空数据，也可以直接调用它们。

这一页先说明怎样调用，再按用途分为 [查看状态](#查看状态)、[手动控制](#手动控制)、[清空数据](#清空数据) 和 [Smart 负载均衡](#smart-负载均衡) 四部分。术语见 [术语表](../glossary/)。

## 开始之前

### 开启 Clash API

在配置中设置监听地址。设置了 `secret` 后，每个请求都要带上它：

```json
{
  "experimental": {
    "clash_api": {
      "external_controller": "127.0.0.1:9090",
      "secret": "change-me"
    }
  }
}
```

### 调用方式

本页示例假设监听地址为 `127.0.0.1:9090`。设置了 `secret` 时，在请求头中加上 `Authorization: Bearer <secret>`：

```bash
curl -H 'Authorization: Bearer change-me' http://127.0.0.1:9090/smart/groups
```

缺少或写错密钥时返回 401。错误一般是 `{"message": "..."}` 的形式；个别接口的错误格式不同，会在该接口下单独说明。

### 组名的写法

组名包含中文、emoji 或空格时，在 URL 中按 UTF-8 百分号编码，例如 `香港 自动` 写成 `%E9%A6%99%E6%B8%AF%20%E8%87%AA%E5%8A%A8`。用 curl 时需要自己编码，面板会自动处理。

<Callout type="warn" title="组名包含 / 时">
  `/smart/*` 与 `/cache/smart/flush/{name}` 不会解码路径中的 `%2F`，组名含 `/` 时这些接口找不到组：`/smart/*` 返回 404，而 `/cache/smart/flush/{name}` 会**清空所有 Smart 组**。`/proxies/{name}` 与 `/group/{name}` 系列接口不受影响。
</Callout>

### 接口一览

| 用途 | 接口 |
|---|---|
| 组的当前状态（面板读取的就是它） | `GET /proxies/{name}`、`GET /group/{name}` |
| 节点排名 | `GET /group/{name}/weights`、`GET /proxies/{name}/weights`、`GET /group/weights`、`GET /smart/weights` |
| 列出所有 Smart 组 | `GET /smart/groups` |
| 内部诊断 | `GET /smart/groups/{name}/diag` |
| 测速 | `GET /proxies/{name}/delay`、`GET /group/{name}/delay` |
| 每条连接实际使用的节点 | `GET /connections` |
| 手动指定、取消指定 | `PUT /proxies/{name}`、`DELETE /proxies/{name}`、`POST /smart/groups/{name}/clear-selection` |
| 封锁节点 | `POST`、`DELETE /smart/groups/{name}/block/{node}`，`DELETE /connections/smart/{id}` |
| 立即重算排名 | `POST /smart/groups/{name}/recompute` |
| 清空学习数据 | `DELETE /proxies/{name}/weights`、`POST`/`DELETE /cache/smart/flush`、`POST`/`DELETE /cache/smart/flush/{name}` |
| smart-loadbalance 的地区与分配方式 | `/smart/groups/{name}/regions`、`/smart/groups/{name}/balance` |

旧版的 `PUT /smart/groups/{name}/algorithm` 已删除，调用会返回 404 或 405。

## 查看状态

### `GET /proxies/{name}`

查看一个组此刻的状态。Smart 组的 `type` 是 `Smart`，除了 Clash 的标准字段，还带有与 mihomo Smart 相同的字段：

```json
{
  "type": "Smart",
  "name": "auto",
  "udp": true,
  "now": "HK-01",
  "all": ["HK-01", "HK-02", "JP-01"],
  "history": [{ "time": "2026-10-29T08:00:00Z", "delay": 123 }],
  "alive": true,
  "delay": 123,
  "hidden": false,
  "icon": "",
  "testUrl": "https://www.gstatic.com/generate_204",
  "expectedStatus": "*",
  "fixed": "",
  "fixedSuspended": false,
  "fixedActive": "",
  "policy-priority": "香港|HK:1.20;日本|JP:1.10",
  "useLightGBM": true,
  "collectData": false,
  "sampleRate": 1,
  "preferASN": false,
  "tolerance": 0,
  "lgbmModelAge": "2h3m0s"
}
```

| 字段 | 含义 |
|---|---|
| `udp` | 本组是否处理 UDP，即没有设置 `disable_udp` |
| `now` | 面板显示的“当前节点”：手动指定的节点，否则是最近一次承载连接的成员，否则是一条新连接最可能选中的成员。Smart 为每条连接单独选择，它只是一个代表 |
| `history`、`delay`、`alive` | `now` 这个节点的测速记录。`alive` 只表示最近一次测速在 10 分钟以内 |
| `fixed`、`fixedActive` | 手动指定的节点（`smart-loadbalance` 没有手动指定而锁定了地区时为该地区），没有时为空字符串 |
| `fixedSuspended` | 始终为 `false`：手动指定的节点不会被临时替换 |
| `policy-priority` | `policy_priority` 解析后的规则，系数保留两位小数，没有配置时为空字符串 |
| `useLightGBM`、`collectData`、`sampleRate`、`preferASN`、`tolerance`、`expectedStatus` | 对应的配置值 |
| `lgbmModelAge` | LightGBM 模型距上次加载的时长，只在模型已加载时出现 |
| `loadBalance` | 只有 `smart-loadbalance` 组才有，见 [Smart 负载均衡](#smart-负载均衡) |

`GET /group/{name}` 返回同样的结构（对象不是策略组时返回 404）；`GET /group` 返回所有策略组：`{"proxies": [...]}`。

### `GET /group/{name}/weights`

查看本组的节点排名，与 mihomo 的同名接口一致；`GET /proxies/{name}/weights` 是同一个接口。参数：

- `refresh=true`：立即重新计算，而不是返回最多 30 秒前的缓存；
- `full=1`（或 `full=true`）：附带 `diagnostic`，内容同 [`GET /smart/groups/{name}/diag`](#get-smartgroupsnamediag)。

```json
{
  "weights": [
    {
      "Name": "HK-01", "Rank": "MostUsed", "Weight": 100,
      "Alive": true, "Pool": true,
      "Utility": 1.0123, "Reliability": 0.9412, "Observed": 0.9831, "Quality": 0.8734,
      "Completed": 37.42, "Qualified": true, "FailStreak": 0, "BackedOff": false,
      "ProbeMs": 182, "ResponseMs": 240.5, "SetupMs": 95.2,
      "UploadBps": 81234, "DownloadBps": 2345678, "Loss": 0.0021,
      "Success": 412, "Failure": 7, "Targets": 23
    }
  ]
}
```

| 字段 | 含义 |
|---|---|
| `Name`、`Rank`、`Weight` | mihomo 的三个字段：节点名；`MostUsed` / `OccasionalUsed` / `RarelyUsed`；0–100 的相对分。算法见 [面板中的排名](../scoring/#面板中的排名) |
| `Alive` | 健康检查正常且没有被整组封锁 |
| `Pool` | 是否在 TCP 服务池中 |
| `Utility` | 节点的整体综合分（不分服务，已乘 `policy_priority` 系数） |
| `Reliability`、`Observed` | 可靠性下界与观测成功率（衰减后） |
| `Quality` | 整体连接质量（不含系数），没有时为 0 |
| `Completed`、`Qualified` | 衰减后的完成次数；是否已验证 |
| `FailStreak`、`BackedOff` | 连续硬失败次数；是否处于退避期 |
| `ProbeMs`、`ResponseMs`、`SetupMs` | 健康检查延迟、首次响应耗时、建连耗时（只在 2 分钟内的新鲜数据存在时出现） |
| `UploadBps`、`DownloadBps` | 最近的上传、下载吞吐（字节/秒），没有时省略 |
| `Loss` | 近 30 分钟的 TCP 重传率平均，没有时省略 |
| `Success`、`Failure` | 累计成功与失败次数 |
| `Targets` | 这个节点有记录的服务数 |

排名按 `Alive`、`Weight`、`Name` 排序。还没有数据时返回空列表并附加 `"message": "No weight data available for the specified group"`。对象不是 Smart 组时返回 400 `{"weights": [], "error": "not a Smart group"}`。对 `smart-region` 出站调用时，返回所属组排名中属于该地区的部分，并带上 `group` 与 `region`。

### `GET /group/weights`

一次取回所有 Smart 组的排名（最多 5 个组同时计算），与 mihomo 一致；`GET /smart/weights` 是同一个接口。支持 `refresh=true`。

```json
{
  "weights": { "auto": [ { "Name": "HK-01", "Rank": "MostUsed", "Weight": 100 } ] },
  "errors": {}
}
```

某个组计算失败时，错误记在 `errors` 中该组名下。没有 Smart 组时返回 `{"weights": {}, "message": "No Smart groups or no weight data available"}`。

### `GET /smart/groups`

列出所有 Smart 组及主要设置，用来确认配置有没有按预期生效：

```json
{
  "groups": [
    {
      "name": "auto", "type": "smart",
      "testUrl": "https://www.gstatic.com/generate_204", "expectedStatus": "*",
      "preferASN": false, "useLightGBM": true, "collectData": false, "sampleRate": 1, "tolerance": 0,
      "fixed": "", "now": "HK-01", "members": 42,
      "policyPriority": [ { "pattern": "香港|HK", "factor": 1.2 } ],
      "lgbmModelAge": "2h3m0s"
    }
  ]
}
```

- `type` 为 `smart` 或 `smart-loadbalance`；后者还带有与 `/proxies` 相同的 `loadBalance` 块。
- `members` 是成员节点数。`fixed` 是手动指定的节点，或 `smart-loadbalance` 锁定的地区。
- `policyPriority`、`lgbmModelAge`、`loadBalance` 为空时省略。

### `GET /smart/groups/{name}/diag`

一个组的内部状态：为什么这样选、哪些节点被封锁、服务池里有谁。只读，可以频繁调用：

```json
{
  "name": "auto", "type": "smart", "now": "HK-01", "fixed": "",
  "testUrl": "https://www.gstatic.com/generate_204",
  "members": [
    { "name": "HK-01", "alive": true, "delay": 182, "stabilityGrade": 1, "load": 3, "priority": 1.2,
      "exitRegion": "HK", "exitAsn": "9304" },
    { "name": "US-03", "alive": true, "delay": 420, "stabilityGrade": 2, "load": 0, "priority": 1,
      "blocked": "unstable", "blockedUntil": 1761730000 }
  ],
  "selection": [
    { "network": "tcp",
      "reasons": { "incumbentHeld": 812, "performanceWinner": 37, "coldExplore": 6, "periodicExplore": 21 },
      "ordinarySwitch": 15, "switchFlap": 2, "pool": ["HK-01", "JP-01", "SG-02", "HK-04"],
      "budgets": [ { "family": "ipv4", "coldAllowance": 8, "coldAvailable": 2, "earnedAvailable": 3,
                     "earningPeriod": 16, "paused": false, "inFlight": 0, "trialYield": 0.83,
                     "businessStarts": 1203, "trialStarts": 33, "coldTrialStarts": 6, "periodicTrialStarts": 21,
                     "recoveryStarts": 6, "budgetBlocked": 140, "inFlightBlocked": 4, "refunded": 1,
                     "trialSuccess": 25, "trialFailure": 5 } ] },
    { "network": "udp", "reasons": {}, "ordinarySwitch": 0, "switchFlap": 0, "pool": null, "budgets": null }
  ],
  "filtered": 96,
  "cache": { "aggregate": 168, "aggregateEvicted": 0, "site": 1320, "siteEvicted": 0, "exact": 4210, "exactEvicted": 0 },
  "hosts": [ { "key": "*.example.com", "nodes": { "HK-02": "answer" } } ],
  "hostFailLimit": 14,
  "floodSuppressed": false,
  "asnClaims": 0,
  "connections": 57,
  "preferAsn": false, "useLightGBM": true, "lightgbmLoaded": true, "collectData": false,
  "ranking": [ { "Name": "HK-01", "Rank": "MostUsed", "Weight": 100 } ]
}
```

| 字段 | 含义 |
|---|---|
| `members[]` | 每个成员：`alive` 健康检查是否正常，`delay` 最近一次检查的延迟，`stabilityGrade` 稳定性档位（1–4），`blocked` / `blockedUntil` 整组封锁的原因与截止时间（Unix 秒），`load` 经本组的活跃连接数，`priority` 系数，`exitRegion` / `exitAsn` 实际出口 |
| `selection[]` | TCP 与 UDP 各一项：`reasons` 选择理由计数（见 [选择理由](../scoring/#选择理由)），`ordinarySwitch` 换人次数，`switchFlap` 来回换的次数，`pool` 服务池成员，`budgets` 每个地址族的探索预算 |
| `filtered` | 累计被过滤掉的候选数 |
| `cache` | 三张证据表的当前大小与累计淘汰数（所有组共用） |
| `hosts[]` | 有封锁记录的网站或服务键：`nodes` 为节点 → 封锁代码，`hostBlocked` 表示网站本身被判为故障，`udp` 表示 UDP 记录 |
| `hostFailLimit` | 网站本身故障的阈值（被封锁节点数超过它即判定） |
| `floodSuppressed` | 是否处于失败风暴 |
| `asnClaims` | 当前的 ASN 认领数 |
| `connections` | 本组当前的连接数 |
| `lightgbmLoaded`、`collectedSamples` | 模型是否已加载；本次运行写入的训练样本数（开启采集时出现） |
| `ranking` | 与 `weights` 接口相同的排名 |

组不存在返回 404 `group not found: <name>`，不是 Smart 组返回 404 `not a Smart group: <name>`。

### `GET /proxies/{name}/delay`

把组当作一个代理测速：经组当前会选的节点访问探测地址。参数 `timeout`（必填，毫秒）与 `url`（可选，`http://` 开头的会被忽略）。成功返回 `{"delay": 120}`；超时返回 504，其他失败返回 503。**不会**解除手动指定。

### `GET /group/{name}/delay`

逐个测试组内的每个成员（同时最多 4 个），参数同上，返回 `{"HK-01": 120, "JP-01": 85}`，只包含成功的成员。结果同时计入成员的健康状态与评分中的探测延迟。

<Callout type="warn" title="组测速会解除手动指定">
  与 mihomo 一致，对 Smart 组调用这个接口会先解除手动指定的节点。面板上的“测速”按钮通常调用的就是它。
</Callout>

### `GET /connections`

查看每条连接实际走的节点。经过 Smart 的连接，`chains` 会补全到真正拨通的节点，顺序与 mihomo 相同，最终节点在前：

```json
{ "chains": ["HK-01", "auto", "proxy"] }
```

## 手动控制

### `PUT /proxies/{name}`

手动指定节点：之后的新连接只走这个节点。在面板里点选节点就是调用这个接口。`PATCH` 与它等价。

```bash
curl -X PUT http://127.0.0.1:9090/proxies/auto -d '{"name":"HK-01"}'
```

- 成功返回 204；请求体不是合法 JSON 返回 400；节点不是本组成员时返回 400 `Smart update error: not found`。
- `{"name": ""}` 取消指定。
- 指定保存在缓存文件中，重启后恢复。开启了 `interrupt_exist_connections` 时，已有连接被关闭。
- 指定期间不过滤、不评分、不换备用，也不根据连接结果封锁节点，见 [手动指定](../how-it-works/#手动指定)。

### `DELETE /proxies/{name}`

取消手动指定，恢复自动选择。面板上“取消固定”一类的按钮调用的就是它。

```json
{ "group": "auto", "previous_pin": "HK-01", "now": "JP-01", "interrupted": false }
```

- `previous_pin` 是原来指定的节点，没有指定时省略；`now` 是取消后的当前节点。
- `interrupted` 表示是否开启了 `interrupt_exist_connections`（为 `true` 时本组已有连接被关闭）。
- `urltest` 与 `smart-region` 也支持这个接口，返回 `{"group", "previous_pin", "now"}`；其他类型的组返回 400。

### `POST /smart/groups/{name}/clear-selection`

与 `DELETE /proxies/{name}` 效果和返回相同。

### `POST /smart/groups/{name}/block/{node}`

把节点从本组中整体移出一段时间，例如你知道它今晚线路有问题。参数 `duration`（Go 时长格式，如 `15m`、`2h`），默认 30 分钟，写错时按默认值处理。

```bash
curl -X POST 'http://127.0.0.1:9090/smart/groups/auto/block/HK-01?duration=2h'
```

```json
{ "group": "auto", "node": "HK-01", "blocked_until": "2026-10-29T18:30:00+08:00" }
```

- 封锁期间节点在过滤第 1 级被排除（所有成员都不可用时仍可能作为兜底），排名中 `Alive` 为 `false`；封锁保存在缓存文件中。
- 手动指定的节点不受影响。
- 节点不在本组时返回 404 `node not a member of this group: <node>`。

### `DELETE /smart/groups/{name}/block/{node}`

提前解除整组封锁（包括稳定性检查造成的 `unstable` 封锁），返回 204。

### `DELETE /connections/smart/{id}`

关闭一条连接，并把它**实际使用的** Smart 成员对这条连接的网站封锁（代码 `manual`），与 mihomo 一致。适合在连接列表里发现某个网站经某个节点特别慢时一键处理。`id` 是 `GET /connections` 返回的连接 ID。

```json
{ "group": "auto", "node": "HK-01" }
```

- 封锁记在连接的通配主机（如 `*.example.com`）上，同时记在连接的服务键上（命中的规则，如 `RuleSet [geosite-netflix]`；开启 `prefer_asn` 时可能是 ASN 或认领该 ASN 的服务），同一服务的其他域名也会避开这个节点。它**永久有效**，只能通过 [清空数据](#清空数据) 解除。
- 相关连接被关闭，在任节点被清除。
- 连接没有经过 Smart 组时返回 `{}`，连接仍会被关闭；没有路由元数据时返回 204。
- `id` 不是合法 UUID 返回 400，连接不存在返回 404。

### `POST /smart/groups/{name}/recompute`

立即重新计算排名并返回：`{"group": "auto", "ranking": [...]}`。

## 清空数据

清空会删除这个组的全部学习数据，相当于从头学起：证据、在任节点、服务池与探索预算、所有封锁记录（包括 `manual`）、整组封锁、手动指定、出口信息，以及缓存文件中的全部记录；健康状态也会重置。`smart-loadbalance` 组的地区锁定与运行时设置恢复为配置值，并重新识别地区。

### `DELETE /proxies/{name}/weights`

清空一个组，并返回删除的条目数：

```json
{ "group": "auto", "deleted": { "aggregate": 168, "site": 1320, "exact": 4210, "blocks": 12 } }
```

`aggregate`、`site`、`exact` 是三层证据单元的数量，`blocks` 是封锁记录数。写缓存文件失败时返回 500，同时附带 `error`。对象不是 Smart 组时返回 400 `{"error": "not a Smart group"}`。

### `POST /cache/smart/flush`

清空当前配置中的所有 Smart 组，成功返回 **204**（无正文），与 mihomo 一致。`DELETE` 与它等价。某个组失败时返回 500 `{"message": "<组>: <错误>"}`。

### `POST /cache/smart/flush/{name}`

清空名为 `name` 的 Smart 组，成功返回 204。`DELETE` 与它等价。mihomo 的这个路径以配置名为参数，所以 `name` 不是 Smart 组时，会清空所有 Smart 组。

## Smart 负载均衡

`smart-loadbalance` 组与它的地区出站（`smart-region`）在面板中的 `type` 都是 `Smart`，上面的所有 Smart 接口对它们同样有效。下面是额外的字段与接口；“地区”“地区出站”“锁定”等概念见 [Smart 负载均衡](../smart-loadbalance/)。

### `GET /proxies/{name}`

`smart-loadbalance` 组额外带有 `loadBalance` 块，汇总当前的分配方式和各地区的节点数：

```json
{
  "type": "Smart",
  "name": "balance",
  "now": "🇭🇰 香港 03",
  "all": ["🇭🇰 香港负载", "🇯🇵 日本负载", "🇺🇸 美国负载", "unknown-node-1"],
  "fixed": "",
  "loadBalance": {
    "strategy": "smart", "affinity": "none", "mode": "auto", "lock": "", "fallback": "auto",
    "regions": [
      { "code": "HK", "name": "香港", "nameEn": "Hong Kong", "flag": "🇭🇰", "count": 12, "healthy": 11, "outbound": "🇭🇰 香港负载" },
      { "code": "OTHER", "name": "其他", "nameEn": "Other", "flag": "", "count": 1, "healthy": 1 }
    ]
  }
}
```

- `region.outbounds.members` 为 `regions`（默认）且生成了地区出站时，`all` 依次列出地区出站、还没有节点的已声明地区出站，以及没有地区出站的地区里的节点。`members` 为 `nodes` 时，`all` 与普通 Smart 组相同。
- `now` 是节点：手动指定的节点，否则是最近一次承载连接的节点。`GET /smart/groups`、`DELETE /proxies/{name}` 与地区接口返回的 `now` 则按地区显示：锁定地区的出站，否则是最近一条连接所在地区的出站。
- `fixed` 是手动指定的节点；没有手动指定而锁定了地区时，是该地区的出站（不列出地区出站时是地区代码）。
- `regions[].name` 是中文显示名（或 `region.rules` 中设置的名称），`nameEn` 是英文名；`healthy` 是按 TCP 统计的可用节点数；`icon`、`outbound` 只在存在时出现。

地区出站额外带有 `group`（所属组）、`region`、`fallback`、`generated`（是否由组自动生成）。它的 `all` 是该地区的节点；`now` 依次取：在这个出站上单独指定的节点、经它的最近一条连接所用的节点、该地区最近使用的节点、该地区质量最高的可用节点。`fixed` 是在这个出站上单独指定的节点。

### `PUT /proxies/{name}`

对 `smart-loadbalance` 组，请求体中的 `name` 可以是三类值：

| 请求体 | 效果 |
|---|---|
| `{"name": "🇯🇵 日本负载"}` 或 `{"name": "JP"}` | 锁定该地区（地区出站标签、地区代码或名称都可以），同时取消手动指定的节点 |
| `{"name": "HK-01"}` | 手动指定节点，与普通 Smart 组相同；地区锁定保留，但手动指定优先 |
| `{"name": ""}` | 同时取消手动指定与地区锁定 |

节点名与地区名相同时，按节点处理。对地区出站，`{"name": "<本地区的节点>"}` 只在这个出站上指定节点；传入其他地区的节点返回 400 `smart-region update error: not a member of the region`；`""` 取消。

`DELETE /proxies/{name}` 同样适用：对组，同时清除手动指定与地区锁定（没有手动指定时，`previous_pin` 显示原来锁定的地区）；对地区出站，清除它单独指定的节点，返回 `{"group", "previous_pin", "now"}`，其中 `group` 是地区出站自己的标签。SFA / SFW / SFL 图形客户端的选择操作遵循同样的规则。

### `GET /proxies/{name}/weights` 与组测速

对地区出站调用 `weights`，返回所属组排名中属于该地区的部分，并带上 `group` 与 `region`：`{"weights": [...], "group": "balance", "region": "HK"}`。

对列出地区出站的组调用 `GET /group/{name}/delay`，测的是每个地区出站当前的节点，结果以地区出站的标签为键。

### `GET /smart/groups/{name}/regions`

查看地区划分的全部细节：每个节点分到了哪个地区、依据是什么、是否可用、当前负载，以及正在生效的模式、策略与锁定。节点分错了地区，或者想知道“为什么连接都落在某个地区”，先看这里。

```json
{
  "group": "balance",
  "mode": "auto", "configMode": "auto", "lock": "",
  "strategy": "smart", "configStrategy": "smart",
  "affinity": "none", "configAffinity": "none", "affinityTtl": "10m0s",
  "fallback": "auto", "priority": ["HK", "JP"], "minNodes": 1, "minQuality": 0.5,
  "maxNodes": 0, "maxConnections": 0, "sticky": "30m0s", "switchMargin": 0.25, "unknown": "keep",
  "detect": { "name": true, "exit": "fallback", "exitUrl": "https://www.cloudflare.com/cdn-cgi/trace", "exitTtl": "24h0m0s" },
  "probe": { "enabled": true, "interval": "10m0s", "targets": 6, "regions": 5, "tracked": 14, "results": 22 },
  "outbounds": { "enabled": true, "auto": false, "members": "regions", "tag": "{flag} {name}负载" },
  "regions": [
    {
      "code": "HK", "name": "香港", "nameEn": "Hong Kong", "flag": "🇭🇰",
      "count": 12, "healthy": 11, "load": 37, "score": 0.912, "allowed": true,
      "outbound": "🇭🇰 香港负载", "last": "🇭🇰 香港 03",
      "members": [
        { "name": "🇭🇰 香港 03", "source": "name", "healthy": true, "load": 4, "quality": 0.947 },
        { "name": "mystery-7", "source": "exit", "healthy": true, "load": 2, "quality": 0.55, "exit": "HK", "exitIp": "203.0.113.7" }
      ]
    }
  ],
  "excluded": [],
  "memory": { "regionTargets": 128, "affinity": 0 }
}
```

| 字段 | 含义 |
|---|---|
| `mode`、`strategy`、`affinity` | 当前生效的值；带 `config` 前缀的是配置文件中的值，两者不同说明运行时切换过 |
| `members[].source` | 地区的来源：`rule`（自定义规则）、`name`（节点名称）、`exit`（出口探测）、`unknown`（未识别） |
| `members[].exit`、`exitIp` | 出口探测得到的国家与 IP，只在探测成功时出现 |
| `members[].quality` | 不针对具体目标的节点质量（总体权重或由测速换算的值），已乘以 `policy_priority` 系数 |
| `load` | 经本组的活跃连接数（TCP 与 UDP），加上正在拨号的连接数 |
| `score` | 不针对具体目标的地区评分，不含地区探测的系数 |
| `allowed` | 是否被 `allow` / `deny` 允许 |
| `last` | 该地区最近一条连接所用的节点 |
| `probe.tracked`、`probe.results` | 正在跟踪的探测候选网站数，以及现存的探测结果数 |
| `excluded` | `unknown: exclude` 时被排除的节点 |
| `memory` | 记住了地区的目标数，以及会话亲和的绑定数 |

组不存在返回 404；不是 `smart-loadbalance` 组返回 400 `not a smart-loadbalance group: <name>`。下面几个接口也一样。

### `PUT /smart/groups/{name}/regions`

锁定地区和 / 或切换地区模式，没有写的字段不变：

```bash
curl -X PUT http://127.0.0.1:9090/smart/groups/balance/regions -d '{"lock":"JP"}'
curl -X PUT http://127.0.0.1:9090/smart/groups/balance/regions -d '{"mode":"destination"}'
```

```json
{ "group": "balance", "mode": "destination", "lock": "JP", "now": "🇯🇵 日本负载" }
```

- `lock` 可以写地区代码、名称、旗帜或地区出站标签，该地区必须有成员，否则返回 400 `unknown region: ...`；写 `""` 解锁。
- `mode` 写 `""` 恢复配置中的模式；配置里没有 `priority` 列表时，不能切换到 `priority`。切换模式会清空各目标记住的地区。
- 两个字段都没有时返回 400。锁定与模式都会保存到缓存文件，重启后恢复。开启了 `interrupt_exist_connections` 时，锁定变化会中断已有连接。

### `DELETE /smart/groups/{name}/regions/lock`

解除地区锁定，返回 `{"group", "previous", "now"}`，其中 `previous` 是原来锁定的地区。

### `POST /smart/groups/{name}/regions/detect`

重新识别所有成员的地区，并为需要的节点启动出口探测；加上 `?force=true` 则对所有节点重新探测。修改了节点名称规则、或怀疑探测结果已经过时，就调用它。

返回 `{"group": "balance", "exitProbes": 3}`，`exitProbes` 是本次启动的探测数。探测在后台进行，完成后地区自动更新。

### `PUT /smart/groups/{name}/balance`

切换分配策略和 / 或会话亲和。空字段不变，`"default"` 恢复配置中的值：

```bash
curl -X PUT http://127.0.0.1:9090/smart/groups/balance/balance -d '{"strategy":"least-connections","affinity":"site"}'
```

```json
{ "group": "balance", "strategy": "least-connections", "affinity": "site" }
```

无法识别的值返回 400。切换会保存到缓存文件，重启后恢复；更换亲和会清空已有的绑定。
