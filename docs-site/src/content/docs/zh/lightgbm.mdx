这一页介绍 Smart 的可选功能：用机器学习模型计算连接质量。不开启时 Smart 照样学习和选择，第一次使用可以跳过本页。

## 它影响什么

每条连接结束时，Smart 会为它算一个**连接质量**（大致 0–1.5），见 [连接质量](../scoring/#连接质量)。默认用 vernesong/mihomo 的场景公式计算；开启 `use_lightgbm` 后，改由 **LightGBM** 模型预测。模型由大量决策树组成，从真实连接数据中训练而来，能学到手写公式难以表达的组合关系。

连接质量在 Smart 里有四个用处：

- 综合分中的质量项（权重 0.02，只在可靠性接近时起作用）；
- 质量 × `policy_priority` 系数低于 0.4 时封锁节点（`lowWeight`）；
- 面板中的节点排名；
- `smart-loadbalance` 的节点质量。

所以模型主要影响“哪些节点被认为质量差而封锁”和排名，对可靠性优先的选择影响有限。

### 什么时候值得开启

- **一般不必开**：场景公式已经够用，Smart 的可靠性评分、封锁、探测与模型无关。
- **想与 mihomo Smart 保持一致**：开启 `use_lightgbm`，使用默认模型。
- **想用自己的数据训练**：先开启 `collect_data` 采集一段时间，再按 [训练自己的模型](#训练自己的模型) 操作。

## 启用

在需要的组（`smart` 与 `smart-loadbalance` 都可以）上设置 `use_lightgbm: true`。模型由所有组共享，设置在 `experimental.smart.lightgbm` 中，全部可以省略。

启用后：

- **首次下载**：模型文件不存在时，后台下载 vernesong/mihomo 发布的 `Model.bin`，保存到数据目录下的 `Model.bin`（`model_path`）。`auto_update` 为 `false` 时也会下载缺失的文件；已存在的文件不再下载。
- **下载期间**：继续用场景公式，下载完成后模型立即生效，无需重启。
- **自动更新**：`auto_update: true` 时每隔 `update_interval`（默认 72 小时）检查一次，新模型下载后热加载。
- **下载路径**：`http_client`，没有时用 `download_detour`，都没有时用默认 HTTP 客户端。不要让模型经过还没学好的 Smart 组本身下载。
- **数据库**：开启 `use_lightgbm` 的组会打开 ASN 与国家数据库（没有配置时由 GeoX 自动下载 GeoLite2），供模型的 ASN 与国家特征使用。

## 确认已生效

- **日志**：模型加载时输出 INFO `lightgbm model loaded from <路径> (<N> features)`，下载后重新加载时输出 `lightgbm model reloaded from <路径>`；无法使用时输出 WARN `lightgbm: cannot use model <路径>: <原因>`。
- **Clash API**：模型加载后，`GET /proxies/{name}` 与 `GET /smart/groups` 出现 `lgbmModelAge`（模型已加载多久）；`GET /smart/groups/{name}/diag` 的 `lightgbmLoaded` 为 `true`。
- **训练数据**：开启 `collect_data` 时，CSV 的 `weight_source` 列为 `LightGBM` 表示这条连接的质量由模型算出，`Traditional` 表示由场景公式算出。

## 模型如何参与计算

连接关闭后，Smart 组装这条连接的 32 个特征交给模型，预测值直接作为连接质量（不乘系数，系数在使用时再乘）。以下情况改用场景公式：

- 模型还没加载（下载中、文件损坏）；
- 模型带有 `[transforms]` 段，而其中的 `[order]` 与 Smart 的特征顺序不一致；
- 预测出错、结果为 NaN 或不大于 0。

这个节点在该服务上不到 2 次完成时，两种方式都不计算。

## 模型格式

支持 LightGBM 的文本格式模型（`save_model` 的输出）。输入**按位置**对应：第 i 个输入就是下表的第 i 个特征，与模型文件里的特征名无关。

- 模型输入少于 32 个时，只使用前面的特征，所以用早期 30 维布局训练的模型仍然可用；
- 多于 32 个时，多出的输入填 0，并记录一条警告。

模型文件末尾（最后 16 KB 内）可以附带 mihomo 格式的 `[transforms] … [/transforms]` 段：`[order]` 写出“序号=特征名”，`[definitions]` 定义 StandardScaler 或 RobustScaler，在推理前对特征做缩放。缩放参数校验失败时忽略这一段、不做缩放；`[order]` 与下表顺序不一致时，模型的预测不会被使用。

## 采集训练数据

在组上设置 `collect_data: true` 后，每条有结论（成功或失败）的连接结束时，向 CSV 追加一行；被判为“不计”的连接与拨号失败不记录。不打算训练模型时不要开启。

- **文件**：`experimental.smart.collector.path`，默认数据目录下的 `smart_weight_data.csv`。多个组写入同一个文件，`group_name` 列区分来源。
- **采样**：`sample_rate` 取值 (0, 1]，例如 `0.3` 只记录 30% 的连接。
- **写入**：每 100 行刷新一次到磁盘，退出时也会刷新。
- **上限**：`size_limit_mb`（默认 100 MB），达到后停止写入并记录一次日志，不轮转。删除文件后 5 秒内自动新建。
- **表头**：首行是 42 个列名。已有文件的表头缺少 `cumul_loss_rate` 或 `exit_region`（旧格式）时，改名为 `<路径>.bak.<时间戳>` 备份，再新建文件。

## 训练自己的模型

仓库没有附带训练脚本。下面用 Python 的 pandas 与 lightgbm 演示流程。

**第 1 步：采集数据。** 在常用的组上开启 `collect_data`，正常使用几天，积累至少几万行。连接种类越多样越好。

**第 2 步：准备标签。** `weight` 列是**当时**算出的质量（劣化与触发封锁的连接已被压低）。直接用它训练，模型只会模仿现有公式；想做得更好，需要自己构造标签，例如结合连接是否成功、吞吐与时长。标签的数值范围应与现有质量相近（大多在 0.1–1.5 之间），因为预测值会直接当作质量使用，低于 0.4 会封锁节点。

**第 3 步：训练。**

```python
import pandas as pd
import lightgbm as lgb

df = pd.read_csv("smart_weight_data.csv")
X = df.iloc[:, 0:32].astype(float)   # 前 32 列：特征，顺序必须保持不变
y = df["weight"].astype(float)       # 标签，实际使用时换成自己构造的

booster = lgb.train(
    {"objective": "regression", "learning_rate": 0.05, "num_leaves": 31, "verbose": -1},
    lgb.Dataset(X, y),
    num_boost_round=300,
)
booster.save_model("Model.bin")   # LightGBM 文本格式
```

特征按位置读取，所以不能挑选或重排列；不想用某个特征时，可以在训练前把那一列置为常数。

**第 4 步：部署。** 把文件放到 `model_path`（默认数据目录下的 `Model.bin`），并把 `auto_update` 设为 `false`，否则自动更新会用默认模型覆盖它；也可以把 `url` 指向你自己发布的文件。然后重启 sing-box：手动替换的文件不会被自动发现。

**第 5 步：确认。** 日志应出现 `lightgbm model loaded from …`，之后 CSV 的 `weight_source` 列出现 `LightGBM`。
