Smart 默认完全自动选路。这一页介绍三种让它“听你的”的方式，适合想让某些节点多用一点、临时固定一个节点，或者不希望同一网站频繁换节点的用户：

- **`policy_priority`**：在配置里按节点名称写长期偏好，例如“香港节点优先，倍率节点靠后”。
- **手动指定**：在面板里点一个节点，让本组暂时只用它；在 `smart-loadbalance` 组里还可以锁定一个地区。
- **`hysteresis` 与 `sticky-session`**：减少同一网站在节点之间来回切换。

文中的“目标”“候选”“权重”等术语见 [术语表](../glossary/)。

## policy_priority

### 语法

`policy_priority` 是一个字符串，由若干条规则组成，规则之间用 `;` 分隔，每条规则写作 `模式:系数`。系数必须大于 0 且不等于 1：大于 1 表示提升，小于 1 表示降低。

```json
"policy_priority": "香港:1.3;IPLC:1.2;~(?i)\\d+(\\.\\d+)?x:0.8;=US-Backup:0.5"
```

模式有五种写法：

| 写法 | 匹配方式 | 示例 | 能匹配 |
|---|---|---|---|
| `关键字` | 名称中包含该子串 | `香港` | `香港 01`、`🇭🇰 香港 IPLC` |
| `=名称` | 与名称完全相同 | `=US-Backup` | 只有 `US-Backup`，不含 `US-Backup-2` |
| `~正则` | Go RE2 正则，名称中出现即可 | `~^(SG\|TW)-\d+$` | `SG-01`、`TW-12` |
| 含 `*` 或 `?` | 通配符，必须匹配**整个**名称 | `HK-*` | `HK-01`，不匹配 `My HK-01` |
| `!` 前缀 | 取反，与上面任一写法组合 | `!IPLC`、`!=US-Backup` | 不含 `IPLC` 的节点；除 `US-Backup` 外的节点 |

几条容易踩的细节：

- **区分大小写**。`hk` 不匹配 `HK-01`；正则要忽略大小写时写 `~(?i)hk`。
- 模式与系数在**最后一个** `:` 处分开，所以模式里可以出现 `:`，但不能出现 `;`。
- 正则默认只要名称中**有一段**匹配就算命中；要匹配整个名称，自己加 `^` 和 `$`。通配符则总是匹配整个名称。
- 在 JSON 字符串里，正则的反斜杠要写两次：`\d` 写成 `\\d`。
- 前缀后面的空格会保留：`! HK` 匹配的是子串 ` HK`（带空格），不是 `HK`。
- 一个节点命中多条规则时，所有系数**相乘**。
- 写错的规则（系数不是正数、系数等于 1、正则无法编译、模式为空）会被跳过，并记录一条 WARN：`policy_priority: ignored invalid rule [...]`，不影响启动。

### 一个完整的例子

用上面那条配置，各节点的系数如下：

| 节点 | 命中的规则 | 系数 |
|---|---|---|
| `🇭🇰 香港 IPLC 01` | `香港`、`IPLC` | 1.3 × 1.2 = **1.56** |
| `🇭🇰 香港 02 2x` | `香港`、倍率正则 | 1.3 × 0.8 = **1.04** |
| `🇯🇵 日本 01` | 无 | **1** |
| `US-Backup` | `=US-Backup` | **0.5** |
| `US-Backup-2` | 无（`=` 要求完全相同） | **1** |

解析结果可以在 `GET /smart/groups` 的 `policyPriority` 字段中核对：每条规则都列出解析后的模式、匹配方式（`substring`、`exact`、`regex`、`glob`）、是否取反和系数。

### 生效位置

系数在 `smart` 组中有三个作用：

1. **候选排序**：每次选路时，候选先按“系数 × 手动指定学习加成”从高到低稳定排序，再交给选路算法。系数大于 1 的节点会排到所有系数为 1 的节点前面，**与权重高低无关**，只要它通过了可用性过滤。
2. **补足顺序**：候选不足 10 个、需要从其他节点补足时，按系数从高到低补。
3. **权重**：节点每次连接后算出的权重乘以系数再保存，LightGBM 的输出同样乘以系数。所以偏好也会慢慢体现在学到的权重里。

<Callout type="warn" title="系数大于 1 就是硬排序">
  因为第 1 点，哪怕只写 `香港:1.01`，所有可用的香港节点也会排在其他节点前面。上例中的 `🇭🇰 香港 02 2x` 虽然被倍率规则降了一档，系数仍是 1.04，照样排在日本节点之前。想要“稍微偏向”而不是“一律优先”时，请谨慎使用大于 1 的系数；只想排除某些节点时，直接用 `include` / `exclude` 更清楚。
</Callout>

在 `smart-loadbalance` 组中，系数不是硬排序，而是乘在节点质量上：系数越高，节点在地区节点池里分到的连接越多，所在地区的评分也越高。详见 [Smart 负载均衡](../smart-loadbalance/)。

## 手动指定节点

手动指定（面板里常叫“固定”）让本组暂时只用你选的那个节点。它适合临时排查问题，或者某个网站只在特定节点上能用的情况。指定会保存，重启后仍然有效。

### 指定与取消

在面板中点击 Smart 组里的节点即可指定。也可以直接调用 Clash API：

```bash
# 指定
curl -X PUT http://127.0.0.1:9090/proxies/auto -d '{"name":"HK-01"}'
# 取消（轻量）：传空名称
curl -X PUT http://127.0.0.1:9090/proxies/auto -d '{"name":""}'
# 取消并清空选择状态，随后重新计算预取与排名
curl -X DELETE http://127.0.0.1:9090/proxies/auto
```

- `PATCH` 与 `PUT` 等价。SFA / SFW / SFL 图形客户端里的选择走同样的逻辑。
- 指定的节点必须是本组成员，否则返回 400 `Smart update error: not found`。
- 指定后，Smart 清除本组的 unwrap 缓存（目标到节点的短期记忆），并把指定写入缓存文件。重启时如果这个节点已经不在组内，指定会被自动丢弃。
- 默认只影响**之后的新连接**；已建立的连接继续走原来的节点。开启 [`interrupt_exist_connections`](#interrupt_exist_connections) 后才会中断已有连接。

### 指定期间的选路

- 候选列表里**只有**被指定的节点：选路算法、`policy_priority`、请求场景重排都不起作用，节点被手动屏蔽也不影响它。
- 只有被指定节点的**熔断器打开**时，Smart 才会绕过指定、按正常流程选路。单次失败或测速失败都不会让它绕过。
- 被指定节点**拨号失败**时，这一次请求会立即改用正常选路的节点完成，同时把指定标记为“暂停”。指定本身保留，不会被清除。

### 一个故障与恢复的例子

假设你指定了 `HK-01`，随后它出了故障：

1. **第一次拨号失败**：这条连接改由算法选出的节点完成。指定进入“暂停”状态，日志出现 `pin [HK-01] suspended`。熔断器记下 1 次失败。
2. **下一条新连接**：仍然先试 `HK-01`（熔断器还没打开）。如果 30 秒内再失败一次，熔断器打开。
3. **熔断期间**：新连接直接绕过 `HK-01` 正常选路，不再浪费时间去试它。熔断约 15 秒，连续熔断时依次延长到约 30、60、120 秒（另有 ±20% 的随机抖动），见 [熔断器](../health/#熔断器)。
4. **恢复**：熔断到期后，下一条连接会再试一次 `HK-01`；它拨号成功，或后台探测成功，或网络切换后的预热成功，都会立即解除暂停，流量切回 `HK-01`，日志出现 `pin [HK-01] resumed`。

暂停期间，Clash API 中的 `fixed` 仍是 `HK-01`，`fixedSuspended` 为 `true`，`now` 和 `fixedActive` 显示实际在用的节点。面板因此可以显示“已固定 HK-01（当前不可用，流量走 JP-02）”，而不是误导性的“固定 HK-01、当前 HK-01”。

### 在 smart-loadbalance 组中

`smart-loadbalance` 组除了指定节点，还可以**锁定地区**：

| 操作 | 结果 |
|---|---|
| 选择一个地区出站（如 `🇯🇵 日本负载`）或地区代码（如 `JP`） | 锁定该地区，同时取消已指定的节点 |
| 选择一个节点 | 与 `smart` 组相同，只用这个节点；地区锁定保留，但节点优先 |
| 传空名称，或 `DELETE /proxies/{name}` | 同时取消指定节点和地区锁定 |

节点名恰好与地区名相同时，按节点处理。地区锁定同样保存在缓存文件里，重启后保持；被锁定的地区没有可用节点时，按 `region.fallback` 决定是否改用其他地区。

每个地区出站（`smart-region`）也可以单独指定一个本地区的节点，只影响经这个地区出站的连接，不影响组本身。它与组的指定有两点不同：只保存在内存中，重启后需要重新指定；失败时同样会临时改用该地区的其他节点，但不会显示“暂停”状态。

### 从手动指定中学习

Smart 把手动指定当作一种反馈，用来调整之后的自动选路：

- 指定期间，经这个节点的每条连接算出的权重额外乘以 1.15。生成 LightGBM 训练数据时会再除掉，避免把你的偏好当成节点本身的质量去训练。
- 每个被指定过的节点都有一份“认可记录”：使用次数、成功率、基准延迟、常访问的目标与 ASN、常用的时段。由此算出一个加成系数，最高约 1.63，并随时间衰减（时间常数 3 天）。
- 加成在**取消指定后仍然有效**，最长 14 天；节点当前延迟超过记录中基准延迟的 2.5 倍时，加成暂时失效。
- 加成参与候选排序（与 `policy_priority` 相乘）和权重计算。

所以，长期手动指定过的节点，在取消指定后的一段时间内仍会被优先选中。想立即清除这些记录，调用 `DELETE /proxies/{name}/weights` 或 `POST /cache/smart/flush/{name}`（会同时清空该组的其他学习数据）。

## 减少切换：hysteresis 与 sticky-session

同一个网站的连接如果在节点之间来回切换，登录状态、断点续传、视频缓冲都可能受影响。`smart` 组提供两种办法：

| | `hysteresis` | `sticky-session` 算法 |
|---|---|---|
| 作用 | 在窗口期内，把这个目标上次用的节点换回首位 | 优先使用这个目标上次成功的节点 |
| 何时失效 | 超出窗口，或该节点不在过滤后的前 10 个候选中 | 节点不可用、被判为对该目标可疑，或组内手动指定了节点 |
| 是否跳过选路流程 | 否，仍经过完整的过滤与算法 | 是，满足条件时直接拨号，速度最快 |
| 能否与其他算法组合 | 能 | 本身就是一种算法 |

`hysteresis` 的时间戳在每次成功拨号时刷新，所以窗口是滑动的：只要某个目标一直有流量，它就一直停在同一个节点上。超过窗口 2 倍时间的记录每 5 分钟清理一次。`sticky-session` 的记录超过 8192 条时整体清空。

注意：`hysteresis` 之后还有请求场景重排、可疑节点后移，以及排序型算法第 0 轮的双节点竞速，它们仍可能让另一个节点胜出。需要更强的粘性时，用 `sticky-session`。

`smart-loadbalance` 组不使用这两个设置（配置了会被忽略并记录 WARN），对应的是地区记忆 `region.sticky` 与会话亲和 `balance.affinity`，见 [Smart 负载均衡](../smart-loadbalance/#会话亲和)。

## interrupt_exist_connections

默认情况下，切换手动指定只影响之后的新连接，正在进行的下载、直播不会被打断。开启 `interrupt_exist_connections` 后：

- 指定、取消指定、`clear-selection`，以及 `smart-loadbalance` 组锁定或解锁地区时，会中断经过本组的**全部**已有连接（TCP 和 UDP），客户端随后会用新的选择重新连接；
- 某条连接被判定劣化时，同一目标、同一节点上的其他 **TCP** 连接也会被关闭。劣化指：建立后完全没有收发数据的 HTTPS 连接、节点权重一次下降超过 30%，或失败累计到让节点被屏蔽（见 [劣化与恢复](../how-it-works/#劣化与恢复)）。目标本身被判定为不可达时不算。

无论是否开启，Watchdog 判定卡死的连接都会被关闭，网络切换时 sing-box 也会关闭所有连接，见 [健康检查与故障处理](../health/)。
