Smart 自动选路的同时，提供三种表达偏好的方式：`policy_priority` 长期加权，手动指定临时固定节点，`hysteresis` 与 `sticky-session` 减少切换。

## policy_priority

### 语法

规则之间用 `;` 分隔，每条规则写作 `模式:系数`。系数必须大于 0 且不等于 1：大于 1 提升，小于 1 降低。

```json
"policy_priority": "香港:1.3;日本:1.15;=US-Backup:0.5;~^(SG|TW)-\\d+$:1.1;!IPLC:0.9"
```

| 写法 | 匹配方式 | 示例 | 匹配 |
|---|---|---|---|
| `关键字` | 子串 | `香港` | `香港 01`、`🇭🇰 香港 IPLC` |
| `=名称` | 精确匹配 | `=US-Backup` | 只有 `US-Backup` |
| `~正则` | Go RE2 正则 | `~^(SG\|TW)-\d+$` | `SG-01`、`TW-12` |
| 含 `*` 或 `?` | 通配符，匹配整个名称 | `HK-*` | `HK-01`，不匹配 `My HK-01` |
| `!` 前缀 | 取反，可与上面的写法组合 | `!IPLC` | 名称**不含** `IPLC` 的节点 |

- 模式与系数在**最后一个** `:` 处分开，所以模式中可以出现 `:`，但不能出现 `;`。
- **区分大小写**，正则需要忽略大小写时写 `~(?i)hk`。
- 一个节点命中多条规则时，系数**相乘**。
- 写错的规则（系数无效、正则无法编译、模式为空）会被忽略并记录 WARN，不影响启动。前缀之后的空格不会被去掉，`! HK` 匹配的是子串 ` HK`。

解析结果可以在 `GET /smart/groups` 的 `policyPriority` 字段中查看。

### 生效位置

系数在三处起作用：

1. **候选排序**：每一层的候选先按“系数 × 手动指定学习加成”稳定排序，然后才交给选路算法。系数大于 1 的节点会排到所有系数为 1 的节点前面，**与权重高低无关**，只要它通过了过滤。
2. **补足顺序**：候选不足 10 个时，按系数从高到低补足。
3. **权重**：计算出的权重乘以系数后保存。LightGBM 的输出同样乘以系数。

<Callout type="warn" title="系数是硬排序">
  因为第 1 点，`香港:1.01` 也会让所有可用的香港节点排在其他节点之前。只想轻微倾斜时，第 3 点已经足够，但无法单独启用；请谨慎使用接近 1 的系数，或者用 `include` / `exclude` 直接控制成员。
</Callout>

## 手动指定节点

### 指定与取消

在面板中点击 Smart 组的节点，或直接调用 Clash API：

```bash
# 指定
curl -X PUT http://127.0.0.1:9090/proxies/auto -d '{"name":"HK-01"}'
# 取消（轻量）：传空名称
curl -X PUT http://127.0.0.1:9090/proxies/auto -d '{"name":""}'
# 取消并清空选择状态，重新计算预取与排名
curl -X DELETE http://127.0.0.1:9090/proxies/auto
```

`PATCH` 与 `PUT` 等价。指定的节点必须是本组成员，否则返回 400 `Smart update error: not found`。

指定后，Smart 清除本组的 unwrap 缓存，并把指定保存到缓存文件，重启后恢复；节点已不在组内时自动丢弃。只有开启了 `interrupt_exist_connections`，已有连接才会被中断。

### 指定期间的选路

- 候选列表**只有**被指定的节点，选路算法、场景重排都不起作用。手动指定也会无视屏蔽状态。
- 只有被指定节点的**熔断器打开**时，Smart 才会绕过指定、正常选路。近期失败或测速失败都不会绕过。
- 被指定节点**拨号失败**时，Smart 立即绕过指定重新选择一次，并把指定标记为“暂停”（`fixedSuspended` / `pinSuspended`）。指定本身保留。
- 被指定节点下一次拨号或探测成功时，暂停自动解除，流量切回该节点。网络切换后也会优先预热被指定的节点。

暂停期间，`now` 显示实际使用的节点，`fixedActive` 同样指向它；`fixed` 仍是被指定的节点。

### 从手动指定中学习

Smart 把手动指定当作一种反馈：

- 指定期间每条连接的权重乘以 1.15，生成训练数据时再除掉，不污染模型标签。
- 每个被指定过的节点维护一份“认可记录”：使用次数、成功率、基准 RTT、常访问的目标与 ASN、常用时段。由此算出一个加成系数，最高约 1.63，按 3 天的时间常数衰减。
- 加成在**取消指定后仍然有效**，最长 14 天；节点当前 RTT 超过基准 2.5 倍时加成失效。
- 加成参与候选排序（与 `policy_priority` 相乘）和权重计算。

因此，曾经长期手动指定的节点，在取消指定后的一段时间内仍会被优先选择。要立即清除，调用 `DELETE /proxies/{name}/weights` 或 `POST /cache/smart/flush/{name}`。

## 减少切换：hysteresis 与 sticky-session

| | `hysteresis` | `sticky-session` 算法 |
|---|---|---|
| 作用 | 窗口内把上次使用的节点换回首位 | 优先使用上次成功的节点 |
| 何时失效 | 超出窗口，或节点不在过滤后的前 10 名候选中 | 节点不可用或被判为可疑 |
| 是否跳过选路流程 | 否，仍经过完整过滤与算法 | 是，满足条件时直接拨号 |
| 能否与其他算法组合 | 能 | 本身就是算法 |

`hysteresis` 的时间戳在每次成功拨号时刷新，所以窗口是滑动的：只要某个目标一直有流量，就会一直停留在同一节点上。窗口外 2 倍时间的记录每 5 分钟清理一次。

注意：`hysteresis` 之后的场景重排、可疑节点后移，以及排序型算法第 0 轮的双节点竞速，仍可能让另一个节点胜出。需要更强的粘性时，用 `sticky-session`。

## interrupt_exist_connections

默认情况下，切换手动指定只影响之后的新连接。开启 `interrupt_exist_connections` 后：

- 指定、取消指定、`clear-selection` 会中断本组已建立的 TCP 连接；
- 某条连接被判定劣化时，同一目标、同一节点上的其他连接也会被关闭。

UDP 连接从不受影响。无论是否开启，Watchdog 判定卡死的连接都会被关闭，网络切换时所有连接都会被关闭。
