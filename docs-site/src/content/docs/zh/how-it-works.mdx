## 总览

Smart 每次拨号都会重新挑选节点。整个过程分为六步，前五步发生在拨号时，最后一步在连接关闭后异步完成。

## 目标

Smart 的统计以“目标”为单位。目标键的来源依次是：连接的域名、嗅探到的域名、路由前的原始域名；都没有时使用目标 IP。

有域名时，Smart 按公共后缀表找到可注册域名（eTLD+1）：可注册域名本身写成 `*.example.com` 的形式；子域名只保留可注册域名左侧的一级标签，更深的层级折叠为 `*.`；看起来是随机生成的标签同样替换为 `*`：

| 请求的域名 | 目标键 |
|---|---|
| `example.com` | `*.example.com` |
| `www.example.com` | `www.example.com` |
| `a.b.example.com` | `*.b.example.com` |
| `r1---sn-abc.googlevideo.com` | `*.googlevideo.com` |
| `abc123def456.example.com` | `*.example.com` |
| 仅有 IP `203.0.113.7` | `203.0.113.7` |

目标键不包含端口、协议和 ASN。TCP 与 UDP 在缓存与权重中分开记录；开启 `use_asn` 后，ASN 决定权重写入哪个槽位，见 [ASN 与 GeoX](../asn-geox/)。

## 分层取候选

Smart 按下表从上到下尝试，取第一个给出结果的层。每一层的结果都会经过下一节的过滤与排序。

| 层 | 来源 | 何时命中 |
|---|---|---|
| 手动指定 | 通过 Clash API 指定的节点 | 设置了手动指定，且该节点的熔断器未打开 |
| unwrap 缓存 | 内存中按目标缓存的上一次候选列表 | 该目标之前已经选过节点，且缓存未被清除 |
| 预取 | 后台每 2 分钟为常用目标算好的节点列表 | 目标在预取范围内 |
| 权重 | 统计库中该目标各节点的权重，按时间衰减 | 有权重数据 |
| 延迟 | URL 测速延迟由低到高 | 以上都没有结果 |
| 兜底 | 任意可用节点 | 全部为空 |

没有缓存文件（统计库不可用）或者识别不出目标时，直接从“延迟”层开始。

unwrap 缓存只在内存中，不会过期，只在节点失效、连接被判定劣化、手动指定变化或清空缓存时删除。因此预取层和权重层主要在某个目标第一次出现、或缓存被清除后才会被用到。

## 过滤与补足

每一层给出的节点先经过过滤，出现以下任一情况的节点会被去掉：

- 已不是本组成员；
- 被屏蔽（失败累计过多，或通过 API 手动屏蔽）；
- 不可用：熔断器打开、3 分钟内拨号或探测失败过、最近一次测速失败，或测速记录早于 3 × `interval`。从未测速过的节点视为可用；
- 请求是 UDP 但节点不支持 UDP；
- 对当前目标处于 10 分钟软屏蔽中，见 [健康检查与故障处理](../health/#处置分级)；
- 权重低于 0.4（unwrap 缓存层不检查权重）。

除 unwrap 缓存层外，候选最多保留 10 个；不足 10 个时依次补足：设置了 `policy_priority` 时按优先级系数，否则按后台排名快照、测速延迟、随机抽样。如果过滤后一个都不剩，就退回任意可用节点，再不行就取前 10 个成员。

## 排序叠加

候选列表确定后，依次经过以下几层调整。这些调整只改变顺序，不增删节点。

1. **`policy_priority`**：按“优先级系数 × 手动指定学习加成”稳定排序，系数大于 1 的节点会排到所有系数为 1 的节点之前，与权重无关。见 [节点偏好与手动指定](../priority-and-pinning/)。
2. **选路算法**：把一个候选换到首位，例如 `p2c` 从前 5 个中随机取两个比较。见 [选路算法](../algorithms/)。
3. **`hysteresis`**：窗口内该目标上一次成功使用的节点如果仍在候选中，就换到首位。
4. **请求场景重排**：仅对排序型算法（`strict-best`、`least-loaded`、`fastest-recent`、`latency-banded`）生效，只调整前 5 个。下载、流媒体类请求按节点峰值下载速度排序；SSH、远程桌面、游戏、语音等按近期 RTT 排序。场景按端口和域名关键字判断，例如 22、3389 端口为交互，3478、27000–28000 端口为实时。
5. **可疑节点后移**：最近 15 分钟内对该目标 TLS 探测失败、或近期成功率低于 40% 的节点移到末尾，但不删除。

`sticky-session` 算法有一条快速路径：该目标上次成功的节点仍可用且不可疑时，直接使用它，跳过上面的全部步骤。

## 拨号与重试

TCP 拨号最多进行 4 轮：

| 轮次 | 拨号的候选 | 说明 |
|---|---|---|
| 第 0 轮 | 第 1 个，或第 1、2 个 | 选择型算法拨 1 个，排序型算法拨 2 个；首选节点近期成功率 ≥ 95% 时只拨 1 个 |
| 第 1 轮 | 第 3–5 个 | 并行拨号，先连通者胜，其余取消 |
| 第 2 轮 | 第 6–8 个 | 同上 |
| 第 3 轮 | 第 9–10 个 | 同上 |

- **对冲拨号**：第 0 轮只拨 1 个节点、且该节点“可疑”（熔断器有失败记录、近期失败过或还没有存活心跳）时，250 ms 后并行拨第 2 个候选。
- **每轮超时**：该轮节点历史建连耗时的 2 倍，没有历史或超过 10 秒时为 10 秒。超时的轮次之后有一个 20–200 ms 的短暂退避。
- **重新选择**：某一轮已无候选可拨时，重新执行一次选择并从第 0 轮开始。手动指定的节点失败时也会走这一步，详见 [手动指定](../priority-and-pinning/#手动指定节点)。
- **失败的后果**：每次非取消导致的拨号失败，都会把该节点标记为不可用 3 分钟、计入熔断器，并记一条失败统计。

UDP 不并行：依次尝试前 3 个候选，每个超时为历史建连耗时的 2 倍或 10 秒。UDP 拨号失败同样会把节点标记为不可用，但不计入熔断器。

拨号成功后，Smart 记住本次使用的节点（用于 `now`、`sticky-session` 与 `hysteresis`），并把实际节点写入连接的出站链。因此在 Clash API 的 `/connections` 中，经过 Smart 的连接显示为 `["node-a", "auto", ...]`，最终节点在最前。

## 记录与学习

连接关闭时，Smart 把这条连接的结果交给后台队列处理。队列已满时直接丢弃这条样本，不会阻塞连接关闭。

### 统计记录

每个（组, 目标, 节点）对应一条记录，包含成功与失败次数、建连耗时与首字节延迟（平滑平均）、上下行流量与峰值速率、连接时长、最后使用时间，以及按槽位存放的权重：`tcp`、`udp`，开启 ASN 后还有 `tcp_asn:<ASN>`、`udp_asn:<ASN>`。

此外每条记录在内存中维护四个按样本数计算的指数滑动平均，不写入磁盘，重启后清零：

| 指标 | 窗口（样本数） | 用途 |
|---|---|---|
| 短期 RTT | 30 | `fastest-recent`、`p2c`、`latency-banded`、场景重排 |
| 短期成功率 | 20（前 11 个样本读数为 0） | 可疑节点判断、第 0 轮是否只拨 1 个 |
| 长期 RTT | 900 | 近期变差惩罚、训练数据 |
| 长期成功率 | 600 | 训练数据 |

### 权重公式

未启用 LightGBM 或模型尚未加载时，权重由传统公式计算；同一（目标, 节点）少于 2 个样本时不计算。

1. **识别连接场景**：按流量形态分为 interactive、streaming、transfer、web、realtime、voip、api 七类，每类有一组不同的系数和上限。
2. **成功率**：对时间衰减后的成功、失败次数取 Wilson 置信下限（z = 1.645）。样本越少越保守：1 次成功只得 0.27，10 次全成功为 0.79。
3. **延迟得分**：建连耗时与首字节延迟分别按 `exp(−ms / 1500)` 换算，抖动越大扣分越多，最多扣 40%。
4. **基础分**：`1.6 × 成功率^a × 建连得分^b × 延迟得分^c`，指数随场景变化；UDP 提高延迟与成功率的比重。
5. **修正项**：乘以流量、时长、质量、效率等因子；流媒体与下载场景按峰值带宽最多加 20%；最近 RTT 明显变差或近期成功率偏低时最多扣 30%；样本少时再乘以置信系数（不低于 0.7）。
6. **优先级**：乘以 `policy_priority` 系数与手动指定学习加成，手动指定期间再乘 1.15。
7. **场景上限**：超出该场景可接受的延迟或建连耗时（如 realtime 为 150 ms / 300 ms），权重封顶 0.38，低于可选门槛 0.4；成功率低于场景下限时按差距打折。

| 场景 | 延迟上限 | 建连上限 | 最低成功率 |
|---|---|---|---|
| realtime | 150 ms | 300 ms | 80% |
| voip | 200 ms | 400 ms | 75% |
| interactive | 300 ms | 500 ms | 70% |
| streaming | 600 ms | 800 ms | 75% |
| api | 600 ms | 600 ms | 70% |
| web | 800 ms | 1000 ms | 60% |
| transfer | 不限 | 不限 | 70% |

新算出的权重与旧值平滑合并：`新权重 = max((4 × 旧 + 2 × 新) / 6, 0.1)`，即每个新样本占三分之一。

启用 LightGBM 且模型已加载时，模型输出**直接替代**上述公式的结果，再乘以优先级系数，详见 [LightGBM 模型](../lightgbm/)。

### 时间衰减

读取统计时按时间衰减，旧数据不会被删除：权重乘以 `2^(−小时数 / 半衰期)`，取整到小时。

- 基础半衰期 168 小时，可用环境变量 `SMART_DECAY_HALF_LIFE_HOURS` 调整。
- 样本越少半衰期越长：约 20 个样本时为 1 倍，5 个以下为 3 倍，40 个以上为 0.5 倍。
- 失败记录的半衰期再乘 2（`SMART_FAILURE_STICKY`），所以失败比成功记得更久。
- 选路时衰减系数不低于 0.4，避免久未使用的好节点被完全遗忘。
- `SMART_LEGACY=1` 可切换回旧版分段衰减曲线。

### 劣化与恢复

连接以失败告终时，该节点的组级失败计数 F 加 1，劣化系数为 `max(0.1, 1 − 0.01 × F)`。F 达到 30 时节点被屏蔽 `30 + 2F + F/10` 分钟（F = 30 时为 93 分钟）。零字节结束的 443 端口连接，或权重骤降超过 30%，也会被标记为劣化并清除该目标的 unwrap 缓存。

后台每 5 分钟检查一次：屏蔽到期即解除；未被屏蔽的节点劣化系数加 0.01、F 乘以 0.95，系数回到 0.99 以上视为恢复。

如果同一目标在本组已累计劣化 `max_host_failed_times` 次（默认 10），Smart 认为是目标本身有问题，此后该目标的失败不再计入节点。

更快的处置（不可用 3 分钟、熔断、按目标软屏蔽）见 [健康检查与故障处理](../health/)。

## 后台任务

每个 Smart 组运行以下周期任务。标记为“空闲跳过”的任务在组空闲时不执行：从未成功拨号，或最近 2 分钟没有成功拨号。

| 任务 | 首次 | 周期 | 空闲跳过 | 作用 |
|---|---|---|---|---|
| 健康检查 | 10 秒 | `interval` | 是 | 测速探测，见 [健康检查](../health/#主动探测) |
| 排名 | 45 秒 | 1 分钟 | 是 | 计算节点排名快照 |
| 预取 | 30 秒 | 2 分钟 | 是 | 为常用目标预先算好候选列表 |
| 恢复检查 | 5 分钟 | 5 分钟 | 是 | 解除到期屏蔽，恢复劣化节点 |
| 目标可疑度探测 | 2 分钟 | 15 分钟 | 是 | 对热门目标做 TLS 握手探测 |
| Watchdog 扫描 | 10 秒 | 2.5 秒 | 否 | 检查卡住的连接 |
| 写盘 | 5 秒 | 5 分钟 | 否 | 把队列中的统计写入缓存文件 |
| 缓存预算调整 | 5 秒 | 5 分钟 | 否 | 按预算重设内存缓存 |
| 内存表清理 | 3 分钟 | 5 分钟 | 否 | 清理过期的内存记录 |
| 清理旧记录 | 10 分钟 | 2 小时 | 否 | 记录过多时裁剪 |
| 清理离组节点 | 10 分钟 | 10 分钟 | 否 | 删除已不在组内的节点数据 |
| 清理离组的组 | 15 分钟 | 2 小时 | 否 | 删除已不存在的组的数据 |

多个 Smart 组的任务按黄金分割错峰启动；设备休眠或时钟跳变后从当前时间继续，不补跑错过的周期；上一轮没跑完时跳过本次触发。

排名任务实际的最小间隔随节点数放宽：100 个以内 1 分钟，250 个以内 3 分钟，500 个以内 5 分钟，更多为 10 分钟。第一次成功拨号 2 秒后会额外计算一次排名。

排名的计算方式：对每个节点，取它在各活跃目标预取结果前 10 名中的权重平均值，换算为 0–100 分；前 20% 标记为 `MostUsed`，接下来 50% 为 `OccasionalUsed`，其余为 `RarelyUsed`。

## 当前节点

面板与 `GET /proxies/{name}` 中的 `now` 按以下顺序确定：

1. 未暂停的手动指定节点；
2. 最近一次成功拨号使用的节点；
3. 排名中第一个权重大于 0 的节点；
4. 测速延迟最低的节点；
5. 第一个成员。

由于 Smart 按目标选节点，`now` 只表示“最近用过的节点”，并不代表所有连接都走它。要看每条连接实际使用的节点，请查看 `/connections` 中的 `chains`。

## 多个 Smart 组之间共享什么

- 一个探测队列与探测线程池（`clamp(2 × CPU 核数, 8, 32)` 个线程），相同节点、相同探测地址的探测会合并，1 秒内的结果直接复用；
- 一个统计记录队列（4 个线程、2048 个槽位，满时丢弃样本）；
- 同一个缓存文件与内存缓存预算；
- LightGBM 模型、训练数据文件与 ASN / 国家数据库的读取器。

统计数据按组隔离：同一个节点在两个 Smart 组中的权重互不影响。

<Callout type="note" title="嵌套策略组">
  Smart 的成员可以是 `urltest`、`selector` 等其他策略组。Smart 把它们当作普通节点：统计、测速都记在该组的标签下，衡量的是它当时选中的节点的表现。`direct`、`block`、`dns` 类型的成员不参与统计与探测。
</Callout>
