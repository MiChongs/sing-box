这一页从头到尾讲一条连接经过 Smart 组时发生的事。想知道“它为什么选了这个节点”“为什么换节点”，或者想调参数之前，先读这一页。只想先跑起来，请看 [快速开始](../quick-start/)；不熟悉的词见 [术语表](../glossary/)。

## 总览

Smart 不会把所有连接固定到一个节点上：**每次拨号都会重新挑选**。挑选依据的是它对“这个网站 + 这个节点”的历史记录。整个过程分六步，前五步发生在拨号的那一刻，最后一步在连接关闭后由后台完成。

## 目标

Smart 的一切统计都以“目标”为单位：同一个节点访问不同网站的表现分开记录、分开打分。目标键按以下顺序取第一个有值的来源：连接的目标域名、嗅探到的域名、路由过程中记下的域名、路由改写前的原始域名；都没有时使用目标 IP。

为了让同一网站的子域名共享经验，Smart 先按公共后缀表找到可注册域名（eTLD+1，如 `example.com`、`example.co.uk`），再按下面的规则折叠：

- 可注册域名本身写成 `*.example.com`；
- 子域名只保留紧挨着可注册域名的一级标签，更深的层级折叠为 `*.`；
- 看起来是随机生成的标签（含 `-`、长串十六进制、数字占比很高）替换为 `*`。

| 请求的域名 | 目标键 |
|---|---|
| `example.com` | `*.example.com` |
| `www.example.com` | `www.example.com` |
| `a.b.example.com` | `*.b.example.com` |
| `r1---sn-abc.googlevideo.com` | `*.googlevideo.com` |
| `abc123def456.example.com` | `*.example.com` |
| 只有 IP `203.0.113.7` | `203.0.113.7` |

目标键不包含端口和协议。TCP 与 UDP 的缓存和权重分开记录；开启 `use_asn` 后，权重还会按目标 IP 所属的 ASN 另存一份，见 [ASN 与 GeoX](../asn-geox/)。

Smart 被其他策略组当作成员，或者被落地节点当作 `detour`（前置）时，如果拿不到原始连接的目标信息，就按这次拨号的目的地址计算目标键。

## 分层取候选

“候选”是这次拨号准备尝试的节点列表。Smart 按下表从上到下尝试各个来源，用第一个给出结果的来源；结果随后经过下一节的过滤与排序。

| 层 | 来源 | 何时用到 |
|---|---|---|
| 手动指定 | 你在面板或 Clash API 中指定的节点 | 设置了手动指定，且该节点的熔断器没有打开 |
| unwrap 缓存 | 内存中按目标保存的上一次候选列表 | 这个目标之前已经选过节点，且缓存还在 |
| 预取 | 后台每 2 分钟为最近用过的目标算好的节点列表 | 目标在预取范围内 |
| 权重 | 统计库中这个目标各节点的权重（已按时间衰减） | 有权重数据 |
| 延迟 | URL 测速延迟，由低到高 | 以上都没有结果 |
| 兜底 | 任意可用节点 | 全部为空 |

没有缓存文件（统计库不可用）或识别不出目标时，直接从“延迟”层开始。

unwrap 缓存只在内存里，没有过期时间。节点失效、连接被判定劣化、手动指定变化或清空缓存时，相关条目会被删除；内存预算不足时，最久没用的条目先被淘汰。所以预取层和权重层主要在某个目标第一次出现，或者缓存被清掉之后才用到。预取覆盖最近使用的目标，数量上限是内存预算允许的目标数的一半。

## 过滤与补足

每一层给出的节点先过滤一遍，满足任一条件的节点被去掉：

- 已不是本组成员；
- 被屏蔽：累计失败过多，或通过 API 手动屏蔽；
- 不可用：熔断器打开；3 分钟内拨号或探测失败过；最近一次测速失败；或者测速记录早于 3 × `interval`。从未测速过的节点算作可用，这样刚启动时也有节点可选；
- 这是 UDP 连接，而节点不支持 UDP；
- 对当前目标处于 10 分钟软屏蔽中，见 [健康检查与故障处理](../health/#处置分级)；
- 权重低于 0.4（unwrap 缓存层不看权重）。

除 unwrap 缓存层外，候选最多保留 10 个；不足 10 个时依次补足：设置了 `policy_priority` 时按优先级系数，否则依次按后台排名、测速延迟、随机抽样。如果过滤后一个都不剩，就退回任意可用节点；仍然没有，就取前 10 个成员，保证连接总有节点可以尝试。

## 排序叠加

候选列表确定后，再经过以下几层调整。这些调整**只改顺序，不增删节点**，排在第一位的节点最先拨。

1. **`policy_priority`**：按“优先级系数 × 手动指定认可加成”稳定排序。系数大于 1 的节点会排到所有系数为 1 的节点前面，与权重高低无关。见 [节点偏好与手动指定](../priority-and-pinning/)。
2. **选路算法**：把某个候选换到第一位，例如 `p2c` 从前 5 个中随机取两个比较。见 [选路算法](../algorithms/)。
3. **`hysteresis`**：窗口内这个目标上一次成功用过的节点如果还在候选中，就把它换回第一位，减少来回切换。
4. **请求场景重排**：只对排序型算法（`strict-best`、`least-loaded`、`fastest-recent`、`latency-banded`）生效，只调整前 5 个。下载、流媒体按节点的峰值下载速度排；SSH、远程桌面、游戏、语音按近期 RTT 排。场景按端口和域名关键字判断，例如 22、3389 端口算交互，3478、27000–28000 端口算实时。
5. **可疑节点后移**：最近 15 分钟内对这个目标 TLS 探测失败，或近期成功率低于 40% 的节点挪到末尾，但不删除，所有节点都可疑时仍有节点可用。

`sticky-session` 算法有一条快速路径：这个目标上次成功的节点仍然可用且不可疑时，直接用它，跳过上面全部步骤。

## 拨号与重试

TCP 拨号最多 4 轮，每轮拨下表中的候选，先连通的胜出，其余取消：

| 轮次 | 拨号的候选 | 说明 |
|---|---|---|
| 第 0 轮 | 第 1 个，或第 1、2 个 | 选择型算法拨 1 个，排序型算法拨 2 个；排序型算法的首选节点近期成功率 ≥ 95% 时也只拨 1 个 |
| 第 1 轮 | 第 3–5 个 | 并行拨号 |
| 第 2 轮 | 第 6–8 个 | 同上 |
| 第 3 轮 | 第 9–10 个 | 同上 |

- **对冲拨号**：第 0 轮只拨 1 个节点、且这个节点“可疑”（近期有拨号失败、3 分钟内被标记不可用，或本次运行中还没有拨通或测速成功过）时，250 ms 后同时拨第 2 个候选，谁先连通用谁。健康的节点通常在 250 ms 内就连上了，不会触发对冲。
- **每轮超时**：这一轮节点历史建连耗时的 2 倍；没有历史或超过 10 秒时为 10 秒。因超时结束的一轮之后，会等待约 20–200 ms 再进入下一轮；很快就失败的一轮（例如连接被拒绝）不等待。
- **重新选择**：某一轮已经没有候选可拨（候选少于 9 个时会出现）而仍未成功时，Smart 重新选择一次——此时刚失败的节点已被标记为不可用，会选出别的节点——再从第 0 轮开始。每次拨号最多重选一次。手动指定的节点失败时也走这一步，详见 [手动指定节点](../priority-and-pinning/#手动指定节点)。
- **失败的后果**：每次不是因取消导致的拨号失败，都会把该节点标记为不可用 3 分钟、计入熔断器，并记一条失败统计。

UDP 不并行：依次尝试前 3 个候选，每个超时为历史建连耗时的 2 倍或 10 秒。UDP 失败同样会把节点标记为不可用 3 分钟，但不计入熔断器。

拨号成功后，Smart 记住这次用的节点（用于 `now`、`sticky-session` 和 `hysteresis`），并把实际节点写入连接的出站链。所以在 Clash API 的 `/connections` 中，经过 Smart 的连接显示为 `["node-a", "auto", ...]`，实际节点排在最前。

## 记录与学习

连接关闭时，Smart 把这条连接的结果交给后台队列处理。队列已满时直接丢弃这条样本，不会拖慢连接关闭。

### 统计记录

每个（组, 目标, 节点）对应一条记录，包括：成功与失败次数、建连耗时与首字节延迟（平滑平均）、上下行流量与峰值速率、连接时长、最后使用时间，以及分槽保存的权重：`tcp`、`udp`，开启 ASN 后还有 `tcp_asn:<ASN>`、`udp_asn:<ASN>`。

每条记录还在内存中维护四个按样本数计算的指数滑动平均，用来捕捉“最近变好或变差”。它们不写入磁盘，重启后清零：

| 指标 | 窗口（样本数） | 用途 |
|---|---|---|
| 短期 RTT | 30 | `fastest-recent`、`p2c`、`latency-banded`、场景重排 |
| 短期成功率 | 20（前 11 个样本读数为 0） | 判断可疑节点、决定第 0 轮是否只拨 1 个 |
| 长期 RTT | 900 | 近期变差惩罚、训练数据 |
| 长期成功率 | 600 | 训练数据 |

### 权重公式

权重是 Smart 给（目标, 节点）打的分，越高越优先，低于 0.4 的节点不会被选为候选。未启用 LightGBM 或模型尚未加载时，权重由传统公式计算；同一（目标, 节点）少于 2 个样本时不计算。

1. **识别连接场景**：按流量形态分为 interactive、streaming、transfer、web、realtime、voip、api 七类，每类有一套不同的系数和上限。
2. **成功率**：对按时间衰减后的成功、失败次数取 Wilson 置信下限（z = 1.645）。样本越少越保守：1 次成功只得 0.27，10 次全部成功得 0.79。
3. **延迟得分**：建连耗时与首字节延迟分别按 `exp(−ms / 1500)` 换算；抖动越大扣分越多，最多扣 40%。
4. **基础分**：`1.6 × 成功率^a × 建连得分^b × 延迟得分^c`，指数随场景变化；UDP 提高延迟与成功率的比重。
5. **修正项**：乘以流量、时长、质量、效率等因子；流媒体与下载场景按峰值带宽最多加 20%；最近 RTT 明显变差或近期成功率偏低时最多扣 30%；样本少时再乘以置信系数（不低于 0.7）。
6. **优先级**：乘以 `policy_priority` 系数与手动指定认可加成；手动指定期间再乘 1.15。
7. **场景上限**：超出该场景可接受的延迟或建连耗时（例如 realtime 为 150 ms / 300 ms）时，权重封顶 0.38，低于可选门槛 0.4；成功率低于场景下限时按差距打折。

| 场景 | 延迟上限 | 建连上限 | 最低成功率 |
|---|---|---|---|
| realtime | 150 ms | 300 ms | 80% |
| voip | 200 ms | 400 ms | 75% |
| interactive | 300 ms | 500 ms | 70% |
| streaming | 600 ms | 800 ms | 75% |
| api | 600 ms | 600 ms | 70% |
| web | 800 ms | 1000 ms | 60% |
| transfer | 不限 | 不限 | 70% |

新算出的权重与旧值平滑合并：`新权重 = max((4 × 旧 + 2 × 新) / 6, 0.1)`，即每个新样本占三分之一，单次异常不会让权重大起大落。

启用 LightGBM 且模型已加载时，模型的输出**直接替代**上述公式的结果，再乘以优先级系数，详见 [LightGBM 模型](../lightgbm/)。

### 时间衰减

旧数据不会被删除，而是在读取时按时间打折：权重乘以 `2^(−小时数 / 半衰期)`，小时数取整。这样一个节点很久以前的好成绩，不会一直压过它最近的表现。

- 基础半衰期 168 小时（7 天），可用环境变量 `SMART_DECAY_HALF_LIFE_HOURS` 调整。
- 样本越少，半衰期越长：约 20 个样本时为 1 倍，5 个以下为 3 倍，40 个以上为 0.5 倍。
- 失败记录的半衰期再乘 2（`SMART_FAILURE_STICKY`），所以失败比成功记得更久。
- 选路时衰减系数不低于 0.4，避免久未使用的好节点被完全遗忘。
- `SMART_LEGACY=1` 可切换回旧版的分段衰减曲线。

### 劣化与恢复

除了按目标的统计，Smart 还为每个节点在组内维护一个失败计数 F。连接以失败告终时 F 加 1，节点的劣化系数为 `max(0.1, 1 − 0.01 × F)`，会压低它的权重。F 达到 30（系数降到 0.7）时，节点被屏蔽 `30 + 2F + ⌊F/10⌋` 分钟（F = 30 时为 93 分钟）。另外，443 端口上没有传输任何数据就结束的连接，或权重骤降超过 30%，也会把节点标记为劣化，并清除这个目标的 unwrap 缓存。

后台每 5 分钟检查一次：屏蔽到期即解除；没被屏蔽的节点劣化系数加 0.01、F 乘以 0.95，系数回到 0.99 以上即视为恢复。

如果同一个目标在本组已累计劣化 `max_host_failed_times` 次（默认 10），Smart 认为是目标网站本身有问题，此后这个目标的失败不再算到节点头上。

更快的处置手段（不可用 3 分钟、熔断、按目标软屏蔽）见 [健康检查与故障处理](../health/)。

## 后台任务

每个 Smart 组运行以下周期任务。标为“空闲跳过”的任务在组空闲时不执行：从未成功拨号过，或最近 2 分钟没有成功拨号。手机放在口袋里不用时，这些任务就不会耗电。

| 任务 | 首次 | 周期 | 空闲跳过 | 作用 |
|---|---|---|---|---|
| 健康检查 | 10 秒 | `interval` | 是 | 测速探测，见 [健康检查](../health/#主动探测) |
| 排名 | 45 秒 | 1 分钟 | 是 | 计算节点排名快照 |
| 预取 | 30 秒 | 2 分钟 | 是 | 为最近用过的目标预先算好候选列表 |
| 恢复检查 | 5 分钟 | 5 分钟 | 是 | 解除到期屏蔽，恢复劣化节点 |
| 目标可疑度探测 | 2 分钟 | 15 分钟 | 是 | 对热门目标做 TLS 握手探测 |
| Watchdog 扫描 | 10 秒 | 2.5 秒 | 否 | 检查卡住的连接 |
| 写盘 | 5 秒 | 5 分钟 | 否 | 把队列中的统计写入缓存文件 |
| 缓存预算调整 | 5 秒 | 5 分钟 | 否 | 按预算重设内存缓存 |
| 内存表清理 | 3 分钟 | 5 分钟 | 否 | 清理过期的内存记录 |
| 清理旧记录 | 10 分钟 | 2 小时 | 否 | 记录过多时裁剪 |
| 清理离组节点 | 10 分钟 | 10 分钟 | 否 | 删除已不在组内的节点数据 |
| 清理离组的组 | 15 分钟 | 2 小时 | 否 | 删除已不存在的组的数据 |

`smart-loadbalance` 组另有三个任务：地区探测（约 90 秒后首次，周期 `region.probe.interval`，空闲跳过）、出口复测（每小时，重新探测结果过期的节点）、负载均衡内存清理（3 分钟后首次，每 5 分钟）。

- 多个 Smart 组的同名任务按黄金分割错开首次启动时间（最多错开 30 秒，周期较短时为周期的四分之一），再加上不超过周期 10% 的随机偏移，避免同时启动挤占 CPU。
- 设备休眠或系统时钟跳变后，任务从当前时间继续，不补跑错过的周期；上一轮还没跑完时，跳过这次触发。
- 排名任务的最小间隔随节点数放宽：100 个以内 1 分钟，250 个以内 3 分钟，500 个以内 5 分钟，更多时 10 分钟。第一次成功拨号 2 秒后会额外计算一次排名。

排名的算法：对每个节点，取它在各活跃目标预取结果前 10 名中的权重平均值，换算为 0–100 分；前 20% 标为 `MostUsed`，接下来的 50% 为 `OccasionalUsed`，其余为 `RarelyUsed`。

## 当前节点

面板和 `GET /proxies/{name}` 中的 `now` 按以下顺序确定：

1. 手动指定的节点（未暂停时）；
2. 最近一次成功拨号用的节点；
3. 排名中第一个权重大于 0 的节点；
4. 测速延迟最低的节点；
5. 第一个成员。

Smart 按目标选节点，所以 `now` 只表示“最近用过的节点”，并不代表所有连接都走它。要看每条连接实际用的节点，请看 `/connections` 中的 `chains`。列出地区出站的 `smart-loadbalance` 组，`now` 显示的是地区出站，见 [Smart 负载均衡](../smart-loadbalance/)。

## 多个 Smart 组之间共享什么

- 一个探测队列和探测线程池，线程数为 2 × CPU 核数，限制在 8–32 之间。相同节点、相同探测地址的探测会合并，1 秒内的结果直接复用；
- 一个统计记录队列（4 个线程、2048 个槽位，满时丢弃样本）；
- 同一个缓存文件与内存缓存预算；
- LightGBM 模型、训练数据文件，以及 ASN、国家数据库的读取器。

统计数据按组隔离：同一个节点在两个 Smart 组中的权重互不影响。所以同一批节点放进多个 Smart 组，就要各自从头学习一遍。

<Callout type="note" title="嵌套策略组">
  Smart 的成员可以是 `urltest`、`selector` 等其他策略组。Smart 把它们当作普通节点：统计、测速都记在该组的标签下，衡量的是它当时选中的那个节点。`direct`、`block`、`dns` 类型的成员不参与统计和探测。
</Callout>
