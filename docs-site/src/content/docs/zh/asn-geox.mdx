## ASN 有什么用

同一家公司的服务往往分布在多个域名下，但落在同一个自治系统（ASN）里，例如 Google 的 `*.google.com`、`*.youtube.com`、`*.gstatic.com` 都属于 AS15169。开启 `use_asn` 后，节点访问其中一个域名的表现，也会被用来为同 ASN 的其他域名选节点。

## 开启后发生了什么

- **查询**：拨号时用目标的公网 IP 查询 ASN。只有拨号前已经知道 IP 才能查到（例如已解析的地址或 FakeIP 映射）；私有地址与回环地址跳过。只有域名的连接会在关闭时额外做一次最长 200 ms 的 DNS 查询来补上 ASN。
- **记录**：权重写入 `tcp_asn:<ASN>` / `udp_asn:<ASN>` 槽位，同时把通用的 `tcp` / `udp` 槽位设为各 ASN 槽位中的最小值。成功率、延迟等计数仍按（目标, 节点）记录。
- **选路**：权重层查询时，如果目标有 ASN，就汇总**该 ASN 下所有目标**的权重：同一节点取最大值，但只要有一个低于 0.4 就取最小值。该 ASN 还没有数据时，这一层返回空，直接退到测速延迟层，不会再用该目标自己的权重。
- **预取**：预取结果额外按 ASN 保存一份引用，同 ASN 的新目标可以直接命中。
- **加分**：非 CDN 的 ASN 上成功次数达到 10、成功率超过 90% 时，权重最多再加 0.08。
- **模型**：LightGBM 的第 16、23 维特征需要 ASN，未开启时为 0。

### 被忽略的 ASN

以下 33 个 ASN 属于 Cloudflare、Akamai、Fastly、Amazon 等 CDN 与云服务商，以及 Cogent、Level 3 等骨干网。它们承载了大量互不相关的网站，按它们分组反而会把无关站点混在一起，所以不参与 ASN 分组和预取：

13335、12222、16625、20940、31110、35994、54113、22822、15133、19551、20446、60068、16509、36408、4809、199524、212238、55933、43260、43317、43996、52320、396982、16276、30081、12389、37888、45090、174、3356、3209、14061、8452。

## ASN 数据库从哪里来

每个开启 `use_asn` 的组按以下顺序确定数据库：

1. 本组的 `asn_database`：路径按原样使用，不拼接数据目录。图形客户端中相对路径相对于进程工作目录，请写绝对路径。
2. `experimental.geox.url.asn` 下载到数据目录的文件（需要 `geox.enabled: true`）。
3. 都没有时，使用默认数据库 `https://github.com/P3TERX/GeoLite.mmdb/releases/latest/download/GeoLite2-ASN.mmdb`，由 GeoX 下载到数据目录下的 `GeoLite2-ASN.mmdb`。

列出多个数据库时全部打开，查询时依次尝试，取第一个非零结果；打开失败的会被跳过。数据库需要是 MaxMind GeoLite2-ASN 格式（记录中有 `autonomous_system_number` 字段），字段不同的数据库（例如 IPinfo 的 ASN 库）查不到结果。

第 2、3 种数据库都由 GeoX 下载，使用 `experimental.geox` 中的 `http_client`、`auto_update` 与 `update_interval`（默认数据库在 GeoX 未启用时同样如此）。下载在后台进行，不阻塞启动；已有的文件会直接使用，不会在每次启动时重新下载。

数据库读取器在多个组之间共享。GeoX 下载或更新数据库后立即重新加载，所有组随即使用新数据，无需重启；启动时还没下载好的数据库，下载完成后也会自动启用，启动日志中此时显示 `asn=on(downloading)`。`asn_database` 指定的本地文件只在启动时读取，替换后需要重启。

## 国家数据库

LightGBM 的国家特征（第 17、26 维）需要国家数据库。Smart 优先使用 `experimental.geox.url.mmdb` 下载的 `country.mmdb`；没有配置时使用默认的 GeoLite2-Country（来自 P3TERX 的发布页），由 GeoX 下载到数据目录下的 `country.mmdb`。与 ASN 数据库一样，下载或更新后立即生效。

只有开启了 `use_lightgbm` 或 `collect_data` 的组，以及使用 `destination` 地区模式（或设置了 `destination.map`）的 `smart-loadbalance` 组，才会打开国家数据库并查询国家；`smart-loadbalance` 运行中切换到 `destination` 模式时才开始下载。见 [Smart 负载均衡](../smart-loadbalance/#destination)。

## experimental.geox

GeoX 统一管理地理数据文件的下载与更新，目前唯一的使用者是 Smart。

- `enabled: false` 时不下载 `url` 中的文件，Smart 也拿不到这里的路径；Smart 需要的默认数据库仍按本节的下载设置下载。
- `url` 没有默认值，只下载填写了地址的文件。
- 文件名固定：`GeoLite2-ASN.mmdb`（填写多个 ASN 地址时，第一个仍为 `GeoLite2-ASN.mmdb`，之后依次为 `GeoLite2-ASN-1.mmdb`、`GeoLite2-ASN-2.mmdb`……）、`country.mmdb`、`geoip.dat`、`geosite.dat`。`geoip.dat` 与 `geosite.dat` 目前没有组件使用。
- `auto_update: true` 时每个文件按 `update_interval` 定期更新；否则只在文件缺失时下载，已有的文件不再更新。
- 缺失文件下载失败时（例如开机时网络尚未就绪），按 30 秒起、逐次翻倍、最长 30 分钟的间隔重试，直到成功。
- 下载使用 `http_client` 的全部设置：出站与其他拨号选项、TLS、请求头、HTTP 版本。没有 `http_client` 时使用 `download_detour`，都没有则使用默认 HTTP 客户端（`route.default_http_client`）。

## 相关日志

| 日志 | 含义 |
|---|---|
| `smart: ASN database loaded from <path>` | 数据库已打开 |
| `smart: ASN database not configured per-group; using ...` | 使用 GeoX 下载的 `url.asn` 数据库 |
| `smart: no ASN database configured; using the default database GeoX keeps at <path>` | 使用默认数据库 |
| `smart: ASN database <path> is downloading; it is used once the download completes` | 数据库还在下载，完成后自动启用 |
| `smart: failed to open ASN database [<path>] ...` | 某个数据库打开失败，其余继续尝试 |
| `geox: reloaded <name> from <path>` | 下载或更新完成，数据库已重新加载 |
| `assetdl[<name>]: download failed, retrying in <间隔>: ...` | 缺失文件下载失败，稍后重试 |
