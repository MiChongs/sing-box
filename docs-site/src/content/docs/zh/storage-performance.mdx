## 数据保存在哪里

Smart 使用 `experimental.cache_file` 指定的 bbolt 数据库（默认 `cache.db`），所有数据放在 `smart_stats` bucket 中。命令行版本需要设置 `cache_file.enabled: true`；SFA / SFW / SFL 始终启用缓存文件。

没有缓存文件时，Smart 不记录统计，`WeightRanking` 等接口退回按测速延迟排名，手动指定只保存在内存中，`POST /smart/groups/{name}/block/{node}` 返回 `smart: store unavailable`。

### 键与记录类型

键的格式为 `smart/<类型>/singbox/<组>/...`，各段中的 `/`、`%` 与控制字符会被百分号转义。

| 类型 | 键 | 内容 |
|---|---|---|
| `stats` | `…/<组>/<目标>/<节点>` | 成功与失败次数、建连耗时、延迟、流量、峰值速率、时长、最后使用时间、各槽位权重 |
| `node` | `…/<组>/<节点>` | 失败计数、劣化系数、屏蔽截止时间 |
| `prefetch` | `…/<组>/<目标或 ASN>` | 预取得到的候选列表 |
| `ranking` | `…/<组>` | 节点排名 |
| `failures` | `…/<组>/<目标>` | 目标的劣化计数（用于 `max_host_failed_times`） |
| `manual` | `…/<组>` | 手动指定的节点 |
| `dead` | `…/<组>/<节点>` | 不可用标记的时间 |
| `breaker` | `…/<组>/<节点>` | 熔断器状态 |
| `pinendor` | `…/<组>/<节点>` | 手动指定的认可记录 |

记录以 JSON 写入。以下内容只在内存中，重启后重新积累：unwrap 缓存、短期与长期滑动平均、延迟标准差。

### 重启后恢复什么

冷启动，以及通过 SIGHUP 或 Clash API 重新加载配置后，Smart 都会从缓存文件恢复以下数据：

| 数据 | 恢复规则 |
|---|---|
| 统计、权重、预取、排名 | 全部保留，读取时按时间衰减 |
| 手动指定 | 节点仍在组内时恢复 |
| 不可用标记 | 3 分钟内的恢复，更早的删除 |
| 熔断器 | 仍处于打开窗口内的恢复 |
| 手动指定认可记录 | 14 天内的恢复 |

## 写盘

- 写入先进入内存队列，同一个键的多次写入在队列中合并为一次。队列中、正在提交中的数据都能被立即读到。
- 队列长度达到阈值（桌面 300，手机 204）时由唯一的写盘协程提交；另外每 5 分钟定时提交一次（多个组共享，5 秒内最多一次）。
- 每次提交是一个 bbolt 事务，提交后落盘同步。
- 退出时等待在途批次完成后再同步一次。

## 内存预算

Smart 的内存缓存按**实际字节**计量，总预算由环境变量 `SMART_CACHE_BUDGET_MB` 控制：桌面默认 32 MB，Android 与 iOS 默认 8 MB。预算平分为 6 份：

| 缓存 | 内容 | 过期 |
|---|---|---|
| 目标缓存 | 域名到目标键的换算结果 | 无 |
| unwrap 缓存 | 每个目标的上次候选列表 | 无，按事件清除 |
| 记录缓存 | 统计记录，每条按 768 字节计 | 无 |
| 查询缓存 | 前缀扫描结果 | 300 秒 |
| 屏蔽缓存 | 每组被屏蔽的节点集合 | 300 秒 |
| 统计索引 | 按组解码的统计，用于预取与权重查询 | 1 分钟，或积累 1024 次写入后重建 |

由预算推导出的上限：

| | 桌面（32 MB） | 手机（8 MB） |
|---|---|---|
| 每份缓存 | 约 5.3 MB | 约 1.3 MB |
| 记录缓存可容纳 | 约 7300 条 | 约 1800 条 |
| 目标数上限 `MaxTargets` | 5000 | 3276 |
| 预取覆盖的组合数 | 2500 | 1638 |
| 写盘阈值 | 300 | 204 |

预算每 5 分钟按当前设置重新应用一次。缓存满时由准入策略决定淘汰，不会超出预算。

## 数据清理

| 任务 | 周期 | 做什么 |
|---|---|---|
| 清理旧记录 | 每 2 小时（首次 10 分钟） | 某类记录超过 2 × `MaxTargets` 时裁剪到 `MaxTargets`，优先删除没有时间戳的、样本最少的、最旧的 |
| 清理离组节点 | 每 10 分钟 | 删除已不在组内的节点的统计、预取、排名与状态 |
| 清理离组的组 | 每 2 小时（首次 15 分钟） | 删除配置中已不存在的组的全部数据 |

数据不会因为“太旧”而被删除，旧数据通过读取时的时间衰减逐渐失去影响，衰减规则见 [工作原理](../how-it-works/#时间衰减)。

要立即清空，使用 Clash API：

- `DELETE /proxies/{name}/weights`：清空一个组的全部数据并重新计算；
- `POST /cache/smart/flush/{name}`：同上；
- `POST /cache/smart/flush`：清空所有当前配置中的 Smart 组。

## 节点很多时

以下机制让后台开销不随节点数线性增长：

- **探测预算**：每轮只测排名前 16 与 `max(24, ⌈N/10⌉)` 个轮转节点，失败的节点指数退避到 1 小时。500 个节点时每轮约 66 次探测。
- **排名节流**：排名重算的最小间隔随节点数放宽到 10 分钟（500 个以上）。
- **空闲暂停**：2 分钟没有成功拨号时，健康检查、排名、预取、恢复检查与目标探测全部暂停。
- **增量索引**：预取与按目标选路使用增量维护的统计索引，按目标选路一次约 0.6 µs。
- **推理缓存**：LightGBM 结果缓存 30 秒。
- **有界队列**：探测队列 1024、统计队列 2048，满时丢弃而不阻塞；事件计数表上限 4096 个组合。

建议：

- 用 `include` / `exclude` 去掉明显不需要的节点，候选越少，学习越快。
- 多个 Smart 组引用同一个订阅时，统计按组分别保存，内存与磁盘占用成倍增加。只在确实需要不同算法时才拆分多个组。
- `interval` 保持默认的 3 分钟或更长，见 [健康检查](../health/#何时探测)。

## 手机与低内存设备

- 默认预算已降为 8 MB；内存特别紧张时可以设置更小的 `SMART_CACHE_BUDGET_MB`，代价是更多的磁盘读取。
- 探测会唤醒射频，是耗电的主要来源。节点多时，探测预算与退避已经把每轮探测数压到 `16 + max(24, ⌈N/10⌉)`；不需要的节点用 `exclude` 去掉效果更明显。
- 设备休眠或时钟跳变后，周期任务从当前时间继续，不会集中补跑错过的周期。
