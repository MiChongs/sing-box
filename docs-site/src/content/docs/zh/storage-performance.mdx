Smart 的学习成果（每个节点访问每个目标的统计与权重）保存在 sing-box 的缓存文件里，重启后接着用。这一页说明存了什么、占多少内存与磁盘、如何清空，以及节点很多或在手机上运行时怎样减少开销。只想正常使用时，记住一点即可：**命令行版本必须开启 `experimental.cache_file`**。

## 数据保存在哪里

Smart 使用 `experimental.cache_file` 指定的 bbolt 数据库（默认数据目录下的 `cache.db`），所有数据放在其中的 `smart_stats` bucket 里，与规则集、FakeIP 等其他缓存分开。命令行版本需要设置 `cache_file.enabled: true`；SFA / SFW / SFL 图形客户端始终启用缓存文件。

```json
"experimental": {
  "cache_file": { "enabled": true }
}
```

没有缓存文件时 Smart 仍能工作，但：

- 不记录任何统计，选路只依据测速延迟，`/proxies/{name}/weights` 等接口返回按延迟生成的排名；
- 手动指定与 `smart-loadbalance` 的地区锁定只保存在内存中，重启后丢失；
- `POST /smart/groups/{name}/block/{node}` 返回 `smart: store unavailable`。

启动日志出现 `smart: no cache file available, using ephemeral store` 就是这种情况。

### 键与记录类型

每条记录的键为 `smart/<类型>/singbox/<组>/...`，各段中的 `/`、`%` 与控制字符会被百分号转义，所以名称含 `/` 的节点也能正确存取。

| 类型 | 键 | 内容 |
|---|---|---|
| `stats` | `…/<组>/<目标>/<节点>` | 成功与失败次数、建连耗时、延迟、流量、峰值速率、时长、最后使用时间、各槽位权重 |
| `node` | `…/<组>/<节点>` | 失败计数、劣化系数、屏蔽截止时间 |
| `prefetch` | `…/<组>/<目标或 ASN>` | 预取得到的候选列表 |
| `ranking` | `…/<组>` | 节点排名 |
| `failures` | `…/<组>/<目标>` | 目标的劣化计数（用于 `max_host_failed_times`） |
| `manual` | `…/<组>` | 手动指定的节点 |
| `dead` | `…/<组>/<节点>` | 不可用标记的时间 |
| `breaker` | `…/<组>/<节点>` | 熔断器状态 |
| `pinendor` | `…/<组>/<节点>` | 手动指定的认可记录 |
| `region` | `…/<组>` | `smart-loadbalance` 的地区锁定，以及运行中切换过的地区模式、分配策略、会话亲和 |
| `exitgeo` | `…/<组>/<节点>` | `smart-loadbalance` 出口探测得到的国家与出口 IP |

统计记录以 msgpack 写入（旧版本写入的 JSON 记录仍能读取），其余记录为 JSON。

以下内容只在内存中，重启后重新积累：unwrap 缓存（每个目标上次的候选列表）、短期与长期滑动平均、延迟标准差、`sticky-session` 与 `hysteresis` 的记忆、按目标的 SNI 探测结果；`smart-loadbalance` 的目标地区记忆、会话亲和绑定、地区探测结果与目标国家缓存。

### 重启后恢复什么

冷启动，以及通过 SIGHUP 或 Clash API 重新加载配置后，Smart 都会从缓存文件恢复以下数据：

| 数据 | 恢复规则 |
|---|---|
| 统计、权重、预取、排名 | 全部保留，读取时按时间衰减 |
| 手动指定 | 节点仍在组内时恢复 |
| 不可用标记 | 3 分钟内的恢复，更早的删除 |
| 熔断器 | 仍处于打开窗口内的恢复 |
| 手动指定认可记录 | 14 天内的恢复 |
| 地区锁定与运行时设置 | 全部恢复；锁定的地区暂时没有成员时按 `region.fallback` 处理 |
| 出口探测结果 | `detect.exit_ttl`（默认 24 小时）内的恢复，过期的删除 |

## 写盘

- 写入先进入内存队列，同一个键的多次写入在队列中合并为一次。队列中、正在提交中的数据都能被立即读到，不会出现“刚写入却读到旧值”。
- 队列长度达到阈值（桌面 300，手机 204）时由唯一的写盘协程提交；另外每 5 分钟定时提交一次（多个组共享这个任务，5 秒内最多执行一次）。
- 每次提交是一个 bbolt 事务，提交后同步到磁盘。
- 退出时等待正在提交的批次完成后再同步一次，所以正常退出不会丢失最后一批数据。

## 内存预算

Smart 的内存缓存按**实际字节**计量，总预算由环境变量 `SMART_CACHE_BUDGET_MB` 控制：桌面默认 32 MB，Android 与 iOS 默认 8 MB。预算平分为 6 份：

| 缓存 | 内容 | 过期 |
|---|---|---|
| 目标缓存 | 域名到目标键的换算结果 | 无 |
| unwrap 缓存 | 每个目标的上次候选列表 | 无，按事件清除 |
| 记录缓存 | 统计记录，每条按 768 字节计 | 无 |
| 查询缓存 | 前缀扫描结果 | 300 秒 |
| 屏蔽缓存 | 每组被屏蔽的节点集合 | 300 秒 |
| 统计索引 | 按组解码的统计，用于预取与权重查询 | 1 分钟，或积累 1024 次写入后重建 |

由预算推导出的上限：

| | 桌面（32 MB） | 手机（8 MB） |
|---|---|---|
| 每份缓存 | 约 5.3 MB | 约 1.3 MB |
| 记录缓存可容纳 | 约 7300 条 | 约 1800 条 |
| 目标数上限 `MaxTargets` | 5000 | 3276 |
| 预取覆盖的组合数 | 2500 | 1638 |
| 写盘阈值 | 300 | 204 |

预算每 5 分钟按当前设置重新应用一次。缓存满时由准入策略决定淘汰哪些条目，不会超出预算；被淘汰的数据仍在磁盘上，下次需要时重新读取。

`smart-loadbalance` 另有几项不计入上述预算的小型内存表，各有上限：目标地区记忆与会话亲和绑定各 16384 条（超出时先删过期的，仍超出则清空），地区探测追踪 1024 个目标，目标国家缓存 4096 个域名。

## 数据清理

| 任务 | 周期 | 做什么 |
|---|---|---|
| 清理旧记录 | 每 2 小时（首次 10 分钟） | 某类记录超过 2 × `MaxTargets` 时裁剪到 `MaxTargets`，优先删除没有时间戳的、样本最少的、最旧的 |
| 清理离组节点 | 每 10 分钟 | 删除已不在组内的节点的统计、预取、排名与状态 |
| 清理离组的组 | 每 2 小时（首次 15 分钟） | 删除配置中已不存在的组的全部数据 |

前两项由每个组各自清理自己的数据；清理离组的组由所有 Smart 组共享，同一周期内只执行一次。数据不会因为“太旧”而被删除：旧数据通过读取时的时间衰减逐渐失去影响，衰减规则见 [工作原理](../how-it-works/#时间衰减)。

### 手动清空

想让某个组从头学习（例如更换了订阅、节点质量整体变化），使用 Clash API：

| 方法 | 范围 |
|---|---|
| `DELETE /proxies/{name}/weights` | 一个组的全部数据，随后重新计算 |
| `POST /cache/smart/flush/{name}` | 同上 |
| `POST /cache/smart/flush` | 当前配置中的所有 Smart 组 |
| 停止 sing-box 后删除缓存文件 | 所有数据，**包括**规则集、FakeIP、选择器状态等其他缓存 |

清空不仅删除磁盘上的记录，也重置内存中的状态：手动指定、不可用标记、熔断器等全部清除；`smart-loadbalance` 组还会解除地区锁定、恢复配置中的模式与策略，并重新识别地区。

## 节点很多时

以下机制让后台开销不随节点数线性增长：

- **探测预算**：每轮只测排名前 16 与 `max(24, ⌈N/10⌉)` 个轮转节点，探测失败的节点按 3 分钟起、逐次翻倍、最长 1 小时退避。500 个节点时每轮约 66 次探测，而不是 500 次。
- **排名节流**：排名重算的最小间隔随节点数放宽：100 个以内 1 分钟，250 个以内 3 分钟，500 个以内 5 分钟，更多时 10 分钟。
- **空闲暂停**：2 分钟没有成功拨号时，健康检查、排名、预取、恢复检查、目标探测与 `smart-loadbalance` 的地区探测全部暂停，有流量后自动恢复。
- **增量索引**：预取与按目标选路使用增量维护的统计索引，按目标选路一次约 0.6 µs。
- **推理缓存**：LightGBM 结果缓存 30 秒。
- **有界队列**：探测队列 1024、统计队列 2048，满时丢弃而不阻塞；事件计数表上限 4096 个组合。

建议：

- 用 `include` / `exclude` 去掉明显不需要的节点。候选越少，学习越快，探测也越少。
- 多个 Smart 组引用同一个订阅时，统计按组分别保存，内存与磁盘占用成倍增加。只在确实需要不同算法时才拆分多个组。
- `interval` 保持默认的 3 分钟或更长，见 [健康检查](../health/#何时探测)。

## 手机与低内存设备

- **内存**：默认预算已降为 8 MB。内存特别紧张时可以设置更小的 `SMART_CACHE_BUDGET_MB`，代价是更多的磁盘读取。
- **耗电**：探测会唤醒射频，是耗电的主要来源。节点多时，探测预算与退避已经把每轮探测数压到 `16 + max(24, ⌈N/10⌉)`；用 `exclude` 去掉不需要的节点效果更明显；`interval` 可以设为 5 分钟或更长。
- **smart-loadbalance**：地区探测只在有流量时运行，不需要时设 `region.probe.disabled: true`。出口探测结果保存 24 小时，默认只探测名称识别不了的节点；`detect.exit: prefer` 会每天探测全部节点，手机上不建议使用。
- **休眠**：设备休眠或时钟跳变后，周期任务从当前时间继续，不会集中补跑错过的周期。

<Callout type="note" title="图形客户端如何设置环境变量">
  SFA、SFW、SFL 不提供环境变量设置入口，使用默认预算即可。命令行版本可以在启动前导出环境变量，或写进 systemd 单元的 `Environment=`。
</Callout>
