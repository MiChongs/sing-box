这一页带你用最少的配置跑起一个 Smart 组，并教你判断它是否在正常工作。读完后再看 [工作原理](../how-it-works/)，就能理解它为什么这样选节点。遇到不认识的词，可以查 [术语表](../glossary/)。

## Smart 是什么

Smart 是一种出站组（策略组）：你把一批节点交给它，它为每条连接挑一个节点。和按延迟选节点的 `urltest` 不同，Smart 会**记住每个节点访问每个网站的实际表现**——连得上没有、建连多快、首字节多快、传了多少数据——再根据这些记录给节点打分。同一个节点访问 A 网站很快、访问 B 网站很慢，Smart 会分开记下来，下次访问 B 时换别的节点。

如果你想把连接分摊到同一地区的多个节点上，而不是集中到一个最好的节点，请看 [Smart 负载均衡](../smart-loadbalance/)。

## 准备

- **程序**：Smart 只存在于 xiaobaf14g 分支。从 [Releases](https://github.com/MiChongs/sing-box/releases) 下载命令行程序，或下载同一页面发布的图形客户端 SFA（Android）、SFW（Windows）、SFL（Linux）。上游 sing-box 与 reF1nd 分支不认识 `"type": "smart"`，加载配置时会报 `unknown outbound type: smart`。
- **节点**：一个订阅地址，或者配置文件中已有的若干出站。
- **（可选）面板**：想在网页上查看和切换节点，需要开启 Clash API，并使用 [metacubexd](https://github.com/MetaCubeX/metacubexd)、[zashboard](https://github.com/Zephyruso/zashboard) 等面板。

## 最小配置

<CodeBlock code={minimal} filename="01-minimal.json" locale="zh" />

逐段说明：

- **`providers`**：定义一个远程订阅 `my-subscription`，每 12 小时更新一次。Smart 组通过 `"providers": ["my-subscription"]` 使用其中的全部节点。不用订阅时，改用 `"outbounds": ["节点A", "节点B"]` 直接列出节点标签。
- **`smart` 组**：除标签和成员外全部使用默认值——每 3 分钟用 `https://www.gstatic.com/generate_204` 测一次节点，选路算法为 `strict-best`（总是先用得分最高的节点）。
- **`route.final`**：没有命中任何路由规则的流量都交给 Smart。
- **`experimental.cache_file`**：Smart 学到的数据都保存在这里，**必须开启**，见下方提示。
- **`experimental.clash_api`**：供后面的检查步骤和面板使用，不需要时可以删掉。

<Callout type="warn" title="不要省略 cache_file">
  Smart 的统计、权重、手动指定、熔断状态都存放在缓存文件里。命令行版本没有开启 `cache_file` 时，Smart 无处记录，只能按测速延迟选节点，效果和一个更复杂的 `urltest` 差不多；启动日志会出现 `smart: no cache file available, using ephemeral store`。图形客户端始终开启缓存文件，不需要配置。
</Callout>

对应的命令：

```bash
curl -s http://127.0.0.1:9090/smart/groups
curl -s http://127.0.0.1:9090/proxies/auto/weights
curl -s 'http://127.0.0.1:9090/proxies/auto/weights?full=1'   # 附带按目标的明细
```

设置了 `secret` 时，每个请求都要加上 `-H 'Authorization: Bearer <secret>'`。

### 怎样算“在学习”

使用一段时间后，`/proxies/auto/weights` 里的 `sampleCount`（参与计算的连接数）和 `targetCount`（涉及的网站数）会持续增长，`weight` 开始出现差别。加上 `?full=1` 能看到每个网站各节点的成功、失败次数和延迟，这就是 Smart 选节点的依据。

在面板中，Smart 组显示为 `Smart` 类型。你可以像 `selector` 一样点击某个节点来手动指定它，Smart 会一直用这个节点，直到你取消；节点故障时会临时换用其他节点，恢复后自动切回。详见 [节点偏好与手动指定](../priority-and-pinning/)。

## 读懂启动日志

正常启动时，每个 Smart 组会打印一行摘要：

```text
smart[auto] started: 42 outbounds, 12 background tasks, testURL=https://www.gstatic.com/generate_204 interval=3m0s asn=off algorithm=strict-best hysteresis=off ml=off collect=off
```

| 字段 | 含义 |
|---|---|
| `42 outbounds` | 本组的成员数。订阅的节点在订阅加载后才加入；订阅还没加载完时，这里可能只有 1（内置的直连出站 `Compatible`） |
| `testURL` / `interval` | 测速地址与测速周期 |
| `asn` | ASN 学习：`off` 未开启；`on` 已开启；`on(downloading)` 数据库还在下载；`on(no-db)` 没有可用数据库 |
| `algorithm` | **实际生效**的选路算法。写错算法名不会报错，而是回退到 `strict-best`，所以以这一项为准 |
| `hysteresis` | 防抖窗口，`off` 表示关闭 |
| `ml` | LightGBM 模型状态，见下表 |
| `collect` | 训练数据采集：`off`，或 `on(采样比例)` |

| `ml` 的值 | 含义 |
|---|---|
| `off` | 本组没有开启 `use_lightgbm` |
| `pending` | 已开启，模型还在下载或尚未加载，暂时用传统公式打分 |
| `unusable` | 已开启，但模型文件无法使用（格式或特征不受支持），用传统公式打分，原因见 WARN 日志 |
| `loaded` | 模型已加载，由模型打分 |

## 常见的启动问题

- **日志出现 `smart: no cache file available, using ephemeral store`**：没有开启 `experimental.cache_file`，Smart 不会学习。
- **`weights` 一直是测速排名**：还没有足够的连接记录。确认流量确实经过 Smart（路由规则可能把流量交给了别的出站），再多用一会儿。
- **面板中成员一直只有 `Compatible`**：`outbounds` 和订阅都没有提供节点，例如订阅下载失败，或节点被 `include` / `exclude` 全部过滤掉。没有成员时 Smart 会退回内置的直连出站 `Compatible`，流量将不经代理直接发出。
- 其他问题见 [故障排查](../troubleshooting/)。
