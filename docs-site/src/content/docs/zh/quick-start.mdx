这一页带你用最少的配置跑起一个 Smart 组，并教你判断它是否在正常工作。读完后再看 [工作原理](../how-it-works/)，就能理解它为什么这样选节点。遇到不认识的词，可以查 [术语表](../glossary/)。

## Smart 是什么

Smart 是一种出站组（策略组）：你把一批节点交给它，它为每条连接挑一个节点。和只看测速延迟的 `urltest` 不同，Smart 记住**每个节点为每个服务实际干得怎么样**——连没连上、有没有回应、多快、传了多少、有没有丢包——再据此选择。

它由两部分思路合成：

- **综合评分来自 [honk](https://github.com/daeuniverse/honk)**（daeuniverse/honk 的 Score 策略）：先按衰减后的成功率判断哪些节点“可靠”，只在可靠的节点之间比较延迟、吞吐与连接质量；正在用的节点只有被证明更差才会被换掉。
- **服务识别、封锁与探测来自 [vernesong/mihomo](https://github.com/vernesong/mihomo) 的 Smart 组**：命中的路由规则就是一个“服务”，同一服务收敛到一个出口；节点只对出问题的网站封锁；短连接会经同一节点复查网站的真实响应。

想把连接分摊到同一地区的多个节点上，请看 [Smart 负载均衡](../smart-loadbalance/)。

<Callout type="warn" title="从旧版 Smart 升级">

## 准备

- **程序**：Smart 只存在于 xiaobaf14g 分支。从 [Releases](https://github.com/MiChongs/sing-box/releases) 下载命令行程序，或同一页面发布的图形客户端 SFA（Android）、SFW（Windows）、SFL（Linux）。上游 sing-box 不认识 `"type": "smart"`，会报 `unknown outbound type: smart`。
- **节点**：一个订阅，或者配置文件中已有的若干出站。
- **（可选）面板**：想在网页上查看和切换节点，开启 Clash API，并使用 [metacubexd](https://github.com/MetaCubeX/metacubexd)、[zashboard](https://github.com/Zephyruso/zashboard) 等面板。

逐段说明：

- **`providers`**：定义一个远程订阅 `my-subscription`。Smart 组通过 `"providers": ["my-subscription"]` 使用其中的全部节点；不用订阅时，改用 `"outbounds": ["节点A", "节点B"]` 列出节点标签。
- **`smart` 组**：除标签和成员外全部使用默认值——组在使用中时每 5 分钟用 `https://www.gstatic.com/generate_204` 检查一次成员，空闲 30 分钟后暂停检查。
- **`route.final`**：没有命中任何路由规则的流量都交给 Smart。
- **`experimental.cache_file`**：学习数据每 5 分钟写入这里，重启后接着用。不开启时 Smart 照样学习，只是每次重启都从零开始。图形客户端始终开启缓存文件。
- **`experimental.clash_api`**：供后面的检查步骤和面板使用。

对应的命令：

```bash
curl -s http://127.0.0.1:9090/smart/groups
curl -s http://127.0.0.1:9090/group/auto/weights
curl -s http://127.0.0.1:9090/smart/groups/auto/diag   # 选择原因、服务池、封锁记录
```

设置了 `secret` 时，每个请求都要加上 `-H 'Authorization: Bearer <secret>'`。

### 怎样算“在学习”

使用一段时间后，`/group/auto/weights` 里各成员的 `Success`、`Completed` 会持续增长，`Weight` 开始出现差别，常用的节点 `Pool` 为 `true`。`/smart/groups/auto/diag` 的 `selection[].reasons` 统计了每次选择的理由，例如 `incumbentHeld`（继续用原来的节点）、`performanceWinner`（换到更好的节点）、`coldExplore`（试用还没有数据的节点），见 [综合评分与选择](../scoring/#选择理由)。

在面板中，Smart 组显示为 `Smart` 类型。点击某个节点即手动指定：之后新连接只走这个节点，直到你取消。详见 [手动指定](../how-it-works/#手动指定)。

## 看日志

Smart 平时很安静。把 `log.level` 设为 `debug` 可以看到它在做什么，日志前缀是 `outbound/smart[<组标签>]`：

```text
DEBUG outbound/smart[auto]: dial HK-02 for api.example.com failed: i/o timeout
DEBUG outbound/smart[auto]: converged 3 connections of [RuleSet [geosite-openai]] on JP-01
DEBUG outbound/smart[auto]: node US-03 refused for www.example.com: region unavailable
DEBUG outbound/smart[auto]: node HK-05 lowWeight for [*.example.com]
INFO  outbound/smart[auto]: manual pin set to HK-01
```

- `converged`：某个服务的主选节点失败、由备用节点接手后，这个服务经其他节点的连接被关闭，统一到新节点（见 [收敛](../service-keys/#收敛)）。
- `refused for`：响应探测发现网站拒绝了这个节点（见 [响应探测](../blocks-and-probes/#响应探测)）。
- `lowWeight`、`error`、`loss`、`stalled`、`answer`、`manual`：节点被封锁的原因（见 [封锁代码](../blocks-and-probes/#封锁代码)）。

## 常见的启动问题

- **`interval must be less or equal than idle_timeout`**：`interval` 设得比 `idle_timeout`（默认 30 分钟）还长。
- **面板中成员一直只有 `Compatible`**：`outbounds` 和订阅都没有提供节点，例如订阅下载失败，或节点被 `include` / `exclude` 全部过滤。此时流量经内置的直连出站直接发出。
- **`Weight` 全是 0**：还没有足够的连接记录，或流量根本没经过这个组（路由规则把它交给了别的出站）。
- 其他问题见 [故障排查](../troubleshooting/)。
