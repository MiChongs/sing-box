这一页按“症状”组织。先找到与你遇到的现象最接近的小节，每节依次说明可能的原因、怎么确认、怎么解决。文中提到的“目标”“熔断”“软屏蔽”等术语见 [术语表](../glossary/)，接口的完整说明见 [Clash API](../clash-api/)。

## 先收集这些信息

排查之前先准备好下面几样东西，大多数问题看完它们就有答案：

1. **启动日志中的摘要行**。每个 Smart 组启动时输出一行，写明成员数、探测设置与实际生效的算法、模型状态：

   ```
   smart[auto] started: 42 outbounds, 10 background tasks, testURL=https://www.gstatic.com/generate_204 interval=3m0s asn=off algorithm=strict-best hysteresis=off ml=off collect=off
   ```

   `smart-loadbalance` 组还会多一行地区划分结果：

   ```
   smart-loadbalance[balance] regions: HK(12) JP(8) OTHER(1); mode=auto strategy=smart affinity=none fallback=auto
   ```

2. `GET /smart/groups` 与 `GET /smart/groups/{name}/diag` 的输出，确认配置是否按预期生效、统计库里实际有多少数据。
3. `GET /proxies/{name}/weights?full=1` 的输出，看每个（目标, 节点）的权重明细。
4. 需要逐条连接的细节时，把日志级别调到 `debug`：

   ```json
   { "log": { "level": "debug" } }
   ```

   每条连接都会输出选路结果，例如：

   ```
   smart[auto] select via weight: target=*.example.com asn=[none] candidates=[HK-01,HK-02,JP-01]
   smart[auto] tcp → www.example.com:443 via [HK-01] in 85ms (target=*.example.com asn=[none] source=weight)
   ```

   `source` 说明候选来自哪一层（`manual`、`unwrap`、`prefetch`、`weight`、`delay`、`fallback`），含义见 [工作原理](../how-it-works/)。Watchdog 的判定也以 Debug 级别输出。

## 配置报错

| 报错或现象 | 原因 | 解决 |
|---|---|---|
| `outbounds[0].tolerance: json: unknown field "tolerance"`（或 `"idle_timeout"`） | 这是 `urltest` 的字段，Smart 从未支持，早期文档曾错误列出 | 删除该字段 |
| `urltest: invalid expected-status: ...` 或 `urltest: invalid expected-status range: ...` | `expected_status` 格式错误 | 写成 `204`、`200-299` 或 `204/300-399`，状态码在 100–599 之间 |
| `missing outbound and provider tags` | `outbounds` 和 `providers` 都为空 | 至少填写一项 |
| `outbound provider <i> not found: <tag>` | `providers` 引用了不存在的订阅 | 检查订阅的 `tag` |
| `dependency[<tag>] not found for outbound[<smart>]` | `outbounds` 引用了不存在的出站 | 检查出站的 `tag` |

两种情况**不会**报错，但配置没有按你的意思生效：

- **`algorithm` 写错**：Smart 回退到 `strict-best`，只记录一条 WARN：

  ```
  smart[auto] algorithm config [fastest_recnet] was not recognised — falling back to strict-best; accepted values: ...
  ```

  以启动摘要行中的 `algorithm=` 为准。

- **`policy_priority` 部分规则没有生效**：无效规则被忽略，并记录 `smart[auto] policy_priority: ignored invalid rule [...]`。常见原因有：系数写成了 1（等于不调整）、大小写不一致（匹配区分大小写）、想用正则却没加 `~` 前缀。用 `GET /smart/groups` 返回的 `policyPriority` 查看每条规则实际被解析成了什么。

`smart-loadbalance` 的配置报错见下文 [Smart 负载均衡](#smart-负载均衡)。

## Smart 似乎没有在学习

**现象**：`weights` 一直为空；或者所有节点的 `targetCount` 都是 1、`sampleCount` 都是 0，排名只按测速延迟排。

依次检查：

- **没有缓存文件**：日志中出现 `smart: no cache file available, using ephemeral store`。没有缓存文件时 Smart 不记录任何统计。命令行版本需要设置 `experimental.cache_file.enabled: true`；SFA / SFW / SFL 图形客户端始终启用缓存文件。
- **版本太旧**：2026-06-08 至 2026-10-07 之间的版本因为缺陷，统计实际上没有生效（见 [变更记录](../changelog/)）。请升级。
- **还没有流量**：组在第一次成功拨号之前不会做健康检查，也不会计算排名；连续 2 分钟没有拨号的组同样会暂停这些后台任务。产生一些真实流量后再看。
- **样本还不够**：同一个（目标, 节点）至少要有 2 次拨号结果才会计算权重。
- **`targetCount` 为 1、`sampleCount` 为 0**：说明接口返回的是按测速延迟生成的临时排名，还没有统计数据，原因同上。

**确认**：`GET /smart/groups/{name}/diag` 的 `live_coverage` 直接从统计库读取，列出每个节点实际有数据的目标数与样本数；这里有数据而 `weights` 为空时，调用 `POST /smart/groups/{name}/recompute` 立即重算。

## 某个节点从不被选中

依次排除下面的原因：

1. **它不在组里**：`include` / `exclude` 只过滤订阅中的节点。`GET /proxies/{name}` 的 `all` 列出全部成员（列出地区出站的 `smart-loadbalance` 组用 `GET /smart/groups/{name}/regions`）。
2. **它被判为不可用**。以下任何一条都会让节点暂时不参与选择：
   - 最近一次测速失败；
   - 最近 3 分钟内被判定过不可用（测速失败、多次被重置等，见 [下一节](#能用的节点被判为不可用)）；
   - 熔断器打开：30 秒内拨号失败 2 次即熔断，先停用约 15 秒，再次失败时停用时间翻倍，最多 8 倍；
   - 普通 Smart 组中，最近一次测速早于 3 × `interval`（`smart-loadbalance` 组不以此判定）。

   用 `GET /proxies/{node}/delay?timeout=5000` 单独测一次这个节点，确认它当前能否连通。
3. **它被屏蔽了**：失败累计 30 次后，节点被屏蔽 93 分钟起（失败越多越久）；通过 Clash API 手动屏蔽的默认 30 分钟。屏蔽到期前不会被选中。
4. **它只对这个目标被软屏蔽**：连接被重置一次、或首字节超时、或传输中卡死，该节点就对这个目标软屏蔽 10 分钟，其他目标不受影响。
5. **它对这个目标的权重低于 0.4**：权重低于 0.4 的节点不会进入候选。不同场景有延迟上限，例如实时类流量（游戏、语音通话等）超过 150 ms 的节点，权重会被压到 0.38。用 `weights?full=1` 查看该目标上的 `weight_tcp`。
6. **它被 `policy_priority` 压到了后面**：系数大于 1 的节点总是排在前面，系数小于 1 的节点很少轮到。
7. **（`smart-loadbalance`）它在别的地区，或被排除了**：看 `GET /smart/groups/{name}/regions` 中它所在的地区、`source`，以及 `excluded`。

想让本组从头学起，用 `DELETE /proxies/{name}/weights` 清空数据（会同时解除屏蔽与手动指定）。

## 能用的节点被判为不可用

- **`interval` 小于 100 秒**：节点的测速记录超过 3 × `interval` 就被视为过期，但健康检查对 5 分钟内测过的节点不会重测。`interval` 小于 100 秒时，3 × `interval` 不到 5 分钟，就会出现“已判为不可用、却不会重测”的空档。把 `interval` 改回默认的 3 分钟或更长。
- **探测地址在部分节点上不稳定**：探测请求经由节点发出，个别节点的出口可能访问不了默认地址。换成各节点都能稳定访问的 204 地址，例如 `https://cp.cloudflare.com/generate_204`。
- **对同一目标反复出现“无效连接”**：同一目标、同一节点上，60 秒内出现 3 次以下情况，节点会被判为不可用 3 分钟：2 秒内关闭且总流量不足 4 KB；超过 0.5 秒没有收到任何回应；持续超过 2 秒但下行不足 1 KB。日志会记录：

  ```
  smart[auto] node [HK-01] marked dead after 3 short-life closes on target [*.example.com] within 1m0s
  ```

  只上传、几乎不下载的应用容易触发这条规则。
- **同一目标 60 秒内被重置 2 次**：节点会被判为不可用并触发熔断，日志为 `... marked dead after 2 upstream resets on target [...] within 1m0s ...`。这通常意味着该线路对这个网站有干扰。
- **网络刚切换**（如 Wi-Fi 与蜂窝之间）：切换瞬间正在进行的拨号会被取消，客户端随即重试。这是正常现象，不代表节点有问题。

## 节点明明不通却显示可用

`expected_status` 留空时，收到任何 HTTP 响应都算探测成功，包括强制门户（酒店、机场 Wi-Fi 的登录页）返回的重定向。设置 `"expected_status": "204"`，配合默认的探测地址，就能区分“真的能上网”和“被登录页拦截”。

## 面板显示的节点和实际不一样

面板上的“当前节点”（`now`）是一个代表：有手动指定时是被指定的节点，否则是最近一次成功拨号的节点。Smart 为每条连接单独选节点，同一时刻不同网站可能走不同的节点。

要看每条连接实际用的节点，查看 `GET /connections` 中的 `chains`，第一个就是最终节点。`smart-loadbalance` 组在列出地区出站时，`now` 显示的是地区出站而不是节点。

## 手动指定后流量仍走其他节点

- **被指定的节点暂时不可用**：它拨号失败时，Smart 临时改用其他节点，面板上 `fixedSuspended` 变为 `true`，`fixedActive` 显示实际使用的节点。被指定的节点下一次拨号或测速成功后，自动切回。
- **它的熔断器打开了**：熔断期间指定会被暂时绕过，熔断结束后恢复。
- **已有连接没有切换**：指定只影响新连接。已有连接要等它自然结束；想立即切换，开启 `interrupt_exist_connections`。
- **（`smart-loadbalance`）选的是地区不是节点**：在面板中点选地区出站是锁定地区，连接仍会分摊到该地区的多个节点上；要固定到一个节点，点选具体节点。

## 取消手动指定后仍偏向原来的节点

这是手动指定学习的效果：被指定过的节点会获得一个随时间衰减的加成，最高约 1.63 倍，最长持续 14 天，详见 [手动指定节点](../priority-and-pinning/#手动指定节点)。想立即消除，用 `DELETE /proxies/{name}/weights` 清空本组数据。

## 连接被断开

- **首字节超时**：连接建立、客户端发出数据后，5 秒内没有收到任何回应（节点测速延迟较低时更短：测速延迟的 4 倍，最少 1.5 秒），连接会被关闭，节点对该目标软屏蔽 10 分钟。
- **传输中卡死**：收到过数据之后，客户端写出数据却 60 秒没有任何回应，连接会被关闭。正常空闲的长连接（WebSocket、推送、keep-alive）没有未回应的写出，不受影响。
- **网络切换**：sing-box 会关闭所有连接，客户端会自动重连。
- **`interrupt_exist_connections`**：开启后，手动指定变化（以及 `smart-loadbalance` 的地区锁定变化）会中断本组已有的连接。
- **2026-10-05 之前的版本**：经过 Smart 的长连接会在第 30 秒被切断。请升级。

## ASN 没有生效

先看启动日志中的 ASN 状态（详见 [ASN 与 GeoX](../asn-geox/#相关日志)）：

- **`asn=on(downloading)`**：数据库还在下载，下载完成后自动生效，无需重启。一直没有生效时，查找 `assetdl[...]: download failed, retrying in ...` 日志，并检查 `experimental.geox` 的 `http_client` 能否访问下载地址。
- **数据库格式不对**：需要 MaxMind GeoLite2-ASN 格式的 mmdb。
- **相对路径找不到文件**：`asn_database` 中的路径按原样使用，不会拼接数据目录，建议写绝对路径。
- **目标 IP 未知**：选路时只有已经知道目标 IP 的连接才能按 ASN 选择（只有域名、由节点端解析的连接没有 IP）；统计时，连接关闭后会补做一次最长 200 ms 的 DNS 查询。
- **被有意忽略的 ASN**：CDN 与骨干网的 ASN 覆盖面太广，按它们分组没有意义，因此被忽略。

## 模型一直是 ml=pending

模型还没下载成功。检查 `download_detour` 或 `http_client` 指定的出站能否访问模型地址（默认在 GitHub 上）。也可以手动下载 `Model-large.bin`，放到 `model_path`（默认是数据目录下的 `smart_lgbm_model.bin`），然后重启。

## 模型显示 ml=unusable

模型文件存在，但不能使用。日志中的这条 WARN 给出了原因：

```
lightgbm: cannot use model <路径>: <原因>; traditional weights until a usable model replaces it
```

常见原因有：文件损坏或不是 LightGBM 文本格式；使用了 Smart 不认识的特征名；`[transforms]` 块与模型的特征名不一致。自己训练的模型请对照 [模型格式](../lightgbm/#模型格式) 检查。使用默认模型时，删除该文件后重启会重新下载；`auto_update` 关闭时，已存在的文件不会被自动替换。模型不可用期间，Smart 使用传统权重公式，选路照常进行。

## 训练数据不再增长

- **达到大小上限**：文件超过 `size_limit_mb`（默认 100 MB）后停止写入，日志为 `smart collector: reached size limit 100 MB; dropping further samples ...`。删除文件或把它截短到上限以下，30 秒内自动恢复。
- **只采集了部分连接**：`sample_rate` 小于 1 时只按比例采集。
- **统计队列繁忙**：短时间内连接很多时，排不上队的样本会被丢弃。

## 手机耗电或发热

- 把 `interval` 设为 5 分钟或更长，减少测速；
- 用 `exclude` 去掉用不到的节点；
- 避免多个 Smart 组引用同一批节点，每个组都会各自测速与学习；
- `smart-loadbalance` 组不需要时可以关闭地区探测（`region.probe.disabled: true`）；
- 内存紧张时调低 `SMART_CACHE_BUDGET_MB`（仅命令行版本）。

## Smart 负载均衡

### 配置报错

| 报错 | 原因与解决 |
|---|---|
| `unknown balance strategy: ...`、`unknown balance affinity: ...`、`unknown region mode: ...`、`unknown region fallback: ...` | 取值写错。与 `algorithm` 不同，`balance` 与 `region` 中的取值写错会直接报错，可用的值见 [配置字段](../config/#smart-loadbalance) |
| `region.mode priority requires region.priority` | 使用 `priority` 模式时必须填写 `region.priority` |
| `region.outbounds.tag must contain {region}, {name}, {name_en} or {flag}` | 地区出站的标签模板里没有地区占位符，生成的出站会重名 |
| `register region outbound <tag>: duplicate outbound tag: <tag>` | 生成的地区出站与已有出站重名。改 `region.outbounds.tag` 模板，或改已有出站的标签 |
| `smart-region[<tag>]: <group> is not a smart-loadbalance group` | 手动声明的 `smart-region` 指向了不存在或不是 `smart-loadbalance` 的组 |
| 引用地区出站时报 `dependency[...] not found` | 只有 `region.outbounds.regions` 中列出的地区出站在启动时创建；`auto` 在运行中创建的出站不能在配置中引用。把要引用的地区加入 `regions` |

### 节点被分到错误的地区

**确认**：`GET /smart/groups/{name}/regions` 列出每个节点的地区和 `source`（`rule`、`name`、`exit`、`unknown`），看它是依据什么被分过去的。

**解决**：名称识别有误时，用 `region.rules` 按正则或节点名纠正；想以真实出口为准，设置 `detect.exit: prefer`，再调用 `POST /smart/groups/{name}/regions/detect?force=true` 重新探测。

### 报错 `no node can serve ...`

完整的报错形如：

```
smart-loadbalance[balance]: no node can serve www.example.com:443 (priority-unavailable (no healthy node))
```

括号里是地区决策的来源，结尾说明了原因：

- **以 `(no healthy node)` 结尾**：其他地区其实有健康节点，但 `region.fallback` 不允许这条连接使用它们。常见情况：`priority` 模式下列出的地区都没有健康节点，而 `fallback` 是 `none` 或 `priority`；开启了 `fallback` 的地区出站或锁定的地区没有健康节点，而组的 `fallback` 是 `none`，或是 `priority` 但列出的地区也都没有健康节点。把 `fallback` 改为 `auto`，或在 `priority` 中加入更多地区。
- **以 `(no node)` 结尾**：允许的范围内没有能用的成员：成员全部被屏蔽；UDP 连接遇到的成员都不支持 UDP；或者限定的地区（未开启 `fallback` 的地区出站、`fallback: none` 下锁定的地区）里根本没有成员。
- **`all retries failed`**：选出了候选，但全部拨号失败。与普通 Smart 组相同，按“节点不可用”的思路排查。

允许的范围内一个可用节点都没有时（例如长时间断网之后），或者选中地区的可用节点对这个目标都被软屏蔽了，组不会直接报错，而是忽略健康状态，按质量从高到低尝试未被屏蔽的成员，作为最后兜底；Debug 日志中的来源以 `(last resort: no healthy node)` 结尾。未开启 `fallback` 的地区出站，以及 `fallback: none` 下锁定的地区，兜底时仍只在本地区内尝试。被 `allow` / `deny` 排除的地区不参与兜底。

另外，`smart-loadbalance` 不会仅因测速记录过期就把节点判为不可用：组空闲时健康检查会暂停，记录过期是正常的。只有熔断打开、3 分钟内被判定不可用、最近一次测速失败或被屏蔽，才算不可用。

### 连接总是落在同一个节点

依次检查：

- `balance.affinity` 是否为 `target`、`site` 或 `source`：这些设置会把同一批连接绑定到一个节点上；
- 节点池是否只剩一个节点：`min_quality` 设得过高、`max_nodes: 1`，或者地区内其他节点不可用；
- 是否在面板中手动指定了某个节点。

把日志级别调到 `debug`，每条连接会显示 `region=... pick=... pool=...`，`pool` 是可分配的节点数，`pick` 是选中方式（`affinity` 表示来自会话亲和）。

### 出口探测一直没有结果

出口探测经由节点访问 `detect.exit_url`，节点不通或该地址被拦截时会失败，30 分钟后重试；Debug 日志会记录 `exit probe [<节点>] failed: ...`。可以换一个能返回国家的地址，例如返回 `country_code` 字段的 JSON 接口。

### 判断不出目标国家（destination 模式）

先确认国家数据库已经下载：GeoX 在后台下载，下载完成前只能依靠域名后缀判断。使用 FakeIP 时，解析得到的是假地址，查不出国家，可以依靠 `destination.map` 与国家顶级域，或改用 `auto` 模式。

## 重置 Smart 的全部数据

| 方法 | 影响范围 |
|---|---|
| `DELETE /proxies/{name}/weights` | 一个组：统计、手动指定、屏蔽、熔断，以及 `smart-loadbalance` 的地区锁定与出口结果 |
| `POST /cache/smart/flush` | 当前配置中的所有 Smart 组 |
| 停止 sing-box 后删除缓存文件 | 所有数据，**包括**规则集、FakeIP、选择器状态等其他缓存 |
