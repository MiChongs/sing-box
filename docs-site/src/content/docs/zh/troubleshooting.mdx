这一页按“症状”组织。先找到与你遇到的现象最接近的小节，每节依次说明可能的原因、怎么确认、怎么解决。术语见 [术语表](../glossary/)，接口的完整说明见 [Clash API](../clash-api/)。

## 先收集这些信息

1. **`GET /smart/groups`**：确认组的类型、成员数、`preferASN`、`useLightGBM` 等是否按预期生效。
2. **`GET /smart/groups/{name}/diag`**：选择理由、服务池、封锁记录、失败风暴、ASN 认领数，大多数问题看它就有答案。
3. **`GET /group/{name}/weights`**：每个成员的可靠性、失败计数、是否在服务池。
4. 需要逐条连接的细节时，把日志级别调到 `debug`。Smart 会输出拨号失败、收敛、网站拒绝与封锁等事件，前缀为 `outbound/smart[<组>]`，例如：

   ```text
   DEBUG outbound/smart[auto]: dial HK-02 for api.example.com failed: i/o timeout
   DEBUG outbound/smart[auto]: node HK-05 lowWeight for [*.example.com]
   ```

5. 每条连接最终用了哪个节点：`GET /connections` 的 `chains`。

## 升级后启动失败

报错 `json: unknown field "algorithm"`（或 `hysteresis`、`use_asn`、`asn_database`、`max_host_failed_times`）：这些字段在 Smart 重写后已删除。删除它们即可；`use_asn` 换成 `prefer_asn`，自定义 ASN 数据库改用 `experimental.geox.url.asn`。对照见 [已删除的字段](../config/#已删除的字段)。

`policy_priority` 报格式错误：新写法是 `模式:系数`，旧写法的 `=`、`~`、`!` 前缀不再有特殊含义；系数必须是正数。

## 重启后学习数据丢失

- 命令行版本没有开启 `experimental.cache_file`：Smart 只在内存中学习。
- 数据每 5 分钟写一次，进程被强制结束时会丢失最近几分钟的数据。
- 组改了名：数据按组名保存，新名字从零开始。
- 从旧版本升级：旧的 `smart_stats` 数据不迁移，会被自动删除。

## 某个节点从不被选中

先在 `weights` 和 `diag` 里找到这个节点，按下面的顺序看：

| 现象 | 原因 |
|---|---|
| `Alive: false`，`diag` 中 `alive: false` | 连续两次健康检查失败。检查 `url` 与 `expected_status` 是否适合这个节点 |
| `diag` 中 `blocked: "unstable"` | 稳定性检查发现延迟抖动或变慢，整组封锁 12 分钟 |
| `diag` 中 `blocked: "manual"` | 被 `POST /smart/groups/{name}/block/{node}` 封锁；`DELETE` 同一路径即可解除 |
| `FailStreak` ≥ 3 | 节点级连续失败，在退避期内（`BackedOff`）不会被试用，见 [失败状态](../scoring/#失败状态) |
| `hosts` 中对某网站有封锁 | 只是对这个网站不可用，见 [封锁代码](../blocks-and-probes/#封锁代码) |
| `Pool: false` 且 `Completed` 很少 | 不在服务池里。节点多时池只有少数成员，池外成员每 10 分钟轮换一个进来比较；这是正常的 |
| `Observed` 明显低于其他成员 | 可靠性落后超过 0.05，没有资格 |

`policy_priority` 系数较低的节点在可靠性接近时会输给系数高的节点；系数不会让它彻底出局，但会让它很少胜出。

## 一直用同一个节点，不换到更快的

这通常是设计行为：每个服务有一个在任节点，挑战者必须在**双方都成熟**的数据上证明更好才能取代它。`diag` 中 `incumbentHeld`、`insufficientEvidenceHeld` 占多数时就是这种情况。

- 挑战者需要在同一个服务上积累数据，这依赖探索预算与轮换，可能需要几分钟到几十分钟；
- 延迟只占综合分很小的比重，成功率更高的节点即使慢一些也会胜出；
- 想立即换，用手动指定，或清空这个组的数据。

## 节点来回切换

`diag` 中 `switchFlap` 持续增长，说明几个节点的表现非常接近。可以用 `policy_priority` 给其中一个稍高的系数（如 1.05）打破平局，或者把相近的节点放进 `urltest` 组再交给 Smart。

## 能用的节点被封锁

- **`lowWeight`**：连接质量 × 系数低于 0.4。系数小于 1 的节点更容易触发；`use_lightgbm` 时，模型的预测也可能偏低。
- **`error`**：同一网站连续 `max_failed_times` 次错误。网站本身不稳定时，可以调大这个值。
- **`answer`**：网站拒绝了这个节点（403、质询、地区不可用等），这通常是真的被拒绝，见下一节。
- **`manual`**：通过 `DELETE /connections/smart/{id}` 封锁，永久有效，只能清空数据解除。
- 很多节点同时被封锁：超过 1/3 的成员被封锁时会判为网站本身故障并忽略封锁（`hostBlocked: true`）；失败风暴期间不会产生封锁。

## 某个网站总是“该地区不可用”或弹验证

响应探测会识别这种情况，把被拒绝的节点对该网站封锁 `answer`；同一地区多个出口都被拒绝时，整个地区对这个网站被推迟（出口嫌疑）。确认方法：

- `debug` 日志中的 `node <节点> refused for <网站>: <原因>`；
- `diag` 中 `hosts` 对这个网站的 `answer` 记录，以及 `members[].exitRegion`。

如果所有节点都被拒绝，Smart 会把它判为网站本身的问题，暂停封锁 30 分钟。这时只能换用别的线路或订阅。给这个网站写一条单独的规则，可以让它的所有域名一起收敛到能用的节点上。

## 手动指定被取消，或指定后不通

- **组测速会解除手动指定**（与 mihomo 一致）。面板上对 Smart 组点“测速”就会触发；只对组本身测速（`GET /proxies/{name}/delay`）不会。
- 节点离开了组（订阅更新后改名或被删除），指定自动解除。
- 手动指定的节点连不上时，连接直接失败，不会换用其他节点。
- UDP 连接在指定的节点不支持 UDP 时照常自动选择。

## 连接被断开

Smart 会在这些时候主动关闭连接：

- **收敛**：主选失败、由备用节点接通后，同一服务经其他节点的 TCP 连接被关闭（日志 `converged N connections of [...]`）；
- **封锁生效**：节点对某个服务被封锁时，这个服务的 TCP 连接被关闭；
- **手动指定变化**且开启了 `interrupt_exist_connections`；
- 网站第一次被识别为网站键时（`prefer_asn`）。

这些关闭都不计成功或失败，客户端通常会立即重连。如果某个服务的连接频繁被断开，查看 `diag` 中这个服务的封锁记录。

## prefer_asn 没有效果

- ASN 数据库还在下载：`debug` 日志中有 `ASN database ... is downloading`，下载完成后自动生效。
- 路由时没有目标 IP：使用 FakeIP、或域名没有被解析时查不到 ASN，Smart 按网站区分。可以在规则中加入 `resolve` 动作。
- 目标在共用网络上（Cloudflare、Akamai、AWS 等）：按设计按网站区分。
- 规则不是大合集：具体的规则（如 `geosite-netflix`、`domain_suffix`）始终按规则归并，见 [prefer_asn](../service-keys/#prefer_asn)。
- `diag` 中 `asnClaims` 为 0：还没有足够的服务规则证据，ASN 认领每 2 分钟计算一次。

## LightGBM 模型没有生效

- 日志中没有 `lightgbm model loaded from …`：模型还在下载，或下载失败（检查 `download_detour` / `http_client`）。
- WARN `lightgbm: cannot use model …`：文件不是 LightGBM 文本格式或已损坏，删除后重新下载。
- 模型加载了但 CSV 中仍是 `Traditional`：模型带的 `[transforms]` 段中 `[order]` 与 Smart 的特征顺序不一致，或这个节点在该服务上还不到 2 次完成。
- 自己的模型被覆盖：`auto_update` 为 `true` 时会用 `url` 的模型覆盖本地文件。

## 训练数据不再增长

- 文件达到 `size_limit_mb`（默认 100 MB），写入停止；删除文件后 5 秒内自动新建。
- 只有开启 `collect_data` 的组写入；`sample_rate` 小于 1 时只记录一部分连接；拨号失败与“不计”的连接不记录。
- 写入每 100 行刷新一次，最近的样本可能还在缓冲区里。

## 日志出现失败风暴警告

`failures are flooding in, learning paused until a connection succeeds` 表示短时间内连续 50 次失败，通常是网络断了。期间失败不计入任何节点，网络恢复、出现一次成功连接后自动恢复。如果网络正常却频繁出现，检查是否所有节点都已失效（订阅过期）。

## 手机耗电或发热

- 保持默认的 `interval: 5m` 与 `idle_timeout: 30m`，不用时健康检查会暂停；
- 不需要时关闭 `use_lightgbm`、`collect_data` 与 `prefer_asn`；
- 不要配置多个引用同一大订阅的 Smart 组：每个组分别检查、分别学习。

## Smart 负载均衡

### 配置报错

| 报错 | 原因与解决 |
|---|---|
| `unknown balance strategy: ...`、`unknown balance affinity: ...`、`unknown region mode: ...`、`unknown region fallback: ...` | 取值写错，可用的值见 [配置字段](../config/#smart-loadbalance) |
| `region.mode priority requires region.priority` | 使用 `priority` 模式时必须填写 `region.priority` |
| `region.outbounds.tag must contain {region}, {name}, {name_en} or {flag}` | 地区出站的标签模板里没有地区占位符，生成的出站会重名 |
| `register region outbound <tag>: ...` | 生成的地区出站与已有出站重名。改 `region.outbounds.tag` 模板，或改已有出站的标签 |
| `smart-region[<tag>]: <group> is not a smart-loadbalance group` | 手动声明的 `smart-region` 指向了不是 `smart-loadbalance` 的组 |
| 引用地区出站时报 `dependency[...] not found` | 只有 `region.outbounds.regions` 中列出的地区出站在启动时创建；`auto` 在运行中创建的出站不能在配置中引用 |

### 节点被分到错误的地区

**确认**：`GET /smart/groups/{name}/regions` 列出每个节点的地区和 `source`（`rule`、`name`、`exit`、`unknown`）。

**解决**：名称识别有误时，用 `region.rules` 按正则或节点名纠正；想以真实出口为准，设置 `detect.exit: prefer`，再调用 `POST /smart/groups/{name}/regions/detect?force=true` 重新探测。

### 报错 `no available member for ...`

`smart-loadbalance` 选不出任何候选：

- 其他地区有健康节点，但 `region.fallback` 不允许使用它们（`none`，或 `priority` 而列出的地区都没有健康节点）。把 `fallback` 改为 `auto`，或在 `priority` 中加入更多地区。
- 限定的地区（未开启 `fallback` 的地区出站、`fallback: none` 下锁定的地区）里根本没有成员。

允许的范围内一个健康节点都没有时（例如长时间断网之后），组不会直接报错，而是忽略健康状态按质量顺序尝试成员。只有全局失败计数达到 3 且在退避期、健康检查连续失败、最近一次测速失败，或被整组封锁的节点，才算不健康。

### 连接总是落在同一个节点

- `balance.affinity` 是否为 `target`、`site` 或 `source`：这些设置会把同一批连接绑定到一个节点上；
- 节点池是否只剩一个节点：`min_quality` 设得过高、`max_nodes: 1`，或者地区内其他节点不可用；
- 是否在面板中手动指定了某个节点。

### 出口探测一直没有结果

出口探测经由节点访问 `detect.exit_url`，节点不通或该地址被拦截时会失败，30 分钟后重试；`debug` 日志会记录 `exit probe [<节点>] failed: ...`。可以换一个能返回国家的地址，例如返回 `country_code` 字段的 JSON 接口。

### 判断不出目标国家（destination 模式）

先确认国家数据库已经下载：GeoX 在后台下载，下载完成前只能依靠域名后缀判断。使用 FakeIP 时，解析得到的是假地址，查不出国家，可以依靠 `destination.map` 与国家顶级域，或改用 `auto` 模式。

## 重置 Smart 的全部数据

| 方法 | 影响范围 |
|---|---|
| `DELETE /proxies/{name}/weights` | 一个组的全部学习数据、封锁、手动指定，以及 `smart-loadbalance` 的地区锁定与出口结果 |
| `POST /cache/smart/flush` | 当前配置中的所有 Smart 组 |
| 停止 sing-box 后删除缓存文件 | 所有数据，**包括**规则集、FakeIP、选择器状态等其他缓存，以及已从配置中删除的组留下的数据 |
