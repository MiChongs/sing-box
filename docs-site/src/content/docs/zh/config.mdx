这一页是 Smart 全部配置项的参考。想调整默认行为、查某个字段的默认值，或弄清启动报错的原因时来这里查。第一次使用请先看 [快速开始](../quick-start/)，不熟悉的词可以查 [术语表](../glossary/)。

## 如何阅读这一页

Smart 的配置分布在四处：

- **出站组本身**：写在 `outbounds` 里，类型为 `smart`（为每条连接选最可靠的节点），或 `smart-loadbalance`（按地区分池、把连接分摊到多个节点）。
- **`experimental.smart`**：所有组共用的 LightGBM 模型与训练数据采集，一般不用写。
- **`experimental.geox`**：ASN 与国家数据库的下载设置，一般不用写。
- **`experimental.cache_file`**：学习数据保存在这里，建议开启；不开启时 Smart 照样学习，但重启后从零开始。

每个字段都标出了类型和默认值，没有标默认值的字段默认为空。几种类型的写法：

| 类型 | 写法 |
|---|---|
| `duration` | 时长字符串，如 `30s`、`5m`、`72h` |
| `regex` | Go RE2 正则字符串，如 `(?i)香港\|HK`；写错时读取配置就会报错 |
| `string \| string[]` | 可以写一个字符串，也可以写字符串数组 |
| `object` | JSON 对象，如 `{"HK": 1.2}` |

配置中出现不认识的字段会直接报错，例如 `outbounds[0].algorithm: json: unknown field "algorithm"`。旧版 Smart 的字段已全部删除，对照见 [已删除的字段](#已删除的字段)。

## 从最小到常用

### 最小配置

只需要告诉 Smart 用哪些节点：

```json
{
  "outbounds": [
    { "type": "smart", "tag": "auto", "providers": ["my-subscription"] }
  ],
  "experimental": {
    "cache_file": { "enabled": true }
  }
}
```

其余字段全部使用默认值：组在使用中时每 5 分钟检查一次成员，并为每个服务选出最可靠的节点。

### 常用配置

在最小配置的基础上，多数人会加上这几项：

```json
{
  "type": "smart",
  "tag": "auto",
  "providers": ["my-subscription"],
  "exclude": "(?i)剩余|到期|官网",
  "expected_status": "204",
  "policy_priority": "香港|HK:1.2;日本|JP:1.1",
  "prefer_asn": true
}
```

- `exclude` 去掉订阅里“剩余流量”“到期时间”之类的提示条目，它们不是真正的节点。
- `expected_status: "204"` 要求检查地址必须返回 204，避免酒店、机场 Wi-Fi 的登录页把不通的节点误判为可用。
- `policy_priority` 让名称含“香港”“日本”的节点更优先，见 [节点偏好](../scoring/#节点偏好)。
- `prefer_asn` 让通过 `route.final` 或大合集规则进来的网站按网络归并学习，见 [服务键](../service-keys/#prefer_asn)。

完整的可用示例见 [示例配置](../examples/)。

## smart-loadbalance

`smart-loadbalance` 组适合想把连接分摊到多个节点、同时保持出口地区稳定的场景，例如大订阅按地区自动分组、多线程下载、嵌套代理的前置。工作方式见 [Smart 负载均衡](../smart-loadbalance/)。

它接受上面 `smart` 组的全部字段，含义不变，另外加上 `balance` 与 `region` 两块；这两块中的取值写错会直接报配置错误。

最简单的写法与 `smart` 组一样：

```json
{ "type": "smart-loadbalance", "tag": "balance", "providers": ["my-subscription"] }
```

需要调整时，可用的字段及默认值如下：

```json
{
  "type": "smart-loadbalance",
  "tag": "balance",
  "providers": ["my-subscription"],

  "balance": {
    "strategy": "smart",
    "affinity": "none",
    "affinity_ttl": "10m",
    "max_nodes": 0,
    "min_quality": 0.5,
    "max_connections_per_node": 0
  },
  "region": {
    "mode": "auto",
    "priority": [],
    "allow": [],
    "deny": [],
    "weights": {},
    "fallback": "auto",
    "min_nodes": 1,
    "sticky": "30m",
    "switch_margin": 0.25,
    "unknown": "keep",
    "rules": [],
    "destination": { "map": {}, "disable_tld": false, "disable_resolve": false },
    "detect": {
      "disable_name": false,
      "exit": "fallback",
      "exit_url": "https://www.cloudflare.com/cdn-cgi/trace",
      "exit_ttl": "24h",
      "exit_timeout": "8s",
      "exit_concurrency": 4
    },
    "probe": { "disabled": false, "interval": "10m", "targets": 6, "regions": 5 },
    "outbounds": {
      "enabled": false,
      "regions": [],
      "auto": false,
      "tag": "{group}-{region}",
      "fallback": false,
      "members": "regions",
      "hidden": false,
      "icon": ""
    }
  }
}
```

凡是要写地区的地方，都可以写地区代码（`HK`、`GB`，`UK` 等同于 `GB`）、中文或英文名称（`香港`、`Japan`）或旗帜（`🇯🇵`），不区分大小写；不认识的值会转成大写，作为自定义地区（如 `IPLC`）。

## smart-region

`smart-region` 是 `smart-loadbalance` 组中某个地区的出站，经它的连接只会从该地区的节点出去，学习、失败状态与分摊仍由所属组统一处理。通常由 `region.outbounds` 自动生成；需要单独设置 `fallback`、`hidden` 时，也可以手动声明：

```json
{ "type": "smart-region", "tag": "日本前置", "group": "balance", "region": "JP", "fallback": false }
```

## experimental.geox

全局的地理数据下载设置。Smart 用到其中两种数据库：

- **ASN 数据库**：开启 `prefer_asn`、`use_lightgbm` 或 `collect_data` 的组使用，用来查目标与节点出口所属的网络；
- **国家数据库**：开启 `use_lightgbm` 或 `collect_data` 的组，以及 `smart-loadbalance` 组使用。

不写 `geox` 也可以：需要的组会让 GeoX 在后台下载默认的 GeoLite2-ASN 与 GeoLite2-Country，文件保存在数据目录下。

<FieldList lang="zh" fields={geoxFields} prefix="geox-" />

<Callout type="note" title="首次下载与生效时机">
  GeoX 在后台下载，不会拖慢启动。数据库下载或更新完成后立即生效，所有组随即使用新数据，**无需重启**。下载完成前，相当于查不到 ASN 或国家。
</Callout>

## 已删除的字段

Smart 重写后，以下旧字段已删除，写在配置中会报错 `json: unknown field "<字段>"`：

| 旧字段 | 现在 |
|---|---|
| `algorithm` | 删除。选择统一由综合评分决定，见 [综合评分与选择](../scoring/)；`smart-loadbalance` 用 `balance.strategy` |
| `hysteresis` | 删除。服务的在任节点只在挑战者证明更好时才更换，不需要防抖窗口 |
| `use_asn` | 改为 `prefer_asn`，含义也不同：按 ASN 归并大合集规则，而不是额外记录 ASN 维度的权重 |
| `asn_database` | 删除。ASN 数据库统一由 `experimental.geox.url.asn` 提供 |
| `max_host_failed_times` | 删除。网站本身故障的判断改为“超过 1/3 的成员被封锁” |
| 旧的 `SMART_*` 环境变量 | 不再读取 |

新增的字段：`idle_timeout`、`timeout`、`tolerance`、`max_failed_times`、`prefer_asn`。`interval` 的默认值由 3 分钟改为 5 分钟。`policy_priority` 改用 mihomo 的写法（第一条命中的规则生效，正则或子串），旧写法中的 `=`、`~`、`!` 前缀不再有特殊含义。
