import Callout from '../../../components/Callout.astro';

Smart groups (and `smart-loadbalance` groups) expose state and controls through sing-box's built-in Clash API. Paths and response shapes follow the Smart group of [vernesong/mihomo](https://github.com/vernesong/mihomo) as closely as possible, so dashboards such as metacubexd and zashboard work out of the box. Scripts can call the same endpoints to read the ranking, block nodes or flush data.

This page first explains how to call it, then groups endpoints by purpose: [Inspecting state](#inspecting-state), [Manual control](#manual-control), [Flushing data](#flushing-data) and [Smart load balancing](#smart-load-balancing). Terms are in the [Glossary](../glossary/).

## Before you start

### Enable the Clash API

Set a listen address in the config. With a `secret`, every request must carry it:

```json
{
  "experimental": {
    "clash_api": {
      "external_controller": "127.0.0.1:9090",
      "secret": "change-me"
    }
  }
}
```

### Calling it

The examples assume `127.0.0.1:9090`. With a `secret`, add the header `Authorization: Bearer <secret>`:

```bash
curl -H 'Authorization: Bearer change-me' http://127.0.0.1:9090/smart/groups
```

A missing or wrong secret returns 401. Errors are usually `{"message": "..."}`; endpoints with a different error shape say so below.

### Group names in URLs

Percent-encode group names with non-ASCII characters, emoji or spaces as UTF-8; `Hong Kong auto` becomes `Hong%20Kong%20auto`. With curl you encode it yourself; dashboards do it for you.

<Callout type="warn" title="Group names containing /">
  `/smart/*` and `/cache/smart/flush/{name}` do not decode `%2F` in the path, so they cannot find a group whose name contains `/`: `/smart/*` returns 404, and `/cache/smart/flush/{name}` **flushes every Smart group**. The `/proxies/{name}` and `/group/{name}` endpoints are not affected.
</Callout>

### Endpoints at a glance

| Purpose | Endpoint |
|---|---|
| A group's current state (what dashboards read) | `GET /proxies/{name}`, `GET /group/{name}` |
| Node ranking | `GET /group/{name}/weights`, `GET /proxies/{name}/weights`, `GET /group/weights`, `GET /smart/weights` |
| List every Smart group | `GET /smart/groups` |
| Internal diagnostics | `GET /smart/groups/{name}/diag` |
| Delay tests | `GET /proxies/{name}/delay`, `GET /group/{name}/delay` |
| The node each connection really uses | `GET /connections` |
| Pin and unpin | `PUT /proxies/{name}`, `DELETE /proxies/{name}`, `POST /smart/groups/{name}/clear-selection` |
| Block nodes | `POST`, `DELETE /smart/groups/{name}/block/{node}`, `DELETE /connections/smart/{id}` |
| Recompute the ranking now | `POST /smart/groups/{name}/recompute` |
| Flush learned data | `DELETE /proxies/{name}/weights`, `POST`/`DELETE /cache/smart/flush`, `POST`/`DELETE /cache/smart/flush/{name}` |
| Regions and balancing of smart-loadbalance | `/smart/groups/{name}/regions`, `/smart/groups/{name}/balance` |

The old `PUT /smart/groups/{name}/algorithm` has been removed and now returns 404 or 405.

## Inspecting state

### `GET /proxies/{name}`

A group's current state. Smart groups have `type: "Smart"` and, besides the standard Clash fields, carry the same fields as mihomo Smart:

```json
{
  "type": "Smart",
  "name": "auto",
  "udp": true,
  "now": "HK-01",
  "all": ["HK-01", "HK-02", "JP-01"],
  "history": [{ "time": "2026-10-29T08:00:00Z", "delay": 123 }],
  "alive": true,
  "delay": 123,
  "hidden": false,
  "icon": "",
  "testUrl": "https://www.gstatic.com/generate_204",
  "expectedStatus": "*",
  "fixed": "",
  "fixedSuspended": false,
  "fixedActive": "",
  "policy-priority": "Hong Kong|HK:1.20;Japan|JP:1.10",
  "useLightGBM": true,
  "collectData": false,
  "sampleRate": 1,
  "preferASN": false,
  "tolerance": 0,
  "lgbmModelAge": "2h3m0s"
}
```

| Field | Meaning |
|---|---|
| `udp` | Whether the group carries UDP, i.e. `disable_udp` is not set |
| `now` | The dashboard's "current node": the pinned node, else the member that carried the latest connection, else the member a new connection would most likely get. Smart chooses per connection, so this is only a representative |
| `history`, `delay`, `alive` | The probe record of the `now` node. `alive` only means the latest probe is less than 10 minutes old |
| `fixed`, `fixedActive` | The pinned node (for `smart-loadbalance` without a pin, the locked region), or an empty string |
| `fixedSuspended` | Always `false`: a pinned node is never temporarily replaced |
| `policy-priority` | The parsed `policy_priority` rules, factors with two decimals; empty without a config |
| `useLightGBM`, `collectData`, `sampleRate`, `preferASN`, `tolerance`, `expectedStatus` | The configured values |
| `lgbmModelAge` | Time since the LightGBM model was loaded; present only while it is loaded |
| `loadBalance` | Only on `smart-loadbalance` groups; see [Smart load balancing](#smart-load-balancing) |

`GET /group/{name}` returns the same shape (404 when the object is not a group); `GET /group` returns all groups: `{"proxies": [...]}`.

### `GET /group/{name}/weights`

The group's node ranking, as in mihomo's endpoint of the same name; `GET /proxies/{name}/weights` is the same endpoint. Parameters:

- `refresh=true`: recompute now instead of returning the cached ranking (up to 30 s old);
- `full=1` (or `full=true`): add a `diagnostic` object, the same as [`GET /smart/groups/{name}/diag`](#get-smartgroupsnamediag).

```json
{
  "weights": [
    {
      "Name": "HK-01", "Rank": "MostUsed", "Weight": 100,
      "Alive": true, "Pool": true,
      "Utility": 1.0123, "Reliability": 0.9412, "Observed": 0.9831, "Quality": 0.8734,
      "Completed": 37.42, "Qualified": true, "FailStreak": 0, "BackedOff": false,
      "ProbeMs": 182, "ResponseMs": 240.5, "SetupMs": 95.2,
      "UploadBps": 81234, "DownloadBps": 2345678, "Loss": 0.0021,
      "Success": 412, "Failure": 7, "Targets": 23
    }
  ]
}
```

| Field | Meaning |
|---|---|
| `Name`, `Rank`, `Weight` | mihomo's three fields: the node; `MostUsed` / `OccasionalUsed` / `RarelyUsed`; a relative score 0–100. See [The dashboard ranking](../scoring/#the-dashboard-ranking) |
| `Alive` | Health checks pass and no group-wide block |
| `Pool` | In the TCP serving pool |
| `Utility` | The node's overall comprehensive score (not per service, `policy_priority` factor included) |
| `Reliability`, `Observed` | Reliability lower bound and observed success rate (decayed) |
| `Quality` | Overall connection quality (without the factor), 0 when none |
| `Completed`, `Qualified` | Decayed completion count; whether the node is proven |
| `FailStreak`, `BackedOff` | Consecutive hard failures; whether a backoff is running |
| `ProbeMs`, `ResponseMs`, `SetupMs` | Probe delay, first-response time and connect time (present only with fresh data from the last 2 minutes) |
| `UploadBps`, `DownloadBps` | Recent upload and download goodput in bytes per second, omitted when unknown |
| `Loss` | Average TCP retransmission rate over the last 30 minutes, omitted when unknown |
| `Success`, `Failure` | Lifetime successes and failures |
| `Targets` | Number of services the node has records for |

Rows are sorted by `Alive`, `Weight`, then `Name`. Without any data the list is empty, with `"message": "No weight data available for the specified group"`. A non-Smart object returns 400 `{"weights": [], "error": "not a Smart group"}`. Called on a `smart-region` outbound, it returns the part of its group's ranking that belongs to the region, plus `group` and `region`.

### `GET /group/weights`

The ranking of every Smart group in one call (up to 5 groups computed in parallel), as in mihomo; `GET /smart/weights` is the same endpoint. Accepts `refresh=true`.

```json
{
  "weights": { "auto": [ { "Name": "HK-01", "Rank": "MostUsed", "Weight": 100 } ] },
  "errors": {}
}
```

A group that fails is listed under its name in `errors`. Without Smart groups: `{"weights": {}, "message": "No Smart groups or no weight data available"}`.

### `GET /smart/groups`

Every Smart group with its main settings, to confirm the config took effect:

```json
{
  "groups": [
    {
      "name": "auto", "type": "smart",
      "testUrl": "https://www.gstatic.com/generate_204", "expectedStatus": "*",
      "preferASN": false, "useLightGBM": true, "collectData": false, "sampleRate": 1, "tolerance": 0,
      "fixed": "", "now": "HK-01", "members": 42,
      "policyPriority": [ { "pattern": "Hong Kong|HK", "factor": 1.2 } ],
      "lgbmModelAge": "2h3m0s"
    }
  ]
}
```

- `type` is `smart` or `smart-loadbalance`; the latter also carries the same `loadBalance` block as `/proxies`.
- `members` is the number of member nodes. `fixed` is the pinned node, or the locked region of `smart-loadbalance`.
- `policyPriority`, `lgbmModelAge` and `loadBalance` are omitted when empty.

### `GET /smart/groups/{name}/diag`

A group's internal state: why it chose what it chose, which nodes are blocked, who is in the serving pool. Read-only and cheap to poll:

```json
{
  "name": "auto", "type": "smart", "now": "HK-01", "fixed": "",
  "testUrl": "https://www.gstatic.com/generate_204",
  "members": [
    { "name": "HK-01", "alive": true, "delay": 182, "stabilityGrade": 1, "load": 3, "priority": 1.2,
      "exitRegion": "HK", "exitAsn": "9304" },
    { "name": "US-03", "alive": true, "delay": 420, "stabilityGrade": 2, "load": 0, "priority": 1,
      "blocked": "unstable", "blockedUntil": 1761730000 }
  ],
  "selection": [
    { "network": "tcp",
      "reasons": { "incumbentHeld": 812, "performanceWinner": 37, "coldExplore": 6, "periodicExplore": 21 },
      "ordinarySwitch": 15, "switchFlap": 2, "pool": ["HK-01", "JP-01", "SG-02", "HK-04"],
      "budgets": [ { "family": "ipv4", "coldAllowance": 8, "coldAvailable": 2, "earnedAvailable": 3,
                     "earningPeriod": 16, "paused": false, "inFlight": 0, "trialYield": 0.83,
                     "businessStarts": 1203, "trialStarts": 33, "coldTrialStarts": 6, "periodicTrialStarts": 21,
                     "recoveryStarts": 6, "budgetBlocked": 140, "inFlightBlocked": 4, "refunded": 1,
                     "trialSuccess": 25, "trialFailure": 5 } ] },
    { "network": "udp", "reasons": {}, "ordinarySwitch": 0, "switchFlap": 0, "pool": null, "budgets": null }
  ],
  "filtered": 96,
  "cache": { "aggregate": 168, "aggregateEvicted": 0, "site": 1320, "siteEvicted": 0, "exact": 4210, "exactEvicted": 0 },
  "hosts": [ { "key": "*.example.com", "nodes": { "HK-02": "answer" } } ],
  "hostFailLimit": 14,
  "floodSuppressed": false,
  "asnClaims": 0,
  "connections": 57,
  "preferAsn": false, "useLightGBM": true, "lightgbmLoaded": true, "collectData": false,
  "ranking": [ { "Name": "HK-01", "Rank": "MostUsed", "Weight": 100 } ]
}
```

| Field | Meaning |
|---|---|
| `members[]` | Per member: `alive` health checks pass, `delay` the latest check's delay, `stabilityGrade` the stability grade (1–4), `blocked` / `blockedUntil` reason and deadline (Unix seconds) of a group-wide block, `load` live connections through this group, `priority` factor, `exitRegion` / `exitAsn` the real exit |
| `selection[]` | One entry each for TCP and UDP: `reasons` counts selection reasons (see [Selection reasons](../scoring/#selection-reasons)), `ordinarySwitch` incumbent replacements, `switchFlap` switches back, `pool` serving-pool members, `budgets` the exploration budget per address family |
| `filtered` | Candidates removed by filtering, in total |
| `cache` | Current size and total evictions of the three evidence tables (shared by all groups) |
| `hosts[]` | Sites or service keys with block records: `nodes` maps node → block code, `hostBlocked` means the site itself is judged broken, `udp` marks UDP records |
| `hostFailLimit` | The broken-site threshold (more blocked nodes than this) |
| `floodSuppressed` | Whether a failure flood is in progress |
| `asnClaims` | Current number of ASN claims |
| `connections` | Live connections of the group |
| `lightgbmLoaded`, `collectedSamples` | Whether the model is loaded; training samples written this run (present while collecting) |
| `ranking` | The same ranking as the weights endpoint |

An unknown group returns 404 `group not found: <name>`, a non-Smart one 404 `not a Smart group: <name>`.

### `GET /proxies/{name}/delay`

Tests the group as one proxy, through the node it would currently choose. Parameters: `timeout` (required, milliseconds) and `url` (optional; `http://` URLs are ignored). Success returns `{"delay": 120}`; a timeout returns 504 and other failures 503. It does **not** release the pin.

### `GET /group/{name}/delay`

Tests every member of the group (up to 4 at a time) with the same parameters and returns `{"HK-01": 120, "JP-01": 85}`, successful members only. The results also count toward each member's health and the probe delay in the score.

<Callout type="warn" title="A group delay test releases the pin">
  As in mihomo, calling this on a Smart group first releases the pinned node. The "test" button of dashboards usually calls this endpoint.
</Callout>

### `GET /connections`

The node each connection really uses. For connections through Smart, `chains` is completed down to the node that actually connected, in mihomo's order with the final node first:

```json
{ "chains": ["HK-01", "auto", "proxy"] }
```

## Manual control

### `PUT /proxies/{name}`

Pins a node: new connections use only this node. Clicking a node in a dashboard calls this. `PATCH` is equivalent.

```bash
curl -X PUT http://127.0.0.1:9090/proxies/auto -d '{"name":"HK-01"}'
```

- Returns 204 on success; an invalid JSON body returns 400; a node that is not a member returns 400 `Smart update error: not found`.
- `{"name": ""}` releases the pin.
- The pin is saved in the cache file and restored after a restart. With `interrupt_exist_connections`, existing connections are closed.
- While pinned there is no filtering, scoring, fallback or blocking from connection outcomes; see [Manual pin](../how-it-works/#manual-pin).

### `DELETE /proxies/{name}`

Releases the pin and returns to automatic selection. Dashboard buttons such as "unpin" call this.

```json
{ "group": "auto", "previous_pin": "HK-01", "now": "JP-01", "interrupted": false }
```

- `previous_pin` is the node that was pinned, omitted when none was; `now` is the current node afterwards.
- `interrupted` reports whether `interrupt_exist_connections` is on (if `true`, the group's existing connections were closed).
- `urltest` and `smart-region` support this too, returning `{"group", "previous_pin", "now"}`; other group types return 400.

### `POST /smart/groups/{name}/clear-selection`

Same effect and response as `DELETE /proxies/{name}`.

### `POST /smart/groups/{name}/block/{node}`

Takes a node out of the whole group for a while, for example when you know its line is bad tonight. Parameter `duration` (Go duration such as `15m`, `2h`), 30 minutes by default; an invalid value falls back to the default.

```bash
curl -X POST 'http://127.0.0.1:9090/smart/groups/auto/block/HK-01?duration=2h'
```

```json
{ "group": "auto", "node": "HK-01", "blocked_until": "2026-10-29T18:30:00+08:00" }
```

- While blocked, the node is excluded at the first filtering level (it may still serve as a last resort when nothing else is available) and shows `Alive: false` in the ranking; the block is saved in the cache file.
- A pinned node is not affected.
- A node that is not a member returns 404 `node not a member of this group: <node>`.

### `DELETE /smart/groups/{name}/block/{node}`

Lifts a group-wide block early (including an `unstable` block from the stability check); returns 204.

### `DELETE /connections/smart/{id}`

Closes a connection and blocks the Smart member it **actually used** for the connection's site (code `manual`), as in mihomo. Handy when the connection list shows a site crawling through one node. `id` is the connection ID from `GET /connections`.

```json
{ "group": "auto", "node": "HK-01" }
```

- The block is recorded on the connection's wildcard host (such as `*.example.com`) and on its service key (the matched rule such as `RuleSet [geosite-netflix]`; with `prefer_asn` possibly the ASN or the service that claimed it), so the service's other domains avoid the node too. It is **permanent** and only [flushing](#flushing-data) removes it.
- Related connections are closed and the incumbent is cleared.
- A connection that did not go through a Smart group returns `{}` and is still closed; one without routing metadata returns 204.
- An `id` that is not a valid UUID returns 400; an unknown connection 404.

### `POST /smart/groups/{name}/recompute`

Recomputes the ranking now and returns it: `{"group": "auto", "ranking": [...]}`.

## Flushing data

Flushing removes everything the group learned, as if starting over: evidence, incumbents, the serving pool and exploration budget, every block record (including `manual`), group-wide blocks, the manual pin, exit info and all of its records in the cache file; health state is reset as well. A `smart-loadbalance` group returns to its configured lock and settings and re-detects regions.

### `DELETE /proxies/{name}/weights`

Flushes one group and returns how many entries were removed:

```json
{ "group": "auto", "deleted": { "aggregate": 168, "site": 1320, "exact": 4210, "blocks": 12 } }
```

`aggregate`, `site` and `exact` count the evidence cells of the three layers, `blocks` the block records. If writing the cache file fails, it returns 500 with an extra `error`. A non-Smart object returns 400 `{"error": "not a Smart group"}`.

### `POST /cache/smart/flush`

Flushes every Smart group of the current config and returns **204** with no body, as in mihomo. `DELETE` is equivalent. If a group fails, it returns 500 `{"message": "<group>: <error>"}`.

### `POST /cache/smart/flush/{name}`

Flushes the Smart group named `name` and returns 204. `DELETE` is equivalent. mihomo keys this path by configuration name, so when `name` is not a Smart group, every Smart group is flushed.

## Smart load balancing

A `smart-loadbalance` group and its region outbounds (`smart-region`) both show `type: "Smart"` in dashboards, and every Smart endpoint above works on them. Below are the extra fields and endpoints; for regions, region outbounds and locking see [Smart load balancing](../smart-loadbalance/).

### `GET /proxies/{name}`

A `smart-loadbalance` group carries an extra `loadBalance` block summarising how it balances and how many nodes each region has:

```json
{
  "type": "Smart",
  "name": "balance",
  "now": "🇭🇰 Hong Kong 03",
  "all": ["🇭🇰 Hong Kong LB", "🇯🇵 Japan LB", "🇺🇸 United States LB", "unknown-node-1"],
  "fixed": "",
  "loadBalance": {
    "strategy": "smart", "affinity": "none", "mode": "auto", "lock": "", "fallback": "auto",
    "regions": [
      { "code": "HK", "name": "香港", "nameEn": "Hong Kong", "flag": "🇭🇰", "count": 12, "healthy": 11, "outbound": "🇭🇰 Hong Kong LB" },
      { "code": "OTHER", "name": "其他", "nameEn": "Other", "flag": "", "count": 1, "healthy": 1 }
    ]
  }
}
```

- With `region.outbounds.members` set to `regions` (the default) and region outbounds generated, `all` lists the region outbounds, then declared region outbounds that have no members yet, then the members of regions without an outbound. With `members: "nodes"`, `all` is the same as in a plain Smart group.
- `now` is a node: the pinned node, else the node that carried the latest connection. The `now` returned by `GET /smart/groups`, `DELETE /proxies/{name}` and the region endpoints shows the region instead: the locked region's outbound, else the outbound of the region that carried the last connection.
- `fixed` is the pinned node; with no pin but a locked region, it is that region's outbound (the region code when region outbounds are not listed).
- `regions[].name` is the Chinese display name (or a name set in `region.rules`) and `nameEn` the English one; `healthy` counts usable nodes for TCP; `icon` and `outbound` appear only when present.

A region outbound carries `group` (its group), `region`, `fallback` and `generated` (whether the group generated it). Its `all` lists the region's nodes, and its `now` is, in order: the node pinned on this outbound, the node of its last connection, the region's last used node, or the region's best usable member. `fixed` is the node pinned on this outbound.

### `PUT /proxies/{name}`

On a `smart-loadbalance` group, the `name` in the body can be one of three things:

| Body | Effect |
|---|---|
| `{"name": "🇯🇵 Japan LB"}` or `{"name": "JP"}` | Locks that region (region outbound tag, region code or name) and clears the pinned node |
| `{"name": "HK-01"}` | Pins a node as in a plain Smart group; the region lock stays, but the pin takes precedence |
| `{"name": ""}` | Clears both the pin and the region lock |

A node whose name equals a region name is treated as a node. On a region outbound, `{"name": "<node of this region>"}` pins a node for that outbound only; a node of another region returns 400 `smart-region update error: not a member of the region`, and `""` clears it.

`DELETE /proxies/{name}` works here too: on the group it clears both the pin and the lock (`previous_pin` shows the lock when nothing was pinned); on a region outbound it clears that outbound's pin and returns `{"group", "previous_pin", "now"}`, where `group` is the region outbound's own tag. Selections made in the SFA / SFW / SFL GUI clients follow the same rules.

### `GET /proxies/{name}/weights` and group delay tests

On a region outbound, `weights` returns the part of the group's ranking that belongs to the region, plus `group` and `region`: `{"weights": [...], "group": "balance", "region": "HK"}`.

On a group that lists region outbounds, `GET /group/{name}/delay` tests each region outbound's current node, keyed by the region outbound's tag.

### `GET /smart/groups/{name}/regions`

Everything about the region split: which region each node landed in and why, whether it is usable, its current load, and the mode, strategy and lock in effect. Look here first when a node is in the wrong region or you wonder why connections keep landing in one region.

```json
{
  "group": "balance",
  "mode": "auto", "configMode": "auto", "lock": "",
  "strategy": "smart", "configStrategy": "smart",
  "affinity": "none", "configAffinity": "none", "affinityTtl": "10m0s",
  "fallback": "auto", "priority": ["HK", "JP"], "minNodes": 1, "minQuality": 0.5,
  "maxNodes": 0, "maxConnections": 0, "sticky": "30m0s", "switchMargin": 0.25, "unknown": "keep",
  "detect": { "name": true, "exit": "fallback", "exitUrl": "https://www.cloudflare.com/cdn-cgi/trace", "exitTtl": "24h0m0s" },
  "probe": { "enabled": true, "interval": "10m0s", "targets": 6, "regions": 5, "tracked": 14, "results": 22 },
  "outbounds": { "enabled": true, "auto": false, "members": "regions", "tag": "{flag} {name_en} LB" },
  "regions": [
    {
      "code": "HK", "name": "香港", "nameEn": "Hong Kong", "flag": "🇭🇰",
      "count": 12, "healthy": 11, "load": 37, "score": 0.912, "allowed": true,
      "outbound": "🇭🇰 Hong Kong LB", "last": "🇭🇰 香港 03",
      "members": [
        { "name": "🇭🇰 香港 03", "source": "name", "healthy": true, "load": 4, "quality": 0.947 },
        { "name": "mystery-7", "source": "exit", "healthy": true, "load": 2, "quality": 0.55, "exit": "HK", "exitIp": "203.0.113.7" }
      ]
    }
  ],
  "excluded": [],
  "memory": { "regionTargets": 128, "affinity": 0 }
}
```

| Field | Meaning |
|---|---|
| `mode`, `strategy`, `affinity` | Values in effect; the `config*` fields hold the configured ones, so a difference means they were switched at runtime |
| `members[].source` | Where the region came from: `rule` (a custom rule), `name` (the node name), `exit` (an exit probe), `unknown` (not detected) |
| `members[].exit`, `exitIp` | Country and IP found by the exit probe; present only after a successful probe |
| `members[].quality` | Destination-independent quality (overall weight, or a value derived from probe delay), with the `policy_priority` factor applied |
| `load` | Live connections through this group (TCP and UDP) plus dials in flight |
| `score` | Destination-independent region score, without region-probe factors |
| `allowed` | Whether `allow` / `deny` permit the region |
| `last` | Node of the region's last connection |
| `probe.tracked`, `probe.results` | Sites tracked as probe candidates, and probe results currently held |
| `excluded` | Members dropped by `unknown: exclude` |
| `memory` | Destinations with a remembered region, and affinity bindings |

A missing group returns 404; a group of another type 400 `not a smart-loadbalance group: <name>`. The endpoints below behave the same way.

### `PUT /smart/groups/{name}/regions`

Locks a region and / or switches the region mode; fields you leave out stay as they are:

```bash
curl -X PUT http://127.0.0.1:9090/smart/groups/balance/regions -d '{"lock":"JP"}'
curl -X PUT http://127.0.0.1:9090/smart/groups/balance/regions -d '{"mode":"destination"}'
```

```json
{ "group": "balance", "mode": "destination", "lock": "JP", "now": "🇯🇵 Japan LB" }
```

- `lock` takes a region code, name, flag or region outbound tag; the region must have members, otherwise 400 `unknown region: ...`. `""` unlocks.
- `mode` set to `""` restores the configured mode; `priority` is refused when the configuration has no `priority` list. Switching the mode forgets every destination's remembered region.
- A body with neither field returns 400. Lock and mode are saved in the cache file and restored after a restart. With `interrupt_exist_connections`, changing the lock interrupts existing connections.

### `DELETE /smart/groups/{name}/regions/lock`

Releases the region lock and returns `{"group", "previous", "now"}`, where `previous` is the region that was locked.

### `POST /smart/groups/{name}/regions/detect`

Re-detects every member's region and starts exit probes for members that need one; with `?force=true` every member is re-probed. Call it after changing your naming rules, or when you suspect probe results are out of date.

Returns `{"group": "balance", "exitProbes": 3}`, where `exitProbes` is the number of probes started. Probes run in the background and regions update when they finish.

### `PUT /smart/groups/{name}/balance`

Switches the strategy and / or affinity. Empty fields stay as they are, `"default"` restores the configured value:

```bash
curl -X PUT http://127.0.0.1:9090/smart/groups/balance/balance -d '{"strategy":"least-connections","affinity":"site"}'
```

```json
{ "group": "balance", "strategy": "least-connections", "affinity": "site" }
```

Unknown values return 400. The switch is saved in the cache file and restored after a restart; changing the affinity drops existing bindings.
