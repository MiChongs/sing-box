## Basics

| Term | Meaning |
|---|---|
| Member | An outbound the group can choose: a node or another group |
| Exact target | A connection's domain (or IP without one) plus port, such as `api.example.com:443` |
| Wildcard host | The host with subdomains folded, such as `*.example.com`; block records and response probes work per wildcard host. See [Service keys](../service-keys/) |
| Service key | Decides which connections form one service: the matched routing rule (such as `RuleSet [geosite-netflix]`), else the wildcard host; with `prefer_asn`, broad rules are grouped by ASN |
| Site key | The wildcard host used as the service key when the destination is on a shared network or its ASN is unknown |
| ASN | Autonomous system number, identifying a network operator, such as 15169 for Google |
| Shared ASN | A network hosting masses of unrelated sites, such as Cloudflare, Akamai or AWS; never used as a service key |
| ASN claim | Once a service rule's connections succeed on an ASN, the ASN is attributed to that service; see [ASN claims](../service-keys/#asn-claims) |

## Score and selection

| Term | Meaning |
|---|---|
| Comprehensive score | From honk: observed success rate, fine-tuned by latency, goodput and quality, minus a loss penalty, times the `policy_priority` factor. See [Score and selection](../scoring/) |
| Evidence layers | A node's four records: global, address family, service, exact target; more specific layers override their parents as they gather data |
| Useful completion | A successful connection with data both ways, or any failed connection; inconclusive ones do not count |
| Reliability bounds | The Beta confidence interval from successes and failures; wide with few samples |
| Observed success rate | Decayed successes ÷ (successes + failures), a dial failure counting as 3 |
| Half-life | Reliability evidence loses half its weight every 30 minutes, so old outcomes fade |
| Eligibility | Only members not clearly behind the best on reliability, and without 3 failures in a row, can win an ordinary selection |
| Proven | 4 useful completions, or normal traffic within the last 60 s |
| Mature | A performance metric with 4 samples, the newest under 60 s old |
| Incumbent | A service's last ordinary choice; a challenger replaces it only by proving a gain on mature data from both sides |
| Serving pool | The few members where ordinary choices, trials and switches happen; its size follows traffic. See [The serving pool](../scoring/#the-serving-pool) |
| Trial / exploration | Handing a connection to a member that lacks data, within the exploration budget (cold, periodic and recovery trials) |
| Failure streak and backoff | A hard failure adds 1 to the streak and stops trials for 5 minutes, doubling up to 6 hours; 4 different connections proving recovery reset it |
| Connection quality | The value mihomo's scene formula (or the LightGBM model) gives each connection, roughly 0–1.5; below 0.4 blocks the node |
| Factor | The multiplier `policy_priority` gives a node; the first matching rule wins |

## Blocks and probes

| Term | Meaning |
|---|---|
| Block | A node temporarily unusable for one site, recorded per site; other sites are unaffected. Codes: `manual`, `answer`, `error`, `lowWeight`, `loss`, `stalled`; see [Block codes](../blocks-and-probes/#block-codes) |
| Group-wide block | A node temporarily unusable for all of the group's connections: a manual API block or an `unstable` block from the stability check |
| Broken site | When more than a third of the members (at least 2) are blocked for a site, the site is blamed and those blocks are ignored for a while |
| Response probe | After a short connection, a request for `https://<site>/robots.txt` through the same node, to recognize refusals, challenges and "not available in your region" |
| Exit | The country and IP where a node's traffic really lands; the exit a site sees can differ from the node's own |
| Exit suspicion | When several exits of one region are refused by a site while other regions work, that region's members are deferred for the site |
| Half-open | After a suspicion expires, one member at a time may try, holding an 8-second lease |
| Failure flood | 50 failures in a row, each within 2 s of the previous; meanwhile failures count against no node |
| Convergence | After the primary fails and a fallback connects, the service's connections through other nodes are closed to unify on the new node |
| MAD | Median absolute deviation; the stability check uses it on the last 10 delays to find jittery and slowing nodes |

## Manual control

| Term | Meaning |
|---|---|
| Manual pin | A node clicked in the dashboard; new connections use only that node, with no filtering, no fallback, and no blocks from connection outcomes |
| Current node (`now`) | The representative node a dashboard shows: the pinned node, else the member that carried the latest connection |
| Flush | Removes everything a group learned, including blocks, the pin and its records in the cache file |

## Data and models

| Term | Meaning |
|---|---|
| Cache file | The bbolt database of `experimental.cache_file`; Smart's data lives in its `smart_score` bucket |
| LightGBM | A decision-tree machine-learning model; with `use_lightgbm` it computes connection quality instead of the scene formula |
| Features | The 32 numbers handed to the model, by position; see [Features](../lightgbm/#features) |
| GeoX | The global service that downloads ASN and country databases (`experimental.geox`) |

## Load balancing

| Term | Meaning |
|---|---|
| Region | A group of members that `smart-loadbalance` forms by name, rules or exit detection, such as `HK` or `JP` |
| Region outbound | A `smart-region` outbound for one region, usable in routing rules, as a `detour` or in a `selector` |
| Lock | Fixing a `smart-loadbalance` group to one region |
| Balance strategy | How connections are spread over the chosen region's nodes, such as `smart` or `least-connections` |
| Affinity | Keeping a set of connections on one node, such as one site or one client |
