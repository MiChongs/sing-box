## Collect this information first

1. The summary line for each group in the startup log: `smart[<tag>] started: ... algorithm=... ml=... collect=...`.
2. The output of `GET /smart/groups` and `GET /smart/groups/{name}/diag`.
3. `GET /proxies/{name}/weights?full=1`, to see the per-destination breakdown.
4. When you need per-connection detail, set `log.level` to `debug`: each connection's selection result and each Watchdog verdict are logged at Debug level.

## Config errors

**`json: unknown field "tolerance"` or `"idle_timeout"`**: these two are `urltest` fields, and Smart does not support them. Earlier documentation listed them by mistake. Remove them.

**`urltest: invalid expected-status: ...`**: `expected_status` is malformed. Valid forms are `204`, `200-299` and `204/300-399`, with status codes in the range 100–599.

**`missing outbound and provider tags`**: both `outbounds` and `providers` are empty.

**`dependency[<tag>] not found for outbound[<smart>]`**: `outbounds` references an outbound that does not exist.

**A misspelled `algorithm` does not cause an error**: this is expected. Smart falls back to `strict-best` and logs a WARN. Rely on `algorithm=` in the startup log.

**Some `policy_priority` rules do not take effect**: invalid rules are only ignored and logged as `policy_priority: ignored invalid rule [...]`. Common causes: a factor of 1, mismatched case (matching is case-sensitive), or a regex without the `~` prefix. Check the parse result in the `policyPriority` field of `GET /smart/groups`.

## Smart does not seem to be learning

- **The log shows `smart: no cache file available, using ephemeral store`**: Smart did not get a cache file and records no stats. On the command-line version, set `experimental.cache_file.enabled: true`.
- **Just started, no traffic yet**: Smart does not probe or compute a ranking before the first successful dial.
- **Weights are empty**: a weight is computed only once the same (destination, node) pair has at least 2 samples.
- **`targetCount` is 1 and `sampleCount` is 0**: the endpoint is returning a ranking generated from test latency, which means there are no stats yet.

## A node is never selected

Check in order:

1. **Is it in the group?** `include` / `exclude` only filter subscription nodes. `all` in `GET /proxies/{name}` lists all members.
2. **Is it available?** A node is unavailable if its latest latency test failed, it failed within the last 3 minutes, its circuit breaker is open, or its test record is older than 3 × `interval`.
3. **Is it blocked?** After 30 accumulated failures, a node is blocked for 93 minutes or longer. A block through the API lasts 30 minutes by default.
4. **Is it soft-blocked for this destination only?** A single RST or stall soft-blocks the node for that destination for 10 minutes.
5. **Is its weight below 0.4?** Nodes that exceed the scenario's latency ceiling (such as 150 ms for real-time traffic) have their weight capped at 0.38.
6. **Is it pushed back by `policy_priority`?** Nodes with a factor greater than 1 always rank first.

To start over, use `DELETE /proxies/{name}/weights` to clear this group's data.

## The dashboard shows a different node from the one in use

`now` is "the node of the most recent successful dial". Smart selects nodes per destination, so different websites may use different nodes at the same moment. To see the node each connection actually uses, look at `chains` in `/connections`; the final node comes first.

## Traffic still uses other nodes after pinning

- When the pinned node fails to dial, Smart temporarily uses another node and `fixedSuspended` becomes `true`. It switches back automatically after the pinned node's next successful dial or probe.
- When the pinned node's circuit breaker is open, the pin is temporarily bypassed.
- A pin affects only new connections. Existing connections keep going until they end on their own, unless you enable `interrupt_exist_connections`.

## Smart still favors the old node after unpinning

This is the effect of pin learning: a previously pinned node gets a boost of up to about 1.63 times, for up to 14 days. Use `DELETE /proxies/{name}/weights` to clear it immediately.

## Working nodes are marked unavailable

- **`interval` below 100 seconds**: there is a gap between 3 × `interval` and 5 minutes in which a node is marked unavailable but is not retested. Set it back to 3 minutes or longer.
- **The probe URL is unstable on some nodes**: probes are sent through the node, and the exit of some nodes may not be able to reach the default URL. Switch to a 204 URL that every node can reach reliably, such as `https://cp.cloudflare.com/generate_204`.
- **The network just changed**: dials in progress are canceled during the 2 seconds after a network change. This is normal.

## A node shows as available but does not work

When `expected_status` is empty, any HTTP response counts as a successful probe, including a 3xx returned by a captive portal (Wi-Fi login page). Set `"expected_status": "204"`.

## Connections are dropped

- **Versions before 2026-10-05**: long-lived connections through Smart are cut at the 30th second. Upgrade.
- **Watchdog**: a connection is closed if there is no response at all for 60 seconds after the client writes, or on a first-byte timeout. Normally idle long-lived connections are not affected.
- **Network change**: sing-box closes all connections.
- **`interrupt_exist_connections`**: when enabled, a pin change interrupts this group's TCP connections.

## ASN does not take effect

Check the ASN-related lines in the startup log (see [ASN and GeoX](../asn-geox/#log-messages)):

- On a fresh install that uses GeoX, the database is not downloaded yet on the first run. Restart once after the download finishes;
- The database must be in MaxMind GeoLite2-ASN format;
- Relative paths in `asn_database` are not joined with the data directory;
- An ASN can be looked up only if the destination IP is already known at dial time. CDN and backbone ASNs are ignored on purpose.

## The model stays at ml=pending

The model has not been downloaded successfully. Check that the outbound specified by `download_detour` or `http_client` can reach GitHub. You can also download `Model-large.bin` manually, place it at `model_path` (by default `smart_lgbm_model.bin` in the data directory), and restart.

## Training data stops growing

- Writing stops once the file reaches `size_limit_mb` (default 100 MB). After you delete or truncate the file, writing resumes within 30 seconds;
- When `sample_rate` is below 1, only some connections are collected;
- Samples are dropped when the stats queue is busy.

## Battery drain or heat on phones

- Set `interval` to 5 minutes or longer;
- Use `exclude` to remove nodes you don't need;
- Avoid having multiple Smart groups reference the same set of nodes;
- Lower `SMART_CACHE_BUDGET_MB` when memory is tight (command-line version only).

## Resetting all Smart data

| Method | Scope |
|---|---|
| `DELETE /proxies/{name}/weights` | One group |
| `POST /cache/smart/flush` | All Smart groups in the current config |
| Stop sing-box, then delete the cache file | All data, **including** other caches such as rule sets, FakeIP and selector state |

</Callout>
