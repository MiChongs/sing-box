This page covers an optional Smart feature: computing connection quality with a machine-learning model. Without it Smart learns and chooses just the same, so you can skip this page at first.

## What it affects

When a connection ends, Smart computes its **connection quality** (roughly 0–1.5); see [Connection quality](../scoring/#connection-quality). By default this is vernesong/mihomo's scene formula; with `use_lightgbm` a **LightGBM** model predicts it instead. The model is an ensemble of decision trees trained on real connection data, and can capture combinations a hand-written formula cannot.

Connection quality serves four purposes in Smart:

- The quality term of the comprehensive score (weight 0.02; it only matters when reliability is close);
- Blocking a node when quality × the `policy_priority` factor falls below 0.4 (`lowWeight`);
- The node ranking in dashboards;
- Node quality in `smart-loadbalance`.

So the model mostly decides which nodes are considered poor enough to block, and the ranking; its effect on the reliability-first choice is limited.

### When it is worth enabling

- **Usually not needed**: the scene formula is good enough, and Smart's reliability score, blocks and probes do not depend on the model.
- **To match mihomo Smart**: enable `use_lightgbm` with the default model.
- **To train on your own data**: enable `collect_data` for a while first, then follow [Training your own model](#training-your-own-model).

## Enabling

Set `use_lightgbm: true` on the groups that should use it (`smart` and `smart-loadbalance` both work). The model is shared by all groups; its settings live in `experimental.smart.lightgbm`, and all of them can be omitted.

Once enabled:

- **First download**: when the model file is missing, `Model.bin` published by vernesong/mihomo is downloaded in the background and saved as `Model.bin` in the data directory (`model_path`). A missing file is downloaded even with `auto_update` off; an existing file is never downloaded again.
- **While downloading**: the scene formula keeps working; the model takes over as soon as it arrives, with no restart.
- **Auto-update**: with `auto_update: true` the model is checked every `update_interval` (72 hours by default) and a new one is hot-loaded.
- **Download path**: `http_client`, else `download_detour`, else the default HTTP client. Do not download the model through the Smart group that still has to learn.
- **Databases**: groups with `use_lightgbm` open the ASN and country databases (GeoX downloads GeoLite2 when none is configured) for the model's ASN and country features.

## Confirming it works

- **Log**: loading the model logs INFO `lightgbm model loaded from <path> (<N> features)`, a reload after a download logs `lightgbm model reloaded from <path>`, and an unusable file logs WARN `lightgbm: cannot use model <path>: <reason>`.
- **Clash API**: once the model is loaded, `GET /proxies/{name}` and `GET /smart/groups` show `lgbmModelAge` (how long ago it was loaded), and `lightgbmLoaded` is `true` in `GET /smart/groups/{name}/diag`.
- **Training data**: with `collect_data`, the CSV column `weight_source` is `LightGBM` when the model computed a connection's quality and `Traditional` when the scene formula did.

## How the model is used

When a connection closes, Smart assembles its 32 features and hands them to the model; the prediction becomes the connection quality as is (no factor; the factor applies where the quality is used). The scene formula is used instead when:

- The model is not loaded (still downloading, broken file);
- The model has a `[transforms]` section whose `[order]` differs from Smart's feature order;
- Prediction fails, or yields NaN or a value of 0 or less.

Neither is computed while the node has fewer than 2 completions on the service.

## Model format

LightGBM models in text format (the output of `save_model`) are supported. Inputs are **positional**: input i is feature i of the table below, whatever names the model file carries.

- A model with fewer than 32 inputs uses only the leading features, so models trained on the earlier 30-feature layout still work;
- A model with more than 32 inputs gets zeros for the extra ones, with a warning.

The end of the model file (within the last 16 KB) may carry a mihomo-style `[transforms] … [/transforms]` section: `[order]` lists `index=feature name`, and `[definitions]` defines StandardScaler or RobustScaler scaling applied before inference. When the scaling parameters fail validation, the section is ignored and nothing is scaled; when `[order]` differs from the table order, the model's predictions are not used.

## Features

The table gives the order of the 32 features, which is also the order of the first 32 CSV columns. log1p(x) means ln(1 + x), which compresses values spanning many magnitudes. The last two (30, 31) are the exit features appended after the earlier layout, as in mihomo.

Notes:

- "Service" means the connection's service key (see [Service keys](../service-keys/)); counts and totals come from the node's record for that service, or its group-wide record when there is none.
- Slots 19 and 26 need the ASN database, slots 20 and 29 the country database; they are 0 when the lookup fails.
- Slots 17 and 18 come from the retransmission counters of the TCP connection to the node's server, judged in windows of at least 64 segments or 64 KiB; nodes over QUIC or other UDP transports have none.
- Slots 30 and 31 come from the [exit watch](../blocks-and-probes/#exit-watch): the exit as seen by the site when known, else the node's own exit.

## Collecting training data

With `collect_data: true` on a group, every connection that ends with a verdict (success or failure) appends a row to the CSV; inconclusive connections and dial failures are not recorded. Leave it off unless you plan to train a model.

- **File**: `experimental.smart.collector.path`, by default `smart_weight_data.csv` in the data directory. Several groups write to the same file; the `group_name` column tells them apart.
- **Sampling**: `sample_rate` in (0, 1]; `0.3` records 30% of connections.
- **Writes**: flushed to disk every 100 rows and on shutdown.
- **Cap**: `size_limit_mb` (100 MB by default); at the cap writing stops with one log line, with no rotation. Delete the file and a new one is created within 5 s.
- **Header**: the first row holds 42 column names. When an existing file's header lacks `cumul_loss_rate` or `exit_region` (an older format), it is renamed to `<path>.bak.<timestamp>` and a new file is created.

Each row has 42 columns:

## Training your own model

The repository ships no training script. The steps below use Python with pandas and lightgbm.

**Step 1: collect data.** Enable `collect_data` on the groups you use most and use them normally for a few days, until you have at least tens of thousands of rows. The more varied the connections, the better.

**Step 2: prepare labels.** The `weight` column is the quality computed **at the time** (already cut down for connections that degraded a node or triggered a block). Training on it directly only teaches the model to imitate the current formula; to do better, build your own labels, for example from whether connections succeeded, their goodput and duration. Keep labels in the range of existing qualities (mostly 0.1–1.5), because predictions are used as quality directly and values below 0.4 block nodes.

**Step 3: train.**

```python
import pandas as pd
import lightgbm as lgb

df = pd.read_csv("smart_weight_data.csv")
X = df.iloc[:, 0:32].astype(float)   # the first 32 columns: features, order must not change
y = df["weight"].astype(float)       # labels; replace with your own

booster = lgb.train(
    {"objective": "regression", "learning_rate": 0.05, "num_leaves": 31, "verbose": -1},
    lgb.Dataset(X, y),
    num_boost_round=300,
)
booster.save_model("Model.bin")   # LightGBM text format
```

Features are read by position, so you cannot select or reorder columns; to ignore a feature, set its column to a constant before training.

**Step 4: deploy.** Put the file at `model_path` (`Model.bin` in the data directory by default) and set `auto_update` to `false`, otherwise auto-update overwrites it with the default model; or point `url` at a file you publish yourself. Then restart sing-box: a file replaced by hand is not picked up on its own.

**Step 5: confirm.** The log should show `lightgbm model loaded from …`, and the CSV column `weight_source` then shows `LightGBM`.
