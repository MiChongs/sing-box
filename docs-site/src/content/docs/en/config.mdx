This page is the reference for every Smart setting. Come here to change a default, look up what a field does, or work out why startup failed. If you are new to Smart, start with [Quick start](../quick-start/); unfamiliar terms are explained in the [Glossary](../glossary/).

## How to read this page

Smart is configured in four places:

- **The group itself**, in `outbounds`, with type `smart` (concentrates traffic on the best node) or `smart-loadbalance` (sorts nodes into region pools and spreads connections across several of them).
- **`experimental.smart`**: the LightGBM model and training-data collection shared by all groups. Usually not needed.
- **`experimental.geox`**: download settings for the ASN and country databases. Usually not needed.
- **`experimental.cache_file`**: Smart keeps what it learns in the cache file, so it **must be enabled**.

Each field shows its type and default. A field without a default is empty, which means off. The types are written like this:

| Type | How to write it |
|---|---|
| `duration` | A duration string such as `30s`, `5m`, `72h` |
| `regex` | A Go RE2 regular expression such as `(?i)hong kong\|HK`; an invalid pattern is a config error |
| `string \| string[]` | Either one string or an array of strings |
| `object` | A JSON object such as `{"HK": 1.2}` |

Most fields can be left out. An unknown field in the config is an error, which catches typos; the one exception is the `algorithm` of a `smart` group, where a typo only logs a WARN.

## From minimal to typical

### Minimal configuration

All Smart needs is the nodes to use and an enabled cache file:

```json
{
  "outbounds": [
    { "type": "smart", "tag": "auto", "providers": ["my-subscription"] }
  ],
  "experimental": {
    "cache_file": { "enabled": true }
  }
}
```

Everything else keeps its default: nodes are checked every 3 minutes, and each site gets the best node Smart has learned for it.

### A typical configuration

On top of the minimal one, most people add a few fields:

```json
{
  "type": "smart",
  "tag": "auto",
  "providers": ["my-subscription"],
  "exclude": "(?i)traffic|expire|website",
  "expected_status": "204",
  "interval": "5m",
  "algorithm": "p2c",
  "policy_priority": "HK:1.2;JP:1.1"
}
```

- `exclude` drops the "traffic left" and "expires on" entries some subscriptions include; they are not real nodes.
- `expected_status: "204"` requires the probe address to answer 204, so the login page of hotel or airport Wi-Fi cannot make a dead node look healthy.
- `interval: "5m"` probes less often, which saves battery on phones.
- `algorithm: "p2c"` weighs latency and load among the top few nodes, so not every connection lands on the same one; see [Algorithms](../algorithms/).
- `policy_priority` prefers nodes whose names contain `HK` or `JP`; see [Priority and pinning](../priority-and-pinning/).

For complete, working configurations, see [Examples](../examples/).

### All fields at a glance

Every field of a `smart` group and of the two global blocks, with its default, for reference. Do not copy it wholesale; write only the fields you want to change.

```json
{
  "outbounds": [
    {
      "type": "smart",
      "tag": "auto",

      "outbounds": [],
      "providers": [],
      "use_all_providers": false,
      "include": "",
      "exclude": "",

      "url": "https://www.gstatic.com/generate_204",
      "interval": "3m",
      "expected_status": "",

      "algorithm": "strict-best",
      "hysteresis": "0s",
      "policy_priority": "",
      "interrupt_exist_connections": false,
      "disable_udp": false,

      "use_lightgbm": false,
      "collect_data": false,
      "sample_rate": 1.0,
      "max_host_failed_times": 10,

      "use_asn": false,
      "asn_database": [],

      "hidden": false,
      "icon": ""
    }
  ],
  "experimental": {
    "cache_file": { "enabled": true },
    "smart": {
      "lightgbm": {
        "model_path": "smart_lgbm_model.bin",
        "url": "",
        "auto_update": false,
        "update_interval": "72h",
        "http_client": "",
        "download_detour": ""
      },
      "collector": {
        "path": "smart_weight_data.csv",
        "size_limit_mb": 100
      }
    },
    "geox": {
      "enabled": false,
      "auto_update": false,
      "update_interval": "24h",
      "download_detour": "",
      "url": { "asn": [], "mmdb": "", "geoip": "", "geosite": "" }
    }
  }
}
```

<Callout type="warn" title="cache_file must be enabled">
  Smart stores its stats, weights, ranking, pins and circuit-breaker state in the cache file (the `smart_stats` bucket). Without a cache file Smart records no stats and can only pick nodes by probe latency, so it does not learn at all. The command-line version needs `experimental.cache_file.enabled: true`; the SFA / SFW / SFL GUI clients always enable the cache file.
</Callout>

<Callout type="danger" title="Unsupported fields">
  `tolerance` and `idle_timeout` belong to `urltest`; Smart has never supported them. In a Smart group they make startup fail: `outbounds[0].tolerance: json: unknown field "tolerance"`. Earlier documentation listed them by mistake. Remove them from your config.
</Callout>

## smart-loadbalance

A `smart-loadbalance` group is for spreading connections across several nodes while keeping the exit region stable: a large subscription grouped by region on its own, multi-threaded downloads, or the front of chained proxies. See [Smart load balancing](../smart-loadbalance/) for how it works.

It accepts every field of the `smart` group above with the same meaning, except `algorithm` and `hysteresis`, which are ignored (with a WARN at startup) and replaced by `balance` and `region`. Unlike `algorithm`, an invalid value in `balance` or `region` is a config error.

The simplest form looks just like a `smart` group:

```json
{ "type": "smart-loadbalance", "tag": "balance", "providers": ["my-subscription"] }
```

When you need to tune it, these are the fields and their defaults:

```json
{
  "type": "smart-loadbalance",
  "tag": "balance",
  "providers": ["my-subscription"],

  "balance": {
    "strategy": "smart",
    "affinity": "none",
    "affinity_ttl": "10m",
    "max_nodes": 0,
    "min_quality": 0.5,
    "max_connections_per_node": 0
  },
  "region": {
    "mode": "auto",
    "priority": [],
    "allow": [],
    "deny": [],
    "weights": {},
    "fallback": "auto",
    "min_nodes": 1,
    "sticky": "30m",
    "switch_margin": 0.25,
    "unknown": "keep",
    "rules": [],
    "destination": { "map": {}, "disable_tld": false, "disable_resolve": false },
    "detect": {
      "disable_name": false,
      "exit": "fallback",
      "exit_url": "https://www.cloudflare.com/cdn-cgi/trace",
      "exit_ttl": "24h",
      "exit_timeout": "8s",
      "exit_concurrency": 4
    },
    "probe": { "disabled": false, "interval": "10m", "targets": 6, "regions": 5 },
    "outbounds": {
      "enabled": false,
      "regions": [],
      "auto": false,
      "tag": "{group}-{region}",
      "fallback": false,
      "members": "regions",
      "hidden": false,
      "icon": ""
    }
  }
}
```

Wherever a region is expected, you can write a region code (`HK`, `GB`; `UK` means `GB`), a Chinese or English name (`香港`, `Japan`) or a flag (`🇯🇵`), in any letter case. Anything else is upper-cased and treated as a custom region (such as `IPLC`).

## smart-region

A `smart-region` outbound is one region of a `smart-loadbalance` group: connections through it only leave from that region's nodes, while learning, breakers and spreading stay with the group. It is usually generated by `region.outbounds`; to set `fallback` or `hidden` for one region, you can also declare it by hand:

```json
{ "type": "smart-region", "tag": "japan-front", "group": "balance", "region": "JP", "fallback": false }
```

## experimental.smart

The LightGBM model and training-data collector shared by every Smart group. The block has no `enabled` switch and is usually unnecessary: the model is only loaded and downloaded when some group sets `use_lightgbm`, and the CSV is only created when some group sets `collect_data`. Write it only to change the model path, how it is downloaded, or where the CSV goes.

## experimental.geox

Global download settings for geo data. At the moment **only Smart uses this data**: `url.asn` provides the ASN database for groups without `asn_database`, and `url.mmdb` provides the country database used by LightGBM, training-data collection and the `destination` mode of `smart-loadbalance`.

None of the `url` entries has a default address; only files with an address are downloaded. File names are fixed and the files are saved in the data directory. You can also leave `geox` out entirely: groups that need an ASN or country database download the default GeoLite2 databases on their own.

<FieldList lang="en" fields={geoxFields} prefix="geox-" />

<Callout type="note" title="First download and when it takes effect">
  GeoX downloads in the background and does not slow startup down. It does not matter if a file is not there yet when Smart starts: once a database is downloaded or updated it takes effect immediately and every group uses the new data, **with no restart**.
</Callout>
