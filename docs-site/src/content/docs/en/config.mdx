This page is the reference for every Smart setting. Come here to tune a default, look up a field, or understand a startup error. New users should start with [Quick start](../quick-start/); unfamiliar terms are in the [Glossary](../glossary/).

## Reading this page

Smart configuration lives in four places:

- **The group itself**, in `outbounds`, with type `smart` (picks the most reliable node per connection) or `smart-loadbalance` (pools nodes by region and spreads connections across them).
- **`experimental.smart`**: the LightGBM model and training-data collector shared by all groups; usually not needed.
- **`experimental.geox`**: download settings for the ASN and country databases; usually not needed.
- **`experimental.cache_file`**: learned data is saved here; recommended. Without it Smart still learns, but starts from zero after a restart.

Every field shows its type and default; fields without a default are empty by default. Type notation:

| Type | Written as |
|---|---|
| `duration` | A duration string such as `30s`, `5m`, `72h` |
| `regex` | A Go RE2 regex string such as `(?i)Hong Kong\|HK`; an invalid one fails when the config is read |
| `string \| string[]` | A single string or an array of strings |
| `object` | A JSON object such as `{"HK": 1.2}` |

Unknown fields are a config error, for example `outbounds[0].algorithm: json: unknown field "algorithm"`. Every field of the old Smart has been removed; see [Removed fields](#removed-fields).

## From minimal to typical

### Minimal

All Smart needs is its nodes:

```json
{
  "outbounds": [
    { "type": "smart", "tag": "auto", "providers": ["my-subscription"] }
  ],
  "experimental": {
    "cache_file": { "enabled": true }
  }
}
```

Everything else uses defaults: while the group is in use its members are checked every 5 minutes, and every service gets its most reliable node.

### Typical

On top of the minimal config, most people add:

```json
{
  "type": "smart",
  "tag": "auto",
  "providers": ["my-subscription"],
  "exclude": "(?i)traffic|expire|website",
  "expected_status": "204",
  "policy_priority": "Hong Kong|HK:1.2;Japan|JP:1.1",
  "prefer_asn": true
}
```

- `exclude` drops the "traffic left" and "expires on" entries some subscriptions include; they are not real nodes.
- `expected_status: "204"` requires the check URL to answer 204, so a hotel or airport Wi-Fi login page cannot make a dead node look alive.
- `policy_priority` prefers nodes whose names contain "Hong Kong" or "Japan"; see [Node preferences](../scoring/#node-preferences).
- `prefer_asn` groups sites that arrive through `route.final` or broad rules by network; see [Service keys](../service-keys/#prefer_asn).

Complete working examples are in [Examples](../examples/).

## smart-loadbalance

A `smart-loadbalance` group is for spreading connections across several nodes while keeping the exit region stable: a large subscription grouped by region on its own, multi-threaded downloads, or the front of chained proxies. See [Smart load balancing](../smart-loadbalance/) for how it works.

It accepts every field of the `smart` group above with the same meaning, plus the `balance` and `region` blocks; an invalid value in either is a config error.

The simplest form looks just like a `smart` group:

```json
{ "type": "smart-loadbalance", "tag": "balance", "providers": ["my-subscription"] }
```

When you need to tune it, these are the fields and their defaults:

```json
{
  "type": "smart-loadbalance",
  "tag": "balance",
  "providers": ["my-subscription"],

  "balance": {
    "strategy": "smart",
    "affinity": "none",
    "affinity_ttl": "10m",
    "max_nodes": 0,
    "min_quality": 0.5,
    "max_connections_per_node": 0
  },
  "region": {
    "mode": "auto",
    "priority": [],
    "allow": [],
    "deny": [],
    "weights": {},
    "fallback": "auto",
    "min_nodes": 1,
    "sticky": "30m",
    "switch_margin": 0.25,
    "unknown": "keep",
    "rules": [],
    "destination": { "map": {}, "disable_tld": false, "disable_resolve": false },
    "detect": {
      "disable_name": false,
      "exit": "fallback",
      "exit_url": "https://www.cloudflare.com/cdn-cgi/trace",
      "exit_ttl": "24h",
      "exit_timeout": "8s",
      "exit_concurrency": 4
    },
    "probe": { "disabled": false, "interval": "10m", "targets": 6, "regions": 5 },
    "outbounds": {
      "enabled": false,
      "regions": [],
      "auto": false,
      "tag": "{group}-{region}",
      "fallback": false,
      "members": "regions",
      "hidden": false,
      "icon": ""
    }
  }
}
```

Wherever a region is expected, you can write a region code (`HK`, `GB`; `UK` means `GB`), a Chinese or English name (`香港`, `Japan`) or a flag (`🇯🇵`), in any letter case. Anything else is upper-cased and treated as a custom region (such as `IPLC`).

## smart-region

A `smart-region` outbound is one region of a `smart-loadbalance` group: connections through it only leave from that region's nodes, while learning, failure state and spreading stay with the group. It is usually generated by `region.outbounds`; to set `fallback` or `hidden` for one region, you can also declare it by hand:

```json
{ "type": "smart-region", "tag": "japan-front", "group": "balance", "region": "JP", "fallback": false }
```

## experimental.geox

Global download settings for geo data. Smart uses two databases:

- **ASN database**: used by groups with `prefer_asn`, `use_lightgbm` or `collect_data`, to look up the network of destinations and node exits;
- **Country database**: used by groups with `use_lightgbm` or `collect_data`, and by `smart-loadbalance` groups.

`geox` can be left out: groups that need them have GeoX download the default GeoLite2-ASN and GeoLite2-Country in the background, saved in the data directory.

<FieldList lang="en" fields={geoxFields} prefix="geox-" />

<Callout type="note" title="First download and when it takes effect">
  GeoX downloads in the background and does not slow startup. A downloaded or updated database takes effect at once for every group, **with no restart**. Until then, no ASN or country is known.
</Callout>

## Removed fields

After the rewrite these old fields are gone, and writing them fails with `json: unknown field "<field>"`:

| Old field | Now |
|---|---|
| `algorithm` | Removed. The comprehensive score makes every choice, see [Score and selection](../scoring/); `smart-loadbalance` uses `balance.strategy` |
| `hysteresis` | Removed. A service's incumbent only changes when a challenger proves better, so no anti-flap window is needed |
| `use_asn` | Replaced by `prefer_asn`, with a different meaning: broad rules are grouped by ASN, instead of recording extra per-ASN weights |
| `asn_database` | Removed. ASN databases come from `experimental.geox.url.asn` only |
| `max_host_failed_times` | Removed. A site counts as broken itself when more than a third of the members are blocked for it |
| The old `SMART_*` environment variables | No longer read |

New fields: `idle_timeout`, `timeout`, `tolerance`, `max_failed_times`, `prefer_asn`. The default `interval` changed from 3 to 5 minutes. `policy_priority` now uses mihomo's syntax (the first matching rule wins, regex or substring); the old `=`, `~` and `!` prefixes have no special meaning any more.
