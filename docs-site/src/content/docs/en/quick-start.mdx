This page gets a Smart group running with the smallest possible configuration and shows you how to tell whether it is working. Afterwards, [How it works](../how-it-works/) explains why it picks the nodes it picks. Unfamiliar terms are defined in the [Glossary](../glossary/).

## What Smart is

Smart is an outbound group: you give it a set of nodes and it chooses one for each connection. Unlike `urltest`, which picks by probe latency, Smart **remembers how each node actually performed for each website** — whether it connected, how fast it connected, how soon the first byte arrived, how much data moved — and scores nodes from that record. If a node is fast for site A but slow for site B, Smart keeps the two apart and uses a different node for B next time.

If you would rather spread connections over several nodes of one region than concentrate them on the single best node, see [Smart load balancing](../smart-loadbalance/).

## What you need

- **The binary**: Smart exists only in the xiaobaf14g branch. Download the command-line binary from [Releases](https://github.com/MiChongs/sing-box/releases), or the GUI clients published on the same page: SFA (Android), SFW (Windows), SFL (Linux). Upstream sing-box and the reF1nd branch do not know `"type": "smart"` and fail with `unknown outbound type: smart`.
- **Nodes**: a subscription URL, or outbounds already defined in your configuration.
- **(Optional) a dashboard**: to inspect and switch nodes in a browser, enable the Clash API and use a dashboard such as [metacubexd](https://github.com/MetaCubeX/metacubexd) or [zashboard](https://github.com/Zephyruso/zashboard).

## Minimal configuration

<CodeBlock code={minimal} filename="01-minimal.json" locale="en" />

Section by section:

- **`providers`** defines a remote subscription, `my-subscription`, refreshed every 12 hours. The Smart group uses all of its nodes through `"providers": ["my-subscription"]`. Without a subscription, list node tags directly with `"outbounds": ["node-a", "node-b"]`.
- **The `smart` group** uses defaults for everything except its tag and members: it probes every node with `https://www.gstatic.com/generate_204` every 3 minutes, and its selection algorithm is `strict-best` (always try the highest-scoring node first).
- **`route.final`** sends all traffic that matches no route rule to Smart.
- **`experimental.cache_file`** is where everything Smart learns is stored. It is **required** — see the note below.
- **`experimental.clash_api`** is used by the checks below and by dashboards; remove it if you do not need it.

<Callout type="warn" title="Do not omit cache_file">
  Smart keeps its statistics, weights, pins and circuit-breaker state in the cache file. Without `cache_file` in the command-line version, Smart has nowhere to record anything and picks nodes by probe latency only — little more than a complicated `urltest` — and the startup log says `smart: no cache file available, using ephemeral store`. The GUI clients always enable the cache file, so there is nothing to configure there.
</Callout>

The matching commands:

```bash
curl -s http://127.0.0.1:9090/smart/groups
curl -s http://127.0.0.1:9090/proxies/auto/weights
curl -s 'http://127.0.0.1:9090/proxies/auto/weights?full=1'   # with per-destination detail
```

If you set a `secret`, add `-H 'Authorization: Bearer <secret>'` to every request.

### What "learning" looks like

After some use, `sampleCount` (connections counted) and `targetCount` (websites involved) in `/proxies/auto/weights` keep growing, and the `weight` values start to differ. With `?full=1` you see, per website and node, the successes, failures and latencies Smart bases its choices on.

In a dashboard, the Smart group shows as type `Smart`. Click a node, as you would in a `selector`, to pin it: Smart then uses that node until you release it, switches to others temporarily while it is down, and returns to it once it recovers. See [Priority and pinning](../priority-and-pinning/).

## Reading the startup log

On a normal start, each Smart group logs one summary line:

```text
smart[auto] started: 42 outbounds, 12 background tasks, testURL=https://www.gstatic.com/generate_204 interval=3m0s asn=off algorithm=strict-best hysteresis=off ml=off collect=off
```

| Field | Meaning |
|---|---|
| `42 outbounds` | Members of the group. Subscription nodes join once the subscription has loaded; before that, this can be just 1 (the built-in direct outbound `Compatible`) |
| `testURL` / `interval` | Probe URL and probe period |
| `asn` | ASN learning: `off`; `on`; `on(downloading)` while the database downloads; `on(no-db)` when no database is available |
| `algorithm` | The selection algorithm **actually in effect**. A misspelled algorithm is not an error but falls back to `strict-best`, so trust this field |
| `hysteresis` | Anti-flap window; `off` when disabled |
| `ml` | LightGBM model state, see below |
| `collect` | Training-data collection: `off`, or `on(sample rate)` |

| `ml` value | Meaning |
|---|---|
| `off` | The group does not set `use_lightgbm` |
| `pending` | Enabled, but the model is still downloading or not loaded yet; the classic formula scores nodes meanwhile |
| `unusable` | Enabled, but the model file cannot be used (unsupported format or features); the classic formula is used, and a WARN log says why |
| `loaded` | The model is loaded and scores nodes |

## Common first-run problems

- **`smart: no cache file available, using ephemeral store` in the log**: `experimental.cache_file` is not enabled, so Smart does not learn.
- **`weights` stays a latency ranking**: not enough connections recorded yet. Check that traffic really goes through Smart (route rules may send it to another outbound), then give it more time.
- **The dashboard shows only `Compatible` as a member**: neither `outbounds` nor the subscription provides any node — the subscription failed to download, say, or `include` / `exclude` filtered every node out. With no members Smart falls back to the built-in direct outbound `Compatible`, so traffic leaves without any proxy.
- Everything else: [Troubleshooting](../troubleshooting/).
