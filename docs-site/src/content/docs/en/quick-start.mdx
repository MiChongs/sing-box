This page gets a Smart group running with the smallest possible config and shows how to tell that it works. Afterwards, [How it works](../how-it-works/) explains why it picks the nodes it picks. Unfamiliar terms are in the [Glossary](../glossary/).

## What Smart is

Smart is an outbound group: you hand it a set of nodes and it picks one for every connection. Unlike `urltest`, which only looks at probe delay, Smart remembers **how each node actually served each service**: whether it connected, whether the site answered, how fast, how much it carried, whether packets were lost. It chooses from that record.

It merges two designs:

- **The comprehensive score comes from [honk](https://github.com/daeuniverse/honk)** (the Score policy of daeuniverse/honk): decayed success rates decide which nodes are reliable, and only among reliable nodes do latency, goodput and connection quality compete; the node in use is replaced only when a challenger proves better.
- **Service keys, blocks and probes come from the Smart group of [vernesong/mihomo](https://github.com/vernesong/mihomo)**: the matched routing rule is a "service" that converges on one exit, a node is blocked only for the sites where it fails, and short connections are rechecked through the same node to see what the site really answers.

To spread connections over several nodes of one region instead, see [Smart load balancing](../smart-loadbalance/).

<Callout type="warn" title="Upgrading from the old Smart">
  Smart has been rewritten from scratch. Old fields such as `algorithm`, `hysteresis`, `use_asn`, `asn_database` and `max_host_failed_times` are gone, and leaving them in the config fails with `json: unknown field "<field>"`. Old learned data is not migrated; it is cleaned up on the first start. The [Changelog](../changelog/) has the full mapping.
</Callout>

## Prerequisites

- **Binary**: Smart only exists in the xiaobaf14g fork. Download the command-line binary from [Releases](https://github.com/MiChongs/sing-box/releases), or the GUI clients published on the same page: SFA (Android), SFW (Windows), SFL (Linux). Upstream sing-box does not know `"type": "smart"` and fails with `unknown outbound type: smart`.
- **Nodes**: a subscription, or some outbounds already in your config.
- **(Optional) a dashboard**: to view and switch nodes in a browser, enable the Clash API and use a dashboard such as [metacubexd](https://github.com/MetaCubeX/metacubexd) or [zashboard](https://github.com/Zephyruso/zashboard).

## Minimal config

<CodeBlock code={minimal} filename="01-minimal.json" locale="en" />

Section by section:

- **`providers`**: defines a remote subscription `my-subscription`. The Smart group uses all of its nodes through `"providers": ["my-subscription"]`; without a subscription, list node tags with `"outbounds": ["node-a", "node-b"]` instead.
- **The `smart` group**: everything except the tag and members uses defaults: while the group is in use it checks its members every 5 minutes against `https://www.gstatic.com/generate_204`, and checks pause after 30 idle minutes.
- **`route.final`**: traffic that matches no routing rule goes to Smart.
- **`experimental.cache_file`**: learned data is written here every 5 minutes and survives restarts. Without it Smart still learns, but starts from zero after every restart. GUI clients always have a cache file.
- **`experimental.clash_api`**: used by the checks below and by dashboards.

The matching commands:

```bash
curl -s http://127.0.0.1:9090/smart/groups
curl -s http://127.0.0.1:9090/group/auto/weights
curl -s http://127.0.0.1:9090/smart/groups/auto/diag   # selection reasons, pool, block records
```

With a `secret`, add `-H 'Authorization: Bearer <secret>'` to every request.

### What "learning" looks like

After a while, `Success` and `Completed` keep growing in `/group/auto/weights`, `Weight` starts to differ between members, and the members in use show `Pool: true`. In `/smart/groups/auto/diag`, `selection[].reasons` counts why each choice was made, for example `incumbentHeld` (kept the current node), `performanceWinner` (switched to a better node) or `coldExplore` (tried a node with no data yet); see [Score and selection](../scoring/#selection-reasons).

Dashboards show Smart groups as type `Smart`. Clicking a node pins it: new connections use only that node until you release it. See [Manual pin](../how-it-works/#manual-pin).

## Reading the log

Smart is quiet by default. With `log.level` set to `debug` you can watch it work; lines carry the prefix `outbound/smart[<group tag>]`:

```text
DEBUG outbound/smart[auto]: dial HK-02 for api.example.com failed: i/o timeout
DEBUG outbound/smart[auto]: converged 3 connections of [RuleSet [geosite-openai]] on JP-01
DEBUG outbound/smart[auto]: node US-03 refused for www.example.com: region unavailable
DEBUG outbound/smart[auto]: node HK-05 lowWeight for [*.example.com]
INFO  outbound/smart[auto]: manual pin set to HK-01
```

- `converged`: the primary node of a service failed and a fallback took over, so the service's connections through other nodes were closed to unify on the new node (see [Convergence](../service-keys/#convergence)).
- `refused for`: a response probe found that the site refuses this node (see [Response probes](../blocks-and-probes/#response-probes)).
- `lowWeight`, `error`, `loss`, `stalled`, `answer`, `manual`: why a node was blocked (see [Block codes](../blocks-and-probes/#block-codes)).

## Common startup problems

- **`interval must be less or equal than idle_timeout`**: `interval` is longer than `idle_timeout` (30 minutes by default).
- **The dashboard only ever shows `Compatible`**: neither `outbounds` nor the subscription supplied nodes, for example because the download failed or `include` / `exclude` filtered everything out. Traffic then leaves directly through the built-in direct outbound.
- **Every `Weight` is 0**: there are not enough connections yet, or traffic never reaches this group (rules send it elsewhere).
- Everything else: [Troubleshooting](../troubleshooting/).
